# AGENTS.md — the cold-session map

> **Size budget: ~150 lines / ~2k tokens.** Every agent loads this file on
> every session, so it stays a map of pointers and costs — no behaviour.
> The budget is documented here, not gate-enforced: trim before growing
> past it.

Marky Mark: a fast, themeable Markdown viewer/editor. React + CodeMirror
front end, Tauri desktop shell (`src-tauri/`), plus a self-contained
single-file web build.

This file is the single source of truth for agent orientation. `CLAUDE.md`
at the root is a symlink to it, so both harnesses resolve the same content;
`scripts/validate.mjs` fails — in the quick tier too — if that link stops
resolving here.

Coding rules are **not** in this file: they live in
`.sandcastle/CODING_STANDARDS.md`. Read that before writing code.

## Finding code: citation-grep first

Behaviour in this repo carries a citation comment naming the contract it
implements: `// SPEC<n> §x.y: <what and why>` (format details in
`.sandcastle/CODING_STANDARDS.md`).
There are ~829 citation sites across `src/` and `tests/` (counted
2026-08-03 via `grep -rEo 'SPEC[0-9]+' src tests | wc -l`). Grep the spec
number before you open any file.

Worked example — *"where is the folder sidebar implemented?"*:

    rg 'SPEC34' src        # or: grep -rn 'SPEC34' src

26 cited sites come back (`src/App.tsx`, `src/styles.css`,
`src/platform/*`), each with a one-line statement of what it implements —
roughly 2k tokens, landing you at the exact functions. Reading `App.tsx`
end-to-end instead costs ~50k tokens (4,700+ lines). Never read `App.tsx`
whole.

The companion move — **"where is feature X?"** — is `docs/MAP.md`: the
generated spec→code table. Find the spec that owns the behaviour, read off
its `src/` files and the E-numbered e2e tests covering it. It is
regenerated by the one command `npm run map` and never hand-edited (the
validation gate diffs it against what the generator derives).

## Verification: what each command costs

- `npm run typecheck` + `npm run test:unit` — seconds. The iteration pair:
  run these (or tests targeted at what you changed) after each change.
- `npm run test:e2e` — the desktop-shim Playwright suite; minutes, and
  serialized machine-wide. **Too slow for the inner loop.** Debugging one
  behaviour? Run one test: `npx playwright test -g '<title>'`.
- `npm run validate:quick` — the gate before declaring work done (adds the
  e2e suite and the spawn-free file checks). Run it **once** at the end;
  it prints `QUICK VALIDATION: ALL PASSED`.
- `npm run validate` — the full gate (web + desktop builds, web e2e,
  `cargo check`, bundle scans). Release evidence only; needs Rust on PATH.

This must stay consistent with `QUICK_VERIFY_COMMANDS` / `VERIFY_COMMANDS`
in `.sandcastle/config.mts` — if they disagree, fix one of the two.

## Do not read

- `archive/` — historical material (old goal files, retired plans,
  articles), excluded from agent context. That exclusion is a context
  guardrail, **not a security boundary**: anything there is still readable
  by explicit path and ships in every clone, so never place secrets in
  `archive/` on the strength of it.
- `docs/ARCHITECTURE.md` when the question is "which file do I edit" —
  `docs/MAP.md` answers that in one lookup. ARCHITECTURE.md explains the
  system's shape; it does not locate edits.
- `src/App.tsx` end-to-end — citation-grep into it instead (see above).

## Directory map

- `docs/specs/` — the app's numbered contract history (SPEC, SPEC2, …);
  the targets that `SPEC<n>` citations in code point at.
- `issue-specs/` — Sandcastle's per-issue working specs (`issue-<n>.md`).
  The rule in one line: `docs/specs/` is the app's numbered contract
  history that code cites; `issue-specs/` is Sandcastle's per-issue
  working specs.
- `prd/` — product requirement documents behind multi-issue efforts.
- `archive/` — kept history, excluded from agent context (see above).
- `src/lib/` — pure TypeScript modules (settings, themes, comments,
  markdown, hotkeys, …): the unit-tested logic layer under the React shell.
- `tests/e2e/` — Playwright suites split per feature area, tests numbered
  `E<n>`; `helpers.ts` / `fixtures.ts` are shared setup.
- `fixtures/` — sample Markdown documents and a comment sidecar that tests
  and demos load.

Other roots in one breath: `src/` is the React app (`App.tsx` shell,
`components/`, `platform/` tauri/web shims), `src-tauri/` the Rust host,
`scripts/` repo tooling (`validate.mjs`, `map.mjs`, release scripts),
`themes/` the bundled themes, and the rest of `docs/` holds DEVELOPING,
RELEASING, WINDOWS, HOSTING-AZURE and HOSTING-AZURE-PORTAL (the two
operator guides — CLI and portal walkthroughs of the one backend), and
COMMENT-FORMAT.
