# Spec: Agent bridge anchor demos as e2e tests and setup documentation (#368)

## Goal

All acceptance criteria in issue-specs/issue-368.md are satisfied for issue #368, with evidence visible in the session: the three PRD 027 Req 15 anchor demos exist as E-numbered hosted-lane Playwright tests that mint an agent token through the route, drive the real `POST /api/mcp` endpoint over streamable HTTP, and act on a real opted-in browser tab — (a) `create_file` + `open_file` makes a new Markdown file appear in the controlled tab's folder tree, open, and render; (b) with a long document open, `get_editor_state` reports the scroll position and `scroll` by one page moves the visible viewport; (c) a user-made selection is read via `get_editor_state`, replaced via `replace_selection`, formatted via `apply_format`, shows replaced and formatted in the tab, undoes one step per tool call, stays dirty until the `save` tool persists it; a short setup page `docs/AGENT-BRIDGE.md` (PRD 027 Req 16) covers the experimental setting, the `MM_AGENT_BRIDGE=1` server flag, minting a token, the exact `claude mcp add --transport http … --header "Authorization: Bearer <token>"` invocation, and opting a tab in, linked from an existing `docs/` page, `server/README.md` and the AGENTS.md directory map; `docs/MAP.md` matches `npm run map`; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #368.

## Acceptance criteria

### The three anchor demos as e2e tests (PRD 027 Req 15)

- Three new E-numbered Playwright tests exist in the hosted lane (the desktop-shim config `playwright.config.ts`, whose `npm run server:local` web server already runs with `MM_AGENT_BRIDGE=1` and in-memory Azurite), one per demo, titled `E<n>: PRD 027 Req 15a|15b|15c — …`. Ids start at the next unused E number (E659 at spec time; re-check with `grep -rhoE "'E[0-9]+:" tests | sed "s/'E//;s/://" | sort -n | tail -1`). They live either appended to `tests/e2e/hosted.spec.ts` or in a new hosted-lane file (e.g. `tests/e2e/agent-bridge-demos.spec.ts`) that imports the existing hosted helpers (`signIn`, `createWorkspace`, `signInTo`, `openFromSidebar`, `mintToken`, `mcpRpc`/`mcpTool`, `turnAgentBridgeOn`, `optIn`, `intoEditMode`) lifted into a shared non-spec module — never duplicated. `tests/e2e/agent-bridge.spec.ts` (the issue #366 dev-shim suite) is left as is; it does not drive the MCP endpoint and is not the home for these.
- Each demo is end to end through the real seams: a fresh workspace per test (the `E<n> w${workerIndex}` naming and the `finally` cleanup of `settings.json` and the workspace, as E655–E658 do), a token minted through `POST /api/workspaces/<id>/agent-tokens`, every agent action a `tools/call` over `POST /api/mcp` with `Authorization: Bearer <token>` (the existing `mcpTool` helper, or an MCP client library if one is added as a devDependency — raw HTTP is fine and preferred), and a real tab signed in with `signInTo`, the `agentBridge` setting turned on through Settings → Experimental → Save (`experimental-agent-bridge`), and opted in through the `agent-control-toggle` (`optIn`). No dev-shim transport, no `page.evaluate` into app internals, no `__mm*` seam.
- **Demo a — Create.** The agent calls `create_file` with a path and given Markdown content (no browser involvement; the result is not an error), then `open_file` for that path. Afterwards, without a page reload, the controlled tab's folder panel lists the new file (`folder-item` with its name has count 1 — opening a document re-lists its ancestor directories per SPEC34 §5, so no new refresh mechanism is needed as long as the folder panel is visible), `docname` shows it, and its content is rendered in preview (a heading or paragraph from the given content is visible). `read_file` returns the same content.
- **Demo b — Navigate.** A long document (e.g. the 277-line `fixtures/field-guide.md` PUT through the files route, or a generated document of a few hundred lines) is open in the tab in edit mode (`scroll` answers a typed failure in preview mode; the demo runs where it works). The agent reads `get_editor_state` and the snapshot's `scroll.topLine` is 1 with `scroll.totalLines` matching the document; the agent calls `scroll` with `{ target: { by: 'pages', amount: 1 } }`; a following `get_editor_state` reports a `scroll.topLine` greater than before, and the tab's viewport visibly moved (the editor's scroll container has a `scrollTop` greater than 0, or a line from the top of the document is no longer within the viewport while a later one is). The assertion is on direction and non-zero movement, not an exact line count.
- **Demo c — Transform selection.** The user selects a passage in the tab themselves (keyboard or mouse selection inside the CodeMirror content in edit mode — not `set_selection`). `get_editor_state` reports that passage as `selection.text` with a `revision`; `replace_selection` with that revision and new text succeeds and the returned state carries the new text, `dirty: true` and a new revision; `apply_format` with that new revision and a `SmartFormatOp` such as `bold` succeeds; the tab shows the replaced, formatted text (e.g. `**<new text>**` in the editor content) and the `dirty-dot` is visible. Pressing undo in the tab once walks back only the format (the replaced but unformatted text remains), pressing it again restores the original passage — one undo step per tool call; the order in which the test proves undo versus save is the implementer's, but the `save` tool is what clears the dirty state: before it the server-side file (via `read_file` or `GET /api/workspaces/<id>/files/<path>`) is unchanged, after it the file carries the buffer content and the `dirty-dot` has count 0.
- Each demo cites the PRD in its title and a comment: `// PRD 027 Req 15a (issue #368): …` (the citation format in `.sandcastle/CODING_STANDARDS.md`). Existing tests are not changed, weakened, skipped or renumbered. If a new spec file is added, Playwright collects it by glob (no config edit); `E2E_TEST_FLOOR` in `scripts/validate.mjs` may be re-pinned upward to the collected count per the convention documented beside it (647 collected at spec time; the floor is 479), but is never lowered.

### The setup page (PRD 027 Req 16)

- `docs/AGENT-BRIDGE.md` exists: a short page (well under 150 lines) that lets the owner run the side-by-side demo from a clean deployment. It covers, in order: (1) the server flag — `MM_AGENT_BRIDGE=1` on the App Service (pointing at the `MM_AGENT_BRIDGE` rows and the Web sockets switch in `docs/HOSTING-AZURE.md` / `docs/HOSTING-AZURE-PORTAL.md`) and, for local development, `MM_AGENT_BRIDGE=1 npm run server:local` at `http://localhost:4924`; (2) the experimental setting — Settings → Experimental → “Agent bridge”, default off, saved with Save, no reload; (3) minting a token — Workspace settings (Manage) → Agent tokens, label, mint, copy the plaintext shown exactly once, and how to revoke; (4) the exact invocation, in a fenced `sh` block, `claude mcp add --transport http marky-mark https://<origin>/api/mcp --header "Authorization: Bearer <token>"` (the same line `server/README.md` states — the two must agree), with the local-mode variant using `http://localhost:4924/api/mcp`; (5) opting the tab in — the agent-control toggle and the persistent indicator, one controlled tab per workspace, file tools working without a tab; (6) the three demo prompts to type into Claude Code, one per anchor demo, mapped to the tools they exercise (`create_file`/`open_file`; `get_editor_state`/`scroll`; `get_editor_state`/`replace_selection`/`apply_format`/`save`). It states the scope guards the owner must know: the token is workspace-scoped, shown once, never logged; the bridge is create/read/update only (no delete/rename); and it notes the experimental posture. It does not duplicate the route table or tool reference — it links to `server/README.md` (“Agent bridge (PRD 027)”) for those.
- The page is linked from an existing `docs/` page in the place a reader would look (the agent-bridge paragraph of `docs/HOSTING-AZURE.md` near the Web sockets step, and/or the hosted-flavor bullet in `docs/DEVELOPING.md`), from `server/README.md`'s “Agent bridge (PRD 027)” section, and named in `AGENTS.md`'s directory map (the “the rest of `docs/` holds …” sentence, or a one-line bullet) — `AGENTS.md` stays within its ~150-line budget, and `CLAUDE.md` remains the symlink (the quick gate checks it).

### docs/MAP.md

- `docs/MAP.md` is byte-identical to what `npm run map` generates from the tree (the quick gate diffs it). The map is keyed on `SPEC<n>` citations, not PRD ones: if the new tests cite a SPEC (e.g. SPEC34 §5 for the tree re-list in demo a), the regenerated map lists their E numbers under that spec and the result is committed; if they cite only PRD 027, the map is unchanged and that is correct.
