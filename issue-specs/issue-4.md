# Spec: Split preview chevron toggle (collapse/expand at the right edge) (#4)

## Goal

All acceptance criteria in issue-specs/issue-4.md are satisfied for issue #4, with evidence visible in the session: with the split preview open (`mode === 'edit'` and `settings.splitEdit`) a right-pointing chevron (`data-testid="preview-collapse"`) at the preview's top-right corner closes the split, with it closed a left-pointing chevron (`data-testid="preview-expand"`) pinned at the full-screen editor's top-right edge reopens it, both chevrons flip only `settings.splitEdit` and stay in sync with the View → Split Edit menu / `Mod+\` / the Settings panel's `set-split-edit` checkbox, and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- When the split preview is open (`mode === 'edit'` and `settings.splitEdit`), a right-pointing chevron button sits at the split preview's top-right corner and closes the preview (`splitEdit → false`, i.e. today's full-screen editor). It carries `data-testid="preview-collapse"`, a tooltip, and an `aria-label` (e.g. "Hide the preview pane"). (PRD Req 6)
- When the preview is closed (`mode === 'edit'`, `splitEdit` off), a left-pointing chevron button stays pinned at the top-right edge of the full-screen editor and reopens the split (`splitEdit → true`). It carries `data-testid="preview-expand"`, a tooltip, and an `aria-label` (e.g. "Show the preview pane"). (PRD Req 7)
- The chevrons flip only `settings.splitEdit` — no new settings or state keys, dispatched through the existing `toggleSplit` command path. The View → Split Edit menu checkbox, `Mod+\`, and the Settings panel checkbox (`data-testid="set-split-edit"`) all reflect chevron clicks, and `splitEdit` persists to `settings.json` exactly as it does today (e2e E84 in `tests/e2e/app.spec.ts` is extended to cover the chevrons). (PRD Req 8)
- In full preview mode (`mode === 'preview'`) neither preview chevron renders — full preview is a different surface, not a "closed preview" — and on the splash (no document, preview mode) neither renders either.
- The chevrons' hit targets are compact (comparable to the folder pane's chevron buttons), do not obscure preview or editor content beyond that target, and render correctly in both light and dark themes. Chevrons are hand-written inline SVGs reusing the existing `Chevron` component style from `src/components/FolderPanel.tsx` — no icon library.
- Existing behavior is untouched: the split divider drag and double-click reset (`splitRatio`), the `Mod+\` hotkey, the menu item, and the Settings checkbox all keep working; slide animations (PRD Reqs 9–11) and the folder-pane chevrons (Reqs 1–5, already landed) are out of scope.
- `npm run validate:quick` passes, run in the implementer's session. Iterate with `npm run typecheck` and `npm run test:unit` (or Playwright tests targeted at the changed specs, e.g. `npx playwright test -g "E84"`) while developing; run the full `npm run validate:quick` gate ONCE, right before declaring the goal met — not after every small change, and not as a start-of-attempt baseline (baseline with the quick iteration commands only).
- A summary comment from the implementer exists on issue #4.
