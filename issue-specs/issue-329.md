# Spec: Flat sidebar: header without rule, open files unlifted, only the active file tinted (#329)

## Goal

All acceptance criteria in issue-specs/issue-329.md are satisfied for issue #329, with evidence visible in the session: the sidebar header row (`.folder-header`, shared by the folder, outline and search views) has no `border-bottom` while keeping its height, padding, controls and `--mm-bg-elevated` ground (PRD 025 Req 13); `.folder-item.open` has no background, `box-shadow`, `z-index` or pill geometry (no left margin, radius or min-width) and the `--mm-lift-row` / `--mm-lift-row-active` tokens are gone from `src/styles.css` with no remaining `var()` reader (Req 14); the active file `.folder-item.selected` is the only tinted row — a flat full-width `color-mix(in srgb, var(--mm-accent) 14%, transparent)` background declared once as an internal token, `--mm-radius-small` corners, bold label, no shadow — with hover on other rows resolving through `--mm-hover` (Req 15); open rows keep their dirty-dot / close slot and the outline and search rows are unchanged (Req 16); SPEC34 §3 and SPEC36 §4.1 carry amendment notes and the changed CSS carries `PRD 025 Req 13–15` citations; the plane assertions in `tests/e2e/folder-tree.spec.ts` (E93, E305) are rewritten not deleted and a new E-numbered test proves the active-file row is the only tinted row; `npm run validate:quick` has been run once at the end and prints `QUICK VALIDATION: ALL PASSED`; and a summary comment from the implementer exists on issue #329.

## Acceptance criteria

- **Header without a rule (PRD 025 Req 13).** The `.folder-header` rule in `src/styles.css` (grep `.folder-header {`) declares no `border-bottom`. Its `padding` is adjusted so the header keeps its current 38px rendered height (the comment there says "38px with the rule: the tab strip's height" — the removed 1px goes back into the padding), and its `display`/`gap`/controls are untouched. Because `TocPanel.tsx` (`toc-header`), `SearchPanel.tsx` (`search-header`) and `FolderPanel.tsx` (`folder-header`) all render the same `.folder-header` class, all three views lose the rule with the one CSS change; no TSX change is needed for this criterion. The header's ground stays the panel's `--mm-bg-elevated` (no new background on the header). A computed-style check on `folder-header` shows `border-bottom-width: 0px`.
- **Open rows unlifted (PRD 025 Req 14).** After the change `.folder-item.open` (and `.folder-item.open:hover`) sets no `background`, no `box-shadow`, no `z-index`, no `position`, and the shared `.folder-item.selected, .folder-item.open` pill-geometry rule (`border-radius … 0 0 …`, `margin-left: 10px`, `min-width: calc(100% - 10px)`, `padding-left: max(0px, calc(var(--mm-depth) - 10px))`) no longer applies to `.open`. An open-but-inactive row is therefore visually identical to a closed sibling except for its trailing slot and the `open` class (which stays — 20+ tests and `FolderPanel.tsx` line ~646 key on it). The `--mm-lift-row` and `--mm-lift-row-active` custom-property definitions (grep `mm-lift-row` in `src/styles.css`, ~line 155) are deleted along with their `var()` readers; `--mm-lift-tab` / `--mm-lift-tab-active` stay (sibling #331 owns the strip). The style lint (`every var(--mm-…) names a defined property`) stays green.
- **Only the active file is tinted (PRD 025 Req 15).** `.folder-item.selected` is a flat row: full width (no `margin-left`, no `min-width` compensation, plain `padding-left: var(--mm-depth, 10px)` like any other row), `background` = a new internal token declared ONCE in the token block of `src/styles.css` next to `--mm-hover` / `--mm-active-word` (name at the implementer's discretion, e.g. `--mm-selected-row: color-mix(in srgb, var(--mm-accent, #0969da) 14%, transparent)`; the literal lives only in that definition, so the lint passes), `border-radius: var(--mm-radius-small)` on all four corners, `font-weight: 600`, `color: var(--mm-fg)`, no `box-shadow`, no `z-index`, no `position`. `.folder-item.selected:hover` keeps the same tint (no flicker). Hover on every other row (`.folder-item:hover:not(:disabled)`) resolves through `var(--mm-hover)` — the existing fg-9% mix existed only to "stay on the panel plane", which no longer exists. Every bundled theme in `themes/` defines `--mm-accent`, so the tint renders under all of them without theme edits. The scratch row (`folder-item-scratch`, `FolderPanel.tsx` ~line 594) uses the same classes and gets the same treatment for free; the outline's `.folder-item.toc-active` rule is unchanged (its comment that contrasts it with "the selected tab pill" is reworded).
- **Row affordances and other views unchanged (PRD 025 Req 16).** `.folder-tab-slot`, `.folder-dirty` and the close button on open rows are untouched (E93's dirty-dot assertion and the E-tests on `folder-dirty` / `folder-close` keep passing). The outline (`toc-*`) and search views keep their current row styling; their only change is the shared header losing its rule.
- **Reveal scroll still vertical-only.** The reveal effect in `FolderPanel.tsx` (~line 780, "Vertical-only reveal … the selected tab's left gap") keeps restoring `scrollLeft`; its comment no longer describes a tab's left gap. No behavioural change to reveal, expansion, or open/close is made.
- **Spec amendments and citations.** `docs/specs/SPEC34.md` §3 item 3 (the header) gains a `> **Amended (issue #329, 2026-09-07):** …` note in the repo's existing style stating that the header row carries no bottom rule and sits on the same ground as the tree (PRD 025 Req 13). `docs/specs/SPEC36.md` §4.1 gains an amendment note stating that the three-plane / tab-pill treatment is retired: open rows are plain rows with a trailing slot, and the active row is a flat accent-tinted, rounded, bold row — the only highlighted row (PRD 025 Reqs 14–15). The changed CSS rules carry `/* PRD 025 Req 13 (issue #329): … */`, `Req 14`, `Req 15` citations per `.sandcastle/CODING_STANDARDS.md`; stale comments in `src/styles.css` that describe the sidebar rows as planes (`.folder-header` preamble, the `.folder-item.selected` / `.open` blocks, `.folder-item:hover`) are rewritten. Comments in the tab-strip section that call the strip "`.folder-item.open`'s analogue" may stay — #331 rewrites that section. PRD 013 Reqs 10–12 and the `.workspace-stack::after` seam are NOT touched here (sibling #331); the PRD-wide sweep (Req 29) belongs to #332. If `npm run map` output changes (new `PRD 025` citations in `src/` / `tests/`), the regenerated `docs/MAP.md` is committed alongside.
- **Existing tests rewritten, not deleted (PRD 025 Req 30).** In `tests/e2e/folder-tree.spec.ts`: E93's "selected tab floats clear of the panel's left edge" block (the `pill()` helper asserting `gap >= 10`) is rewritten to assert the flat form — the selected row's left edge equals the list's left edge (gap 0 / no margin) and `scrollLeft` stays 0 — and its "panel plane / front plane" comment wording is replaced. E305 keeps its number and its column-alignment guarantee (open, closed and active labels on one column per depth); its comment no longer describes pill compensation. No test is deleted, renumbered, weakened, or marked skip/only.
- **New test: the active row is the only tinted row (PRD 025 Req 30).** A new test in `tests/e2e/folder-tree.spec.ts` takes the next unused E-number (E581 at spec time; re-check with `grep -rhoE "test\('E[0-9]+" tests/e2e | sort -t E -k2 -n | tail -1` before committing). With a root open, one file active and at least one other file open-but-inactive plus a closed sibling, it asserts from computed styles: the `.selected` row's `backgroundColor` is not transparent and differs from the panel's; EVERY other `.folder-item` (open and closed alike, hover not engaged) has a transparent background (`rgba(0, 0, 0, 0)`); the selected row has `boxShadow === 'none'`, `zIndex === 'auto'` and `marginLeft === '0px'`; the open row has `boxShadow === 'none'`; the header (`folder-header`) has `borderBottomWidth === '0px'`; and the open row still shows its `folder-dirty` / close slot. Optionally the same assertions are repeated under a dark theme (One Dark, as E306 does) to prove the tint is theme-derived.
- **Iteration economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (plus targeted e2e runs such as `npx playwright test -g 'E93'`, `-g 'E305'`, `-g 'E581'`) after each change, and baselines an attempt with the quick tier only — never with the full gate.
- **Full gate.** `npm run validate:quick` has been run ONCE in the implementer's session, right before declaring the goal met (not after every small change and not as a baseline at the start), and prints `QUICK VALIDATION: ALL PASSED`.
- **Summary comment.** A summary comment from the implementer exists on issue #329 describing the CSS changes (header rule, unlifted open rows, the new tint token), the amendment notes added, the rewritten and new test numbers, and the validate:quick result.
