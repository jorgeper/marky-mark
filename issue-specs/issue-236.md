# Spec: Sever editor→app couplings: heading-link seam and imageView URL helpers (#236)

## Goal

All acceptance criteria in issue-specs/issue-236.md are satisfied for issue #236, with evidence visible in the session: the editing-surface module graph no longer reaches `shareLinks`/`hostedPaths` (heading-link URLs flow only through the `HeadingLinkSeam` callback) or `src/lib/markdown.ts` (the `isRemoteSrc`/`remoteHost` helpers live in a pure editor-side module), behavior is preserved with `npm run validate:quick` passing, and a summary comment from the implementer exists on issue #236.

## Acceptance criteria

- (PRD 021 Req 5) The `headingLinks → shareLinks → hostedPaths` import edge no longer exists: `src/lib/headingLinks.ts` does not import `./shareLinks` (directly or transitively). The pieces it uses today — `createCopyLinkController`, `COPY_LINK_HEADING_LABEL`, `LINK_COPIED_LABEL` — live in a pure module inside the editor subtree, and the dependency direction is reversed: `shareLinks.ts` (and the app placements `CopyLinkButton.tsx` / `App.tsx`) obtain them from that module (import or re-export), never the other way. Heading-link URL construction continues to arrive only through the existing callbacks (`HeadingLinkSeam.getUrl` in `Editor.tsx`, `getUrlForLine` in `decorateHeadingLinks`); no editor-subtree module constructs hosted URLs.
- (PRD 021 Req 6) `src/components/imageView.ts` no longer imports `src/lib/markdown.ts`: `isRemoteSrc` and `remoteHost` move into a pure module inside the editor subtree (no unified/remark or other app imports), `imageView.ts` imports them from there, and `markdown.ts` consumes the same module (import or re-export) so there is exactly one definition and no behavior fork. After the change, the unified/remark pipeline is reachable only from preview-side rendering code (`App.tsx`'s `renderMarkdown` path), never from the editing surface (`Editor.tsx` and its companion modules and their pure libs).
- The severance is demonstrable in-session: a static import check (e.g. `rg -n "from '.*shareLinks'" src/lib/headingLinks.ts` and `rg -n "from '.*lib/markdown'" src/components`) comes back empty for the cut edges.
- Behavior is preserved: no exported API contract used by callers changes semantics; existing unit tests (`tests/unit/heading-links.test.ts`, `tests/unit/share-links.test.ts`, image tests) and e2e suites pass without behavioral edits — mechanical import-path updates only.
- Moved/new code keeps its citation comments (e.g. `SPEC41 §2.1` on `isRemoteSrc`, the PRD 020 Req 18 comments in `headingLinks.ts`), any new module carries citations for what it implements, and `docs/MAP.md` is regenerated with `npm run map` if citation sites changed files (the gate diffs it).
- The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code) after each change, and ran the full gate `npm run validate:quick` ONCE, right before declaring the goal met — not after every small change and not as a baseline — and it printed `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- A summary comment from the implementer exists on issue #236.
