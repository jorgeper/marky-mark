# Spec: PRD 026: strict lowercase-dash rule for chosen URL names, one slugifier, grandfathered legacy names, server enforcement (#350)

## Goal

All acceptance criteria in issue-specs/issue-350.md are satisfied for issue #350, with evidence visible in the session: `uniqueNameProblem`/`uniqueNameFormatProblem` in `src/lib/workspaceNames.ts` accept only `^[a-z0-9]+(-[a-z0-9]+)*$` (1–100 chars) for a chosen name while a separate legacy rule keeps accepting PRD 020's `[A-Za-z0-9._-]` charset for stored `uniqueName`/`formerNames` in `src/lib/hostedWorkspace.ts`; one exported pure slugifier in `workspaceNames.ts` maps `Team Docs`→`team-docs`, `  Hello, World!! `→`hello-world`, `jane.doe`→`jane-doe`, `A--B`→`a-b` and `!!!`/`日本語`→`""`, with the migration planner and the server's name-only create fallback supplying `workspace`; `POST /api/workspaces` and a manifest `PUT` whose `uniqueName` differs from the stored one answer 400 with the pure rule's own message for a non-conforming name while a `PUT` that keeps the stored (possibly grandfathered) name is not re-validated; unit tests cover the accept/reject table, the slugifier examples and the legacy-vs-strict split; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #350.

## Acceptance criteria

- **Strict rule for chosen names (PRD 026 Req 1).** `uniqueNameFormatProblem` and `uniqueNameProblem` in `src/lib/workspaceNames.ts` return `null` only for names matching `^[a-z0-9]+(-[a-z0-9]+)*$` with length 1–100. Uppercase (`Design-Docs`), dots (`a.b`), underscores (`a_b`), leading/trailing/consecutive dashes (`-a`, `a-`, `a--b`), spaces, slashes, non-ASCII and the empty string each earn a non-null message; the empty-name and over-length messages stay distinct from the charset message. `UNIQUE_NAME_MAX_LENGTH` stays 100, `RESERVED_WORKSPACE_NAMES`, `isReservedWorkspaceName` and `uniqueNameKey` are unchanged, and `uniqueNameProblem` still layers the reserved-word refusal on top of the format check. The charset message wording is the implementer's choice (it should read naturally next to PRD 026 Req 7's guidance, e.g. mention lowercase letters, numbers and dashes) but is defined in exactly one place and is what every caller shows.
- **Legacy rule kept for stored names (PRD 026 Req 9).** `workspaceNames.ts` exports a second pure format check for the PRD 020 charset (`^[A-Za-z0-9._-]+$`, 1–100 chars) and `validateWorkspaceManifest` in `src/lib/hostedWorkspace.ts` validates `uniqueName` and every `formerNames` entry with that legacy check, so a manifest carrying `Team_Docs`, `Design-Docs` or `team.docs` still parses and round-trips. Path resolution (`src/lib/hostedPaths.ts`), listings and share links are untouched and keep matching such names case-insensitively through `uniqueNameKey`.
- **One slugifier (PRD 026 Req 2).** `workspaceNames.ts` exports a single pure slugifier that lowercases, collapses every run of characters outside `[a-z0-9]` to one dash, strips leading and trailing dashes, clamps to 100 characters and strips trailing dashes again after clamping. Observable examples: `Team Docs`→`team-docs`, `  Hello, World!! `→`hello-world`, `jane.doe`→`jane-doe`, `A--B`→`a-b`, `release.notes_v2`→`release-notes-v2`, `!!!`→`""`, `日本語`→`""`, and a 150-character run of `x` followed by `-` material clamps to 100 characters with no trailing dash. Every non-empty output satisfies Req 1. The function is exported so issue #351 (usernames) can import it; `src/lib/usernames.ts` is NOT changed by this issue.
- **Fallback word stays with the callers.** `planUniqueNameMigration` and the server's name-only create path (`POST /api/workspaces` with `name` but no `uniqueName`, `server/workspaces.ts`) and the scratchpad provisioning path substitute `workspace` when the slug is empty and otherwise mint `dedupeUniqueName(slug, taken)` exactly as before. `dedupeUniqueName` and `planUniqueNameMigration` keep their behaviour (suffixes `-2`, `-3`…, reserved words count as taken, length clamp, oldest-first, idempotent). A name-only create for `Team Notes!` now yields `team-notes` and a second one `team-notes-2`; `My scratchpad` still yields `my-scratchpad`.
- **Server enforcement (PRD 026 Req 3).** `POST /api/workspaces` with a `uniqueName` that fails Req 1 answers 400 with `{ error: <the pure rule's message> }` (this already flows through `buildNewWorkspaceManifest` → `uniqueNameProblem`; it must keep doing so). A manifest `PUT` whose body `uniqueName` differs from the stored value answers 400 with the same message when the new name fails Req 1, before any collision scan. A `PUT` whose `uniqueName` equals the stored value, or omits the field, is never checked against Req 1, so a grandfathered `Team_Docs` workspace can still save display-name, member and role changes. Reserved-word 400s and case-insensitive 409 collisions behave exactly as today (a chosen `alpha` against a stored grandfathered `Alpha` is a 409).
- **Client hints agree with the server.** The New Workspace dialog (`src/lib/workspaceLifecycle.ts` `validateNewWorkspaceForm`, `src/components/WorkspaceSwitcher.tsx`) and the settings Names section (`src/components/WorkspaceNames.tsx`) keep calling `uniqueNameProblem` and therefore show the tightened rule as you type with no layout, label, test-id or behaviour change. No form work from PRD 026 Req 4–8, 10, 12 lands here (issues #352–#354 own it).
- **Unit coverage (PRD 026 Req 13, workspaceNames part).** `tests/unit/workspace-names.test.ts` has tests, each titled with the next unused `U<n>:` id (U1314 upward; never reuse a number), for: the Req 1 accept/reject table (including `a-b`, `a1`, `0`, a 100-character name accepted; uppercase, dots, underscores, leading/trailing/double dashes, spaces, non-ASCII, empty and 101 characters refused with the named problem); the Req 2 slugifier examples above plus empty output and the post-clamp trailing-dash strip; and Req 9 (the legacy check accepts `Team_Docs`, `Design-Docs`, `a.b` while the strict check refuses them, and both refuse `a b` and the empty string). `tests/unit/hosted-workspace.test.ts` shows a manifest with a legacy-charset `uniqueName` and `formerNames` entry still validating, and `tests/unit/server-workspaces.test.ts` shows: POST 400 for a strict-rule failure with the shared message; PUT rename to a non-conforming name is 400; PUT of a storage-seeded grandfathered manifest (e.g. `uniqueName: 'Team_Docs'`, written straight into the storage fake) that changes only `name` is 200 and keeps `Team_Docs`; renaming that grandfathered workspace to `team-docs` is 200 and records nothing in `formerNames` (case-only change per PRD 024 Req 2 — the previous U1236 `hist-b`→`Hist-B` scenario is inverted to seed the mixed-case name); a chosen lowercase name colliding case-insensitively with a seeded mixed-case stored name is 409.
- **Existing tests updated to the amended contract, not weakened.** Tests that encode PRD 020's charset as the rule for chosen names are rewritten in place under their existing ids to assert PRD 026's rule: U1044 (accepted set becomes lowercase-dash names, refused set gains uppercase/dot/underscore/edge-dash cases, message updated), U1046 (slugifier examples and empty-output; the `workspace` fallback assertion moves to a planner/fallback test), U1053 (`Design-Docs` becomes a lowercase chosen name and the case-insensitive collision uses a storage-seeded mixed-case name), U1054 (`ALPHA` collision uses a seeded name or lowercase), U1057 (`team-notes`/`team-notes-2`), U1236 (inverted as above), U1238 (`Reclaim-Me`/`GIVER` become lowercase or seeded), the U1234-area manifest charset table, and workspace-lifecycle.test.ts lines asserting the old message text. No test is deleted, skipped or renumbered; the e2e suite (`tests/e2e/hosted.spec.ts`) needs no change because every name it types is already lowercase-dash.
- **Citations.** Every changed behaviour carries a `PRD 026 Req <n>` citation comment per `.sandcastle/CODING_STANDARDS.md`; the `workspaceNames.ts` module header names PRD 026 as amending PRD 020 Req 1+3. No `console.*` in `src/`; `src/lib/` stays import-free of React/Tauri.
- **Verification economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (or `npx vitest run tests/unit/workspace-names.test.ts tests/unit/hosted-workspace.test.ts tests/unit/server-workspaces.test.ts tests/unit/workspace-lifecycle.test.ts`) after each change, and does not run the full gate as a baseline at the start of an attempt.
- **Gate.** `npm run validate:quick` has been run once in the implementer's session, right before declaring the goal met, and prints `QUICK VALIDATION: ALL PASSED`.
- **Summary comment.** A summary comment from the implementer exists on issue #350 describing what changed, the tests added/updated, and the gate result.
