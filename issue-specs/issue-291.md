# Spec: The scratch buffer reads as "Scratch file": placeholder name plus accent/italic chrome token (#291)

## Goal

All acceptance criteria in issue-specs/issue-291.md are satisfied for issue #291, with evidence visible in the session: the buffer the scratch boot opened displays as **"Scratch file"** in the toolbar name, its file tab and the browser tab title (with the usual dirty dot), rendered in the accent colour and italic through a new chrome token that every bundled theme restyles for free while every other untitled buffer keeps "Untitled" and normal styling; unit coverage exists for the display-name resolution and for the new token across all 27 bundled themes; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #291.

## Acceptance criteria

- **Req 6 — placeholder name.** While the scratch buffer (the one the PRD 023 Req 1/3 boot opened, marked in `src/App.tsx` today by `scratchRef`) is the current document, the displayed document name is **"Scratch file"** in all three places a document name is shown: the toolbar's `<workspace> / <file>` name (`Toolbar`'s `docName`, `src/App.tsx:7198`), its tab in the file tab strip (`FileTabStrip`'s untitled tab, currently hard-coded `label="Untitled"`), and the window/browser tab title (the `setTitle` + `document.title` effect at `src/App.tsx:~5910`). No name prompt is shown at boot — entering scratch still lands straight in an empty buffer in edit mode.
- **Req 7 — accent + italic, from a chrome token.** In the toolbar name and the file tab the placeholder renders in the theme accent colour and in italic, and the usual unsaved dot still shows when the buffer is dirty. Both properties come from a **new chrome token pair** (e.g. `--mm-scratch-name` / `--mm-scratch-name-style`) declared inside the `CHROME TOKENS — BEGIN/END` block of `src/styles.css` on the `.theme-root` scope, with the colour derived from the contract variable `--mm-accent` (PRD 018 Req 2) so no bundled theme has to define anything. The token(s) are documented in **both** `THEMES.md` ("Chrome tokens (optional)" table) and `docs/STYLE-GUIDE.md` (the chrome token table), which is also what keeps the style lint's "var() must name a defined property" rule satisfied. No colour, font-style or size literal is introduced at the call sites (the lint enforces this).
- **Req 8 — scoped to the scratch buffer only.** Any other untitled buffer keeps the label "Untitled" and the normal styling everywhere — including a ⌘N buffer opened inside the scratch workspace, and including the buffer left after the scratch marker is cleared (a save, a real document replacing it, closing to the splash). Named files are untouched.
- **The marker is renderable.** The scratch state that Reqs 6–8 read is available at render time (the issue's "promoted from a ref to render state"): a ref alone does not re-render the toolbar/tab/title when it is armed or cleared. Every existing `scratchRef` guard site in `src/App.tsx` (the unsaved-changes prompts, the close guard, the quit walk, the Save As pre-fill) keeps reading a value that is correct **synchronously** at the moment the guard runs — state may not lag those reads.
- **Nothing else moves.** No change to the New File / right-click new-file flow anywhere, including inside the scratch workspace (PRD 009 Reqs 13–14); no change to discard semantics (PRD 019 Req 11); no change to the first-save name pre-fill (that is issue #292); no rename of the "My scratch" workspace (PRD 020 Req 10) — only the unsaved buffer gets the label. The treatment is fixed and token-driven: no per-user styling toggle, no setting. Desktop (Tauri) and single-file builds are unaffected in practice, since only the hosted platform's `scratchStart` boot arms the marker (PRD 019 Req 4).
- **Unit coverage for the display-name resolution.** The name decision is a pure, unit-testable helper (a small function in `src/lib/`, in the mold of the existing lib modules — not logic reachable only through the DOM). New `U<n>:`-titled tests (next free number after U1123) cover: named document → its basename; ordinary untitled → "Untitled"; scratch buffer → "Scratch file"; and that the same helper is what the toolbar, the tab strip and the title effect consume, so the three surfaces cannot drift.
- **Theme coverage for the new token.** A unit test walks every bundled theme in `themes/` (all 27, in the mold of `tests/unit/theme-catalog.test.ts` U14) and asserts the placeholder treatment stays readable on each: the token is not defined by any bundled theme yet resolves for all of them because it derives from `--mm-accent`, which every bundled theme defines with a value distinct from its `--mm-bg`. The existing style-lint suite (`tests/unit/style-lint.test.ts`) and `npm run validate:quick`'s style-lint step must still pass with the new token in place.
- **A stable hook for the hosted e2e slice.** The scratch name carries a class or data attribute in both the toolbar and the tab (e.g. `data-scratch="true"`) that a test can assert on, so issue #293's hosted e2e can pin Reqs 6–7 without re-reading computed colours by luck. Hosted e2e for this behaviour is **issue #293's slice** — it is not required here, and the desktop-shim e2e count floor in `scripts/validate.mjs` must not regress.
- **Citations.** Every changed or added behaviour site carries its contract citation in the repo's format (`// PRD 023 Req <n>: <what and why>`, alongside the PRD 018/019 citations already there), per `.sandcastle/CODING_STANDARDS.md`. The `scratchRef` declaration comment at `src/App.tsx:~460` ("A ref, not state: no UI renders from it") is updated to match reality.
- **Test economy.** Iteration uses `npm run typecheck` and `npm run test:unit` (or a targeted `npx vitest run <file>` / `npx playwright test -g '<title>'` for one behaviour). The full gate is run **once**, right before declaring the goal met — not after every change, and not as a start-of-attempt baseline (baseline with the quick tier only).
- **`npm run validate:quick` passes**, run in the implementer's session, printing `QUICK VALIDATION: ALL PASSED`. It includes the docs/MAP.md freshness check (run `npm run map` and commit the result if it complains), the test-ID uniqueness check, the style lint and the e2e count floor.
- **A summary comment from the implementer exists on issue #291**, describing what changed and carrying the validate:quick evidence.

## Context

The scratch marker is `scratchRef` in `src/App.tsx:468`, armed only at `src/App.tsx:~2800` when the hosted boot sets `platform.scratchStart` (`src/platform/hosted.ts:100`, `src/platform/types.ts:268`) and cleared in `startUntitled` (`src/App.tsx:~3801`), on `openDoc` (`~2235`), on close (`~2378`) and after a save. Guard sites that read it: `~2328/2346` (unsaved prompts), `~2511`, `~2531`, `~4015` (close guard / quit walk), `~4510`, and `~3501` (the Save As pre-fill — issue #292's territory, leave its behaviour alone). Reads happening inside callbacks off `stateRef` are the reason a plain `useState` alone is not enough; the usual repo pattern is state for render plus a ref (or a `stateRef` field) for the synchronous reads.

The three display sites are all one-liners: `src/App.tsx:5910` (title effect), `src/App.tsx:7198` (`Toolbar docName`), and `src/components/FileTabStrip.tsx:366` (`label="Untitled"` on the appended untitled tab). Their markup hooks are `.docname` / `.dirty-dot` in `src/styles.css:552-578` and `.file-tab-label` (`FileTabStrip.tsx:132`).

Styling rules are in `docs/STYLE-GUIDE.md` (read it before touching chrome) and enforced by `scripts/style-lint.mjs` + `tests/unit/style-lint.test.ts`: chrome rules may not carry colour/size literals, and every `var(--mm-…)` must name a property defined in `src/styles.css` or listed in `THEMES.md`. The chrome-token block runs `src/styles.css:50-146`; the one-off internal tokens just below it (`--mm-toolbar-shadow`, `--mm-lift-tab`, …) show the alternative shape if a one-off fits better than a scale entry.
