# Spec: Centered page: keep the page centered with ground and shadow when both side panes are closed (withdraw PRD 025 Req 7) (#348)

## Goal

All acceptance criteria in issue-specs/issue-348.md are satisfied for issue #348, with evidence visible in the session: with both side panes closed the page column is centred in the body row at its PRD 025 Req 3/4 max width with equal ground either side (within 1px) and the page proper keeps its `--mm-radius-small` top corners, its `--mm-panel-shadow` and its four-sided 1px `--mm-border` outline exactly as with a pane open (one rule for zero, one or two panes; no `panes-none` full-width form remains); closing the sidebar or the comments column removes only that pane and the page re-centres without changing width; the static web build shows the same centred, shadowed page; E585, E589 and W19 are rewritten to assert the new rule, `prd/025-centered-page-layout.md` Req 7 is withdrawn (Reqs 8, 18 and 27 amended, mockups 4–5 marked superseded); `npm run validate:quick` has been run once in the implementer's session and passes; and a summary comment from the implementer exists on issue #348.

## Acceptance criteria

### A. One layout rule for every pane state

- With both side panes closed (the sidebar hidden and the comments column unmounted) at a 2000px-wide viewport, the page column (`.workspace-stack`) is horizontally centred in `.body-row`: the ground left of the column equals the ground right of it within 1px, and both are greater than zero. Its width equals the editor-only max from PRD 025 Req 3 (the same width E584 measures with a pane open, `max(--mm-content-width, --mm-pane-min)` plus the 1px outline on each side). With the split preview open in the same state its width equals the preview-open max from PRD 025 Req 4.
- In that both-closed state the page proper (`.workspace-stack > .workspace`) has the same computed treatment as with a pane open: `border-top-left-radius` and `border-top-right-radius` equal to `--mm-radius-small`, a `box-shadow` that is not `none`, and a 1px border on all four sides. The strip band and the column itself still paint no radius and no shadow (issue #340's geometry, E589, is unchanged).
- The `.body-row.panes-none > .workspace-stack { flex: 1 }` and `.body-row.panes-none > .workspace-stack > .workspace { … flat … }` rules in `src/styles.css` are removed (or reduced to a no-op). The `panes-none` class on `.body-row` may stay or go; if it stays, no rule uses it to change the page's width, radius, shadow or outline. Print output is unchanged: on paper the page still spans the sheet flat (the existing `@media print` rules keep their effect without depending on `panes-none`).
- The tab strip (when shown) spans the page column's width and sits above the page as before (PRD 025 Reqs 17–18): with both panes closed the strip band is as wide as the centred column, not the window, and the tabs' outlines, shadows and the page's top hairline under them are unchanged (E353 and E306 pass unmodified).

### B. Collapsing a pane removes only the pane

- Sidebar open then closed at a wide viewport: the page column's width is unchanged within 1px, and after the toggle its left ground equals its right ground within 1px. Comments column open then closed: the same. Toggling either pane applies no transition, transform or `will-change` on the column, the page proper, the body row or the pane wrappers (PRD 025 Req 9; E585's motion check is kept).
- Narrow windows behave as PRD 025 Req 5: when the window is narrower than the page's max width the page shrinks first, down to `--mm-pane-min` per pane, and below that `.workspace` scrolls horizontally. With both panes closed at a viewport narrower than the page's max, the column fills the body row (ground is zero on both sides) and its treatment (radius, shadow, outline) still applies. No new breakpoint or resize JavaScript is added.

### C. Static web build and reopen chevrons

- The static single-file web build (`npm run build:web`, tested through `npm run test:e2e:web`) at a 2000px viewport with comments off shows the page column centred with equal ground either side within 1px and the page proper rounded, shadowed and outlined on four sides; turning comments on mounts the 300px column hugging the page's right edge and the cluster re-centres, with the page's width unchanged. W19 is rewritten to assert this (its "flat and edge to edge" assertions and title go).
- The sidebar's reopen chevron and the comments' reopen chevron stay reachable in every pane state (PRD 025 Req 21). With the strip shown they remain in the strip's lead/trail slots on the band. With the strip hidden the `.edge-cluster-left` / `.edge-cluster` pills keep anchoring to the page column's top corners, not to the window edge: at a 2000px viewport with both panes closed and the strip hidden, each pill's bounding box is horizontally adjacent to the page column's corresponding edge (touching it or overlapping it by no more than the pill's own width), never at the body row's outer edge. W20 and E579 keep passing.

## Context

The issue has no comment thread. The centring rule already exists and is the one to keep: `.body-row` (`src/styles.css:2037`) is a `justify-content: center` flex row whose pane wrappers (`.folder-wrap` `:2460`, `.comments-wrap` `:922`) are `flex-shrink: 0` and whose page column `.workspace-stack` (`:2170`) is `flex: 0 1 var(--mm-page-w)` with `min-width: 0`. The only thing that breaks that rule with zero panes is the pair of `panes-none` overrides at `:2193` (column `flex: 1`) and `:2218` (page proper flattened); removing them yields the issue's target. `panes-none` is derived in `src/App.tsx:8325` from `sidebarShown || commentsPaneMounted`; its remaining users are tests (E585, E589, W19) and the two rules above, so it can be dropped or kept as an inert marker. Mind the `@media print` block (`src/styles.css` ~`:1790`, `.workspace-stack { flex: 1 !important }`), which already forces the full-width flat form on paper independently of the class.

Tests to rewrite: `tests/e2e/file-tabs.spec.ts:1477` (E585) and the closed tail of E589 (`:1573–1585`), `tests/e2e/web.spec.ts:682` (W19). Helpers `rectOf`, `sheetOf`, `flatSheet`, `tokenOf` and `openThree` already exist in `file-tabs.spec.ts`; E583 shows the equal-ground assertion pattern to reuse. Highest numbers in use: E594, W20. The `--mm-page-w` / `--mm-page-pane` tokens at `:2140–2150` are the width contract E584 measures (the column includes the page proper's 1px outline each side). The edge-cluster pills (`:2057–2090`) are absolutely positioned against the stack's `position: relative`, so they follow the centred column with no change; the criterion in section C only forbids anchoring them to the window edge. PRD 025 is at `prd/025-centered-page-layout.md` (note a separate `prd/025-fluid-mode.md` shares the number; the Fluid `PRD 025 Req 7` citations in `editor/` and `src/lib/settings.ts` are unrelated and must not be touched).
