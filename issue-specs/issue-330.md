# Spec: Move the edit/preview mode toggle from the toolbar into the page-level control group (#330)

## Goal

All acceptance criteria in issue-specs/issue-330.md are satisfied for issue #330, with evidence visible in the session: the `edit-toggle` button ("Preview ⌘E" / "Edit ⌘E") is no longer rendered by `src/components/Toolbar.tsx` and instead renders as the LAST member of the existing page-level control group (the `rightCluster` node in `src/App.tsx`, after the comments chevron), styled `.btn.btn-quiet.btn-sm`, with its label, `data-testid`, tooltip, `toggleEdit` hotkey display, `toggleMode` dispatch and render gate (`docGrants.edit && !hostedNothingOpen`) unchanged; with the file tab strip up it sits in `.file-tab-strip-trail`, and with the strip hidden (desktop `fileTabs` off, or the static single-file web build with no `multiFileSession`) the same node lands in the `.edge-cluster` control row at the page's top-right; the icon `mode-switch` and its neighbours are untouched; SPEC2 §4.1 and SPEC12's header list carry amendment notes and the moved code carries `PRD 025 Req 19` / `Req 20` citations; existing tests keyed to the toolbar placement (E141, E495, E206 wording) are rewritten not deleted and a new E-numbered test asserts the toggle is inside the strip's control group, absent from the toolbar, and present in `.edge-cluster` with the strip off; `npm run validate:quick` has been run once at the end and prints `QUICK VALIDATION: ALL PASSED`; and a summary comment from the implementer exists on issue #330.

## Acceptance criteria

- **Toolbar no longer renders the toggle (PRD 025 Req 19).** `src/components/Toolbar.tsx` renders no element with `data-testid="edit-toggle"`; the `canEdit` / `mode` / `onToggleMode` props that existed only for it are removed from `ToolbarProps` and from the `<Toolbar>` call in `src/App.tsx` (`hotkeys` stays: the menu rows still use it). The `.toolbar .btn kbd` rule in `src/styles.css` either moves to (or is generalised for) the toggle's new home so the `<kbd>` combo hint keeps its current size/colour treatment, or is retired if no toolbar button carries a `<kbd>` any more; the style lint stays green. `npm run typecheck` reports no unused props or dangling references.
- **Toggle is the last member of the page-level control group (PRD 025 Req 19).** The `edit-toggle` button is rendered inside the `rightCluster` fragment in `src/App.tsx` (grep `PRD 003 Reqs 6–7 + issue #125 + PRD 007 Req 17`), placed AFTER `CommentsToggleButton` so it is the group's last child in DOM order: `[copy-link-file?] [sync-scroll?] [mode-switch] [preview chevron?] [comments chevron?] [edit-toggle]`. It keeps `className="btn btn-quiet btn-sm"` plus `on` when `mode === 'edit'`, the text `Preview` / `Edit`, the `<kbd>` showing `displayCombo(settings.hotkeys.toggleEdit, platform.isMac)`, the `title` "Toggle edit / preview (…)", and `onClick` dispatching `toggleMode` via `dispatchCommand`. It may live as a small component (e.g. `ModeToggleButton` in `src/components/FolderPanel.tsx` beside `ModeSwitchButton`, or inline) — the implementer's choice — but every TSX `<button>` still passes the lint (carries `.btn*`).
- **Render gate unchanged (PRD 025 Req 19; SPEC2 §4.1 amendment #243; PRD 007 Req 17).** The toggle renders exactly when the toolbar rendered it today: `docGrants.edit && !hostedNothingOpen`. Concretely: on the desktop shim's splash (no document) it is still present and inert (E141 keeps its guarantee: clicking it leaves the splash in preview with no editor mounted); on the hosted home page with nothing open it is absent and reappears when a file opens (E495); for a read-only grant it is absent (E205, E206). The cluster's wrapper condition (`mode === 'edit' || mayToggleMode || fileShare || commentsSeam`) is widened so the cluster exists whenever the toggle's gate is true, otherwise the toggle would vanish on the desktop splash. `mode-switch` keeps its own `mayToggleMode` gate and is not removed, restyled or reordered (20 e2e sites and `tests/e2e/helpers.ts` read it).
- **Same position without the strip (PRD 025 Req 20, Req 27).** Because the toggle rides `rightCluster`, when `showFileTabs` is false the same node renders inside `<div className="edge-cluster">` at the workspace's top-right (the existing strip-hidden fallback, `src/styles.css` grep `edge-cluster`). This covers both the desktop build with the `fileTabs` setting off and the static single-file web build (no `multiFileSession`, so never a strip). The toggle is visible and clickable there in both preview and edit mode, and the `.edge-cluster` pill's sizing accommodates a labelled `.btn-sm` next to the icon buttons without clipping; any new spacing/colour resolves through PRD 018 tokens (no literal colours; lint green).
- **Behaviour otherwise unchanged.** `Mod+E` / the remapped `toggleEdit` hotkey (E6), the View ▸ menu `menu-view-toggleMode` row, `mode-switch`, and the toggle all dispatch the same `toggleMode` command; the selection / reading-position carry-over, autosave-on-toggle and the edit-grant guard are untouched. Existing tests that click `edit-toggle` after `revealToolbar` (E202, E212, E213, E215, E219, E220, E399, E536, E575 in `tests/e2e/hosted.spec.ts`) pass without functional edits, since the testid and behaviour are the same; stale `revealToolbar` calls that only served the toggle may stay or go.
- **Spec amendments and citations.** `docs/specs/SPEC2.md` §4.1 (the "Toolbar becomes: filename · Edit/Preview toggle · overflow menu button" composition and the #243 amendment beneath it) and the header list in `docs/specs/SPEC12.md` ("filename, Edit/Preview button, hamburger menu") each gain a `> **Amended (issue #330, 2026-09-07):** …` note in the repo's existing amendment style stating the toggle now lives in the page-level control group at the tab strip's right end (or the `.edge-cluster` row without a strip) per PRD 025 Reqs 19–20, and that the toolbar is filename · overflow menu. The moved code carries `// PRD 025 Req 19 (issue #330): …` (and `Req 20` at the strip-less fallback) per `.sandcastle/CODING_STANDARDS.md`; the stale comments in `src/App.tsx` (near `mayToggleMode`, grep "the toolbar's Edit toggle" and "gated like the toolbar Edit button") and in `src/components/FolderPanel.tsx` (`ModeSwitchButton` doc, "the toolbar button") no longer describe a toolbar toggle. The PRD-wide sweep (PRD 025 Req 29) is NOT done here — it belongs to sibling #332. If `npm run map` output changes (new PRD 025 citations in `src/` or `tests/`), the regenerated `docs/MAP.md` is committed alongside.
- **Existing tests rewritten, not deleted (PRD 025 Req 30).** E141 in `tests/e2e/shell-and-menus.spec.ts` keeps its number and its guarantee, with "toolbar control" wording replaced (the click target is the toggle in the control group). E495 in `tests/e2e/hosted.spec.ts` keeps its number and asserts the same show/hide-on-home-page behaviour of `edit-toggle` in its new home (title/comments no longer say "toolbar"). Comments in E206 ("No Edit toggle on the toolbar") are updated. No test is deleted, renamed to a new number, or renumbered.
- **New test: toggle in the control group, absent from the toolbar (PRD 025 Req 30).** A new test in `tests/e2e/file-tabs.spec.ts` (or `shell-and-menus.spec.ts`) takes the next unused E-number (E579 at spec time; re-check with `grep -rhoE "test\('E[0-9]+" tests/e2e | sort -t E -k2 -n | tail -1` before committing) and, with a document open, asserts: `page.getByTestId('file-tab-strip').locator('.file-tab-strip-trail')` contains `edit-toggle` as its LAST element child, after `mode-switch` (and after the comments chevron when present); `page.locator('.toolbar').getByTestId('edit-toggle')` has count 0 even after `revealToolbar`; the toggle carries `.btn-quiet`, reads `/Edit/` in preview and `/Preview/` after a click that mounts `editor`; and, after turning the `settings-file-tabs` checkbox off (strip gone), `page.locator('.edge-cluster').getByTestId('edit-toggle')` is visible and still toggles the mode.
- **Iteration economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (plus targeted e2e runs such as `npx playwright test -g 'E141'`, `-g 'E495'`, `-g 'E579'`) after each change, and baselines an attempt with the quick tier only — never with the full gate.
- **Full gate.** `npm run validate:quick` has been run ONCE in the implementer's session, right before declaring the goal met (not after every small change and not as a baseline at the start), and prints `QUICK VALIDATION: ALL PASSED`.
- **Summary comment.** A summary comment from the implementer exists on issue #330 describing where the toggle now renders (strip trail and `.edge-cluster`), the amendment notes added, the rewritten and new test numbers, and the validate:quick result.
