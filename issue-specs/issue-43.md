# Spec: logo renders over text (#43)

## Goal

All acceptance criteria in issue-specs/issue-43.md are satisfied for issue #43, with evidence visible in the session: whenever the splash (app logo) is visible, the preview document container holds no stale document content, on every close path (close file, close last tab, close workspace, delete-to-splash, close from edit/split-edit); a stale in-flight markdown render from a closed document can never repopulate the preview after close-to-splash; an automated regression test asserts the splash and stale content are mutually exclusive after closing a file; and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- Whenever the splash empty state (`.empty-center` / `[data-testid="empty-hint"]`, rendered when `!docPath && !untitled` in `src/App.tsx`) is visible, the preview `.doc` container (`[data-testid="doc"]`) contains no child elements and no text from the previously open document — the logo never draws over document text.
- This holds on **every** path back to the splash, audited explicitly (the issue asks to "look at all states"): Close File on the only/last open file (`closeToSplash`), Close File on the active file when no neighbor activates (`finishCloseFile`), Close Workspace (`finishCloseWorkspace`), the delete-file-to-splash path, closing an untitled buffer, and closing while in edit or split-edit mode (the split pane injection at `splitDocRef` must not leave stale content either when the app returns to preview/splash).
- A markdown render in flight when the document closes (the async `renderMarkdown(...).then(setHtml)` effect in `src/App.tsx`) cannot land after close-to-splash and repopulate `html`/the `.doc` DOM with the closed document's content — the race the reporter hits "sometimes when i close a file" is closed, not just made less likely.
- At least one automated regression test exists and passes covering the reported scenario: open a document with visible text, close it, and assert the splash is visible AND the doc container is empty (no stale rendered HTML). Prefer a Playwright e2e in `tests/e2e/documents.spec.ts` (or the most fitting existing spec) using the existing helpers/fixtures; a targeted unit test is acceptable in addition but not instead if the behavior is only observable in the DOM lifecycle.
- No regressions to normal open/close flows: opening a file after closing to splash renders its content and hides the splash; switching tabs never flashes the splash over content.
- Iterate with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code) while developing; run the full gate `npm run validate:quick` ONCE, right before declaring the goal met — not after every small change and not as a starting baseline. That final `npm run validate:quick` run passes in the implementer's session.
- A summary comment from the implementer exists on issue #43 describing the root cause found, the fix, and the verification evidence.

## Context

The splash is rendered in `src/App.tsx` (~line 4177): `.empty-center` is `position: fixed; inset: 0` (`src/styles.css` ~1254) and overlays the workspace, showing the `AppBadge` logo when `!docPath && !untitled`. The preview body is NOT React-rendered: a `useLayoutEffect` (~line 3437) sets `doc.innerHTML = html`, and `html` is produced by an async, sometimes debounced `renderMarkdown` effect (~line 3334) guarded by a `cancelled` flag and `renderPendingRef`. `closeToSplash` (~line 1613) resets state including `setHtml('')`; close paths are `finishCloseFile`, `finishCloseWorkspace`, and the delete-confirm flow (~line 2637). The bug is intermittent ("sometimes when i close a file") — look for orderings where the splash mounts while `.doc` still holds the old innerHTML, or a stale render resolves after close. The attached screenshot (not downloadable here) shows the logo composited on top of document text. Repo has no `test` script — use `typecheck`, `test:unit`, `test:e2e`, and `validate:quick`.
