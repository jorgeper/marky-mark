# Spec: File tab strip never renders on the hosted (Azure) build — gated on localFolders instead of a multi-file-session capability (#186)

## Goal

All acceptance criteria in issue-specs/issue-186.md are satisfied for issue #186, with evidence visible in the session: the tab strip seam is gated on a new multi-file-session capability declared by the tauri, browser-shim, and hosted platforms (never on `platform.kind`); `localFolders` keeps its PRD 007 Req 21 meaning so hosted still offers no Open Folder… and the static web build still shows no strip; new E-numbered hosted e2e coverage asserts the strip renders with activation and close working; and `npm run validate:quick` passes in the implementer's session with a summary comment from the implementer posted on issue #186.

## Acceptance criteria

- `src/platform/types.ts` declares an honest capability meaning "this platform has a multi-file session" (e.g. `multiFileSession?: boolean`), with a doc comment in the file's existing citation style, and `src/platform/tauri.ts`, `src/platform/browser.ts`, and `src/platform/hosted.ts` all declare it. App code gates on the capability, never on `kind === 'hosted'` (or any other `kind` check).
- The `tabStripSeam` derivation in `src/App.tsx` (~line 6375) is gated on the new capability instead of `localFolders`, and every other `localFolders` read in `src/App.tsx` that actually means "multi-file session" (see ~lines 4154 and 4709, which gate the `fileTabs` setting's persistence/exposure) has been audited and re-gated where its meaning is the multi-file session, not local folder picking.
- `localFolders` retains exactly its PRD 007 Req 21 meaning (local folder picking ⇒ Open Folder… offered): `src/platform/hosted.ts` still does not declare it, `src/lib/startActions.ts` behavior is unchanged, and on hosted the start page and File menu still offer no Open Folder….
- On the hosted platform with a workspace open and ≥1 file open, the tab strip renders with the same behavior as desktop — activation, ✕ / middle-click close, dirty ●, Close Others / Close All, overflow rail, the untitled ephemeral tab — and turning the `fileTabs` setting off hides it.
- The static single-file web build (`src/platform/web.ts`) is unchanged: it declares no new capability, shows no strip, and the W-numbered tests in `tests/e2e/web.spec.ts` are untouched.
- New e2e coverage exists on the hosted fixture (in or alongside `tests/e2e/hosted.spec.ts`, using the localhost:4924 hosted backend) asserting at minimum strip presence, tab activation, and tab close, using fresh globally-unique E numbers (issue #185 gates E-ID uniqueness in the quick tier). The existing E-numbered tests in `tests/e2e/file-tabs.spec.ts` are unchanged.
- The scope notes no longer say desktop-only: the `tabStripSeam` doc comment in `src/App.tsx`, the non-goal in `prd/013-tabs-on-top.md`, and an amendment note in `docs/specs/SPEC36.md` (in the amended-note style already used there for issues #64 / #84) all reflect that hosted has the strip. If `docs/MAP.md` changes as a result, it has been regenerated via `npm run map` (never hand-edited).
- Iteration during the attempt used `npm run typecheck` and `npm run test:unit` (or Playwright tests targeted at the changed behavior, e.g. `npx playwright test -g '<title>'`), with the full gate run only once at the end: a single `npm run validate:quick` run, executed in the implementer's session right before declaring the goal met, prints `QUICK VALIDATION: ALL PASSED`. No full-suite baseline run at the start of the attempt.
- A summary comment from the implementer exists on issue #186.

## Context

The bug: `tabStripSeam = !!platform?.localFolders` (`src/App.tsx:6375`) reuses PRD 007 Req 21's "can pick a local folder" flag to mean PRD 013's "has a multi-file session". Hosted (`src/platform/hosted.ts`) deliberately never declares `localFolders` (its ~line 483 comment explains why), yet all the SPEC36 open-set machinery — `openFiles`, park/restore, Ctrl+Tab, dirty tracking — already runs on Azure; only the strip is hidden. `rg -n 'localFolders' src` finds every gate to audit; the choice of capability shape (new boolean vs. capability-presence derivation) is the implementer's, but the issue explicitly forbids `kind` branching. The hosted e2e suite (`tests/e2e/hosted.spec.ts`) shows the sign-in/fixture pattern for the local hosted backend on port 4924; `tests/e2e/file-tabs.spec.ts` shows the strip's existing selectors and interactions to mirror. Read `.sandcastle/CODING_STANDARDS.md` before writing code; new code carries `SPEC<n> §x.y` citation comments like its neighbors.
