# Spec: Tenant user directory search and membership picker (Microsoft Graph) (#74)

## Goal

All acceptance criteria in issue-specs/issue-74.md are satisfied for issue #74, with evidence visible in the session: user avatars flow end to end through the directory seam (the Graph provider fetches profile photos via `/users/{id}/photo/$value`, the mock provider serves deterministic avatars for the seeded users, and both are exposed to the SPA through a same-origin API endpoint inside the auth guard); a reusable membership-picker component searches the tenant's users as you type against `GET /api/directory/search` and renders display names with avatars (initials fallback when a user has no photo); a member-resolution helper maps stored member ids to display entries such that a user who can't be resolved (404 — left the tenant) renders as a plain identifier without breaking the rest of the list; the new behaviour is proven by unit tests (U243+) and offline hosted-flavor e2e tests (E172+) inside `npm run test:e2e`; and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- **Avatar photos exist through the directory seam (PRD 007 Req 6).** The Azure Graph directory provider (`server/providers/azure/graph.ts`) can fetch a user's profile photo via Microsoft Graph `/users/{id}/photo/$value`, treating a missing photo (404) as "no avatar", not an error. The mock provider (`server/providers/mock/`) serves deterministic avatar images for the seeded users so local dev and e2e render real pictures with zero network. The SPA reaches avatars only through the app's own origin — e.g. a `GET /api/directory/users/<id>/photo` route (exact shape is the implementer's choice) that proxies through the `DirectoryProvider` seam, sits inside the existing bearer-token auth guard (401 unauthenticated), and answers 404 for a user with no photo or who is unknown. `DirectoryUser.avatarUrl` (already declared in `server/providers/types.ts`) is populated in search and lookup results with that same-origin URL. No Azure/Graph URL or SDK use appears outside `server/providers/azure/` (PRD Req 3).
- **A reusable membership-picker component exists.** A component under `src/components/` implements search-as-you-type over the tenant directory: as the user types, it queries `GET /api/directory/search?q=…` (debounced — no request per keystroke), lists matches with display name, username, and avatar (falling back to initials or a neutral glyph when `avatarUrl` is absent), and lets the caller pick users into a selected-members list and remove them; already-selected users are not offered again. The picker takes its API access as props/injection (no hard dependency on a live server), so #75 (create-workspace flow) and #77 (settings membership management) can consume it unchanged. Its non-DOM logic (debounce/query state, result mapping, selection rules, initials derivation) lives as pure functions in `src/lib/` covered by unit tests.
- **Unresolved members render as plain identifiers (PRD 007 Req 6).** A `src/lib/` helper resolves a list of stored member ids to display entries via `GET /api/directory/users/<id>`: a resolvable user yields name + avatar; a 404 (left the tenant) yields a plain-identifier entry (the stored id/username as text, no avatar, not an error state); one unresolvable or failing lookup never breaks resolution of the rest of the list. Unit tests pin all three behaviours.
- **E2e coverage runs offline inside `npm run test:e2e`.** New Playwright tests numbered E172+ (in `tests/e2e/hosted.spec.ts` or a new auto-collected spec) against the local hosted server (port 4924, seeded mock users) observably verify at least: directory search results carry working `avatarUrl`s and the photo endpoint returns image bytes for a seeded user; an unknown user id answers 404 on lookup (and photo); and the new endpoint(s) answer 401 without a token. Zero Azure resources, no network beyond localhost. Existing tests are not weakened, renumbered, or skipped.
- **Unit tests pin the new logic.** New vitest tests (U243+, under `tests/unit/`, collected by `npm run test:unit`) cover the Graph photo fetch/URL shape and 404 mapping (injected fetch, no network — extend `server-azure-providers.test.ts` conventions), the mock avatar behaviour, the picker's pure logic, and the member-resolution helper, per `.sandcastle/CODING_STANDARDS.md`.
- **Standards, docs, map.** New behaviour carries citation comments (`// PRD 007 Req 6: …`); any new endpoint is added to `server/README.md`'s endpoint table; `docs/MAP.md` is regenerated via `npm run map` if the citation set changed (the quick gate diffs it).
- **Scope guard.** No workspace manifest, membership persistence, or roles (issue #72), no create/open/delete workspace flows (#75), no workspace-settings management UI (#77), and no hosted `Platform` implementation (#73). The picker ships as a reusable, unit-tested component; wiring it into live flows is those issues' work — this issue does not need to mount it anywhere in the running app.
- Iteration was done with `npm run typecheck` and `npm run test:unit` (plus targeted e2e runs like `npx playwright test -g 'E172'`), with the full gate run ONCE at the end — not after every small change, and not as a starting baseline (baseline with the quick pair only).
- `npm run validate:quick` passes in the implementer's session, printing `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #74.
