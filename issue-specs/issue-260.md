# Spec: Copy-link affordance missing on headings lower in the document (#260)

## Goal

All acceptance criteria in issue-specs/issue-260.md are satisfied for issue #260, with evidence visible in the session: every heading in a hosted document carries the PRD 020 Req 18 copy-link affordance — first heading to last, in both the preview-hover and editor-gutter placements — copying the file URL plus the section model's `#<slug>`; the root cause of the "top headings only" shape is diagnosed rather than papered over; regression coverage exercises a long fixture whose headings sit deep in the document (and fails without the fix); `npm run validate:quick` passes; and a summary comment from the implementer exists on issue #260.

## Acceptance criteria

- The failure is diagnosed before it is fixed: the implementer's summary comment states which placement(s) actually dropped the affordance and the mechanism (e.g. a line mismatch between the rendered stamp and `headingAnchors(parseSections(src))`, an unstamped heading, or a viewport-limited Lezer tree in the gutter's `syntaxTree` pre-filter — `editor/src/components/diagramView.ts` shows the `ensureSyntaxTree` precedent). The issue body's off-by-N guess is a hypothesis, not a finding; if it is wrong, say so.
- In the hosted rendered preview, every heading of a long document carries the copy-link control regardless of how far down it sits: hovering the document's LAST heading reveals it, and clicking copies `<canonical file URL>#<slug>` with the slug the section model derives (`headingAnchors`), deduped `-1`, `-2`… in document order.
- In the editor, a cursor resting on any heading line reveals the gutter control and copies the same slugged URL — including a heading far below the initially rendered viewport, reached by scrolling/navigating rather than by being on screen at load.
- Container-nested headings (indented under a list item, inside a blockquote — issue #226's `data-mm-hline` path) keep working when they sit deep in the document, in both placements.
- `headingUrlForLine` (`src/App.tsx`) resolves non-null for every heading the preview and gutter offer the control on: no line drift between the rendered/gutter line and the section-model anchor, including documents with YAML front matter, fenced blocks containing `#` lines, and setext headings.
- Behaviour stays hosted-only (PRD 020 Req 15): the desktop (Tauri), dev-shim and single-file builds still show no share placements — the existing `tests/e2e/tabs-and-workspace.spec.ts` assertion that `mm-heading-link` has count 0 there still passes.
- Regression coverage exists and is numbered per the repo's gate-checked scheme (`E<n>` for e2e, `U<n>` for unit; the test-ID uniqueness step enforces it): at least one e2e test in `tests/e2e/hosted.spec.ts` over a fixture long enough that its last headings sit hundreds of lines down (the existing `HEADED_DOC`'s ~60 filler lines was not enough to catch this), covering both the preview button and the editor gutter on a deep heading; plus unit coverage in `tests/unit/` and/or `editor/tests/` for whatever pure layer regressed. The new tests fail against the pre-fix code and pass after — the implementer states that they checked this.
- Changed or added behaviour carries the repo's citation comments (`// SPEC<n> §x.y:` / the PRD-and-issue form used around the Req 18 code) per `.sandcastle/CODING_STANDARDS.md`, and `docs/MAP.md` is regenerated with `npm run map` and committed if citations changed.
- Iteration used the cheap loop — `npm run typecheck` and `npm run test:unit` (plus `npm test --workspace editor` when anything under `editor/` changed; the root unit suite does NOT include `editor/tests/`), and single Playwright tests via `npx playwright test -g '<title>'` — not the full gate after each change.
- `npm run validate:quick` has been run ONCE in the implementer's session, right before declaring the goal met (not as a starting baseline beyond this quick tier), and printed `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #260, naming the root cause, the fix, the new test IDs, and the validate:quick result.

## Context

The affordance is PRD 020 Req 18 (`prd/020-shareable-links.md`, lines ~159-165). Three pieces carry it: `headingUrlForLine` / `getHeadingAnchors` in `src/App.tsx` (~line 4140-4165, resolving a 1-based line to a slugged URL via `headingAnchors(parseSections(src))`), the preview graft `decorateHeadingLinks` in `editor/src/lib/headingLinks.ts` (called post-injection at `src/App.tsx:6188` and `:6332`; it skips any heading with no `data-mm-line`/`data-mm-hline` stamp), and the editor gutter `headingLinkGutter` / `HeadingLinkMarker` in `editor/src/components/Editor.tsx` (~line 973-1060), which returns no marker unless the Lezer tree says the cursor line is a heading AND `getUrl(line)` is non-null. Line stamps come from `stampSourceLines` / `stampNestedHeadingLines` in `editor/src/lib/markdown.ts`; anchors come from `parseSections` in `src/lib/sectionModel.ts` and `headingAnchors`/`headingSlug` in `src/lib/shareLinks.ts`. Existing coverage: `E409`/`E410`/`E414` in `tests/e2e/hosted.spec.ts` (fixture `HEADED_DOC` at ~line 4758), `U1084`/`U1086` in `editor/tests/`, and `tests/unit/share-links.test.ts`. Grep `PRD 020` and `SPEC15` before opening files; never read `src/App.tsx` end-to-end.
