# Spec: Fluid mode (1/5): switch, settings keys, nested page, package seam, inert overlay layer (#333)

## Goal

All acceptance criteria in issue-specs/issue-333.md are satisfied for issue #333, with evidence visible in the session: Settings › Experimental carries a data-registry **Fluid mode** row (off by default, PRD 025 Req 1 description) whose Settings… button opens a nested *Experimental › Fluid mode* page with exactly four action pickers governed by the dialog's Save/Cancel footer; the switch and its action→effect mapping are user-scoped `EXPERIMENTAL_KEYS` with the Req 6 defaults and fallbacks; `@marky-mark/editor` exports a public mapping prop plus the effect/action types, applicability table and large-operation constants (documented in its README, importing nothing from `src/`, adding no runtime dependency); with the switch off the editor root carries no configuration attribute and no overlay element exists, and with it on the inert overlay layer and attribute are present but nothing animates; unit tests and one e2e test in `tests/e2e/settings-and-themes.spec.ts` cover this without any time-based wait; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #333.

## Acceptance criteria

### Settings keys (PRD 025 Reqs 2, 6, 8)

- `src/lib/settings.ts` gains two keys: `fluidMode: boolean` (default `false`) and `fluidEffects`, an object mapping each of the four actions (`cursor`, `selection`, `deletion`, `insertion`) to an effect name or `'none'`. Both are scope-tagged `'U'`, both appear in `EXPERIMENTAL_KEYS`, and neither appears in `WORKSPACE_PINNABLE_KEYS` / `WORKSPACE_ELIGIBLE_KEYS` — exactly the `semanticZoom` treatment. The existing `tests/unit/settings-scope.test.ts` loop over `EXPERIMENTAL_KEYS` still passes.
- The default mapping is Cursor movement → `glide`, Selection change → `elastic`, Deletion → `fade`, Insertion → `pop`.
- The per-key parser for `fluidEffects` is a pure function (exported for tests): a stored value naming an unknown effect, or an effect not applicable to its action (per the applicability table), loads as that action's default; a missing action loads as its default; `'none'` is preserved. A non-object value loads as the whole default mapping.
- Effect durations exist as per-effect constants in the editor package, not settings: Fade, Glide and Pop each in the 120–250 ms range, Elastic ≤ ~350 ms, Burst ≤ 400 ms. Nothing reads them yet.

### The Experimental row and nested page (PRD 025 Reqs 1, 4, 5)

- `EXPERIMENTAL_FEATURES` in `src/components/SettingsPanel.tsx` gains a second data entry (no bespoke row markup): `key: 'fluidMode'`, `testId: 'experimental-fluid-mode'`, label **Fluid mode**, description exactly *"Animates the editor — the cursor glides, selections stretch, and text fades in and out. Does nothing when your system asks for reduced motion."*, no `capability` (enableable on every host), and `page: { id: 'fluid', buttonLabel: 'Settings…' }`. The row order is Semantic zoom first, Fluid mode second.
- `SettingsPageId` admits `'fluid'`, and `pageContent` maps it to a Fluid mode page component. The page reuses the existing nested-page shell (`settings-page-back`, `settings-page-crumb` reading *Experimental › Fluid mode*, `data-testid="settings-page-fluid"`); no copy of the breadcrumb/Back markup is added.
- The Settings… button (`experimental-fluid-mode-settings`) is disabled while the switch is off, following the existing `disabled={!on}` rule.
- The page lists exactly four rows, in this order, each with a `<select>` picker: **Cursor movement** (`fluid-pick-cursor`), **Selection change** (`fluid-pick-selection`), **Deletion** (`fluid-pick-deletion`), **Insertion** (`fluid-pick-insertion`). Each picker's options are **None** (`value="none"`) followed by exactly the effects applicable to that action, labelled Fade / Glide / Elastic / Pop / Burst as applicable: cursor and selection offer Glide, Elastic; deletion offers Fade, Pop, Burst; insertion offers Fade, Pop.
- Picker changes go through the panel's pending-settings `onChange`, so the pinned Save commits the mapping with the rest of the settings and Cancel discards it (issue #246 mechanics; no live write). Chrome follows the style lint: `ui/` wrappers or the sanctioned classes, tokens only, `SectionHeader` for any section header.

### The package seam (PRD 025 Reqs 3, 7, 14, 18–20)

- A new pure module in `editor/src/lib/` (e.g. `fluid.ts`) exports, and `editor/src/index.ts` re-exports: the `FluidAction` and `FluidEffect` name types, a `FluidEffectMap` (action → effect | `'none'`) type, the applicability table as data (Fade: deletion, insertion; Glide: cursor, selection; Elastic: cursor, selection; Pop: deletion, insertion; Burst: deletion only) plus a helper listing the effects applicable to an action, the duration constants above, the large-operation constants `FLUID_LARGE_OPERATION_CHARS = 2000` and `FLUID_LARGE_OPERATION_LINES = 50`, and a pure predicate deciding whether a change of N characters / M lines is "large" (strictly more than either threshold).
- `EditorProps` gains a documented optional prop `fluid?: FluidEffectMap | null`; `null`/absent means off. Marky Mark's `App.tsx` passes `settings.fluidMode ? settings.fluidEffects : null` at the one `<Editor` mount. The applicability table and defaults used by `src/lib/settings.ts` are imported from `@marky-mark/editor`, never duplicated; nothing under `editor/` imports from `src/` (the editor-package-boundary check in `scripts/validate.mjs` stays green).
- With `fluid` absent or `null`: the editor loads no fluid-related CodeMirror extension, renders no overlay element, registers no listener, and the editor root (`data-testid="editor"`) has no `data-fluid` attribute.
- With `fluid` set: the editor root carries `data-fluid` whose value encodes the four pairs in fixed order as `cursor=<effect>;selection=<effect>;deletion=<effect>;insertion=<effect>` (e.g. `cursor=glide;selection=elastic;deletion=fade;insertion=pop`), and an absolutely positioned overlay element with `data-testid="fluid-overlay"`, `aria-hidden="true"` and `pointer-events: none` is mounted inside the editor's scroller (`view.scrollDOM`). The layer is removed when the prop returns to `null`. No animation, timer, `requestAnimationFrame`, transition or Web Animations call is scheduled in this increment: every effect is a no-op.
- `editor/README.md` gains one section documenting the `fluid` prop, the five-effect catalogue with its applicability, the four actions and their defaults, the large-operation constants, and the never-delay guarantee (the document, real selection and caret change synchronously; effects are overlays drawn afterwards).
- No new entry in `dependencies` of `package.json` or `editor/package.json`; `THIRD-PARTY-NOTICES.md` is unchanged.
- New or changed behaviour carries a citation comment (`// PRD 025 Req <n>: …`) per `.sandcastle/CODING_STANDARDS.md`; no `console.*` in `src/` or `editor/src/`.

### Tests (PRD 025 Reqs 21–23)

The editor module's tests live in `editor/tests/<kebab-name>.test.ts`.
- One e2e test in `tests/e2e/settings-and-themes.spec.ts`, ID the next unused `E` number (E577 at spec time), using `openSettings(page, 'experimental')` and `saveSettings` from `tests/e2e/helpers.ts`: asserts the row is unchecked by default with its description; checks the switch on; opens the page via `experimental-fluid-mode-settings`; asserts `settings-page-fluid` is visible with the crumb *Experimental › Fluid mode*; asserts the four pickers exist in order with exactly the option sets above; changes one mapping (e.g. deletion → Pop); saves; asserts the editor root's `data-fluid` equals `cursor=glide;selection=elastic;deletion=pop;insertion=pop` and `fluid-overlay` has count 1; then reopens Settings, unchecks the switch, saves, and asserts `fluid-overlay` has count 0 and the editor root has no `data-fluid` attribute. It uses no `waitForTimeout` or other time-based wait.
- No test observes, waits for or measures an animation. No existing test or test ID is changed, renamed, weakened or skipped.
