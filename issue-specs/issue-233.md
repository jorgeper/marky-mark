# Spec: Highlights: copy link to highlight and #hl- fragment landing (#233)

## Goal

All acceptance criteria in issue-specs/issue-233.md are satisfied for issue #233, with evidence visible in the session: an active highlight reveals the PRD 020 copy-link primitive at the left margin beside its first line (tooltip "Copy link to highlight", hosted-only, absent for untitled buffers) that copies the file's canonical URL plus `#hl-<comment id>`; the `hl-` prefix is a reserved fragment namespace parsed before heading slugs, and landing on such a fragment opens the file, scrolls the highlight into view, and flashes it with the existing mark-flash affordance, while an id that no longer resolves shows the dismissible "That highlight wasn't found — it may have been removed" notice; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #233.

## Acceptance criteria

- **Copy-link on the active highlight (PRD 022 Req 10).** When a highlight is active (the #232 activation state — noted or note-less alike), a copy-link control appears at the left margin beside the highlight's first painted line, mirroring the heading affordance's placement; it deactivates/leaves with the highlight. It reuses the PRD 020 Req 14 primitive contract (`createCopyLinkController` / `CopyLinkButton`-style behavior): click copies, the control shows "Link copied" for ~2s, and the same words are aria-announced via a live region. Its rest tooltip and accessible name are **"Copy link to highlight"** (the #227 name-the-target convention).
- **Hosted-only (PRD 020 Req 15).** The control renders only on the hosted platform with a file riding the path (the existing `platform?.kind === 'hosted' && docPath` gate in `src/App.tsx`); it is absent for untitled buffers, the dev shim, Tauri, and the single-file web build.
- **The copied URL (Req 11, copy side).** The copied text is the file's canonical PRD 020 share URL (same derivation as `fileShareUrl`/`headingShareUrl` in `src/lib/shareLinks.ts` — origin + canonical pathname off the address bar, read at click time) plus `#hl-<comment id>`, where the id is the highlight's stable entry id (the `data-cid` on `mark.hl`). The URL-building logic is pure and lives in `src/lib/shareLinks.ts` beside its siblings.
- **`hl-` is a reserved fragment namespace (Req 11, parse side).** Fragment parsing recognizes `#hl-<id>` *before* heading-slug matching: a visited fragment starting with `hl-` is treated as a highlight link and never falls through to (or is shadowed by) a heading slug. The split is a pure, unit-testable function in `src/lib/shareLinks.ts` (extending or sitting beside `slugFromHash`).
- **Landing (Req 11).** Visiting a `#hl-<id>` URL opens the file and — once the entry's range has been anchored and painted — scrolls the highlight into view and flashes it via the existing mark-flash affordance (`mark.hl` + `.flash`, the SPEC14 §1.3 pattern already used in `src/App.tsx`). The landing follows the heading-landing retry pattern (`landOnHeadingSlug`, hosted boot path): bounded per-frame retries until the mark exists in the DOM, working in the current view mode.
- **The graceful miss (Req 11).** A `#hl-<id>` whose id resolves to no live highlight (deleted, or the file has no such entry; an orphaned entry that paints no mark also must not spin forever) shows the dismissible notice pattern from PRD 020 Req 19 (the `headingMiss` notice machinery: self-clears, dismissible sooner) with the text **"That highlight wasn't found — it may have been removed"**, leaving the file at the top.
- **No regressions.** Heading share links (`#<slug>` copy and landing, including the renamed-section miss) and the #232 card lifecycle behave as before; existing comment and hosted e2e suites pass with at most mechanical updates.
- **Tests (PRD 022 Req 15 slice).** Unit tests for the fragment split (`hl-` namespace wins over a look-alike heading slug, malformed escapes, empty ids) and the highlight share-URL builder, numbered `U<n>` continuing after U1106. E2e covering at least: the active highlight's copy-link copies the `#hl-<id>` URL with the "Link copied" confirmation; a visited `#hl-<id>` lands scrolled-to and flashed; an unresolvable id shows the not-found notice; the control is absent when not hosted or for an untitled buffer. E-numbered continuing after E423, in the suite that fits (`tests/e2e/hosted.spec.ts` holds the PRD 020 share-link tests; `comments.spec.ts` holds highlight activation).
- **Test economy.** The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code, e.g. `npx playwright test -g '<title>'` for one e2e), and ran the full quick gate exactly once, right before declaring the goal met — not after every small change, and not as a baseline at the start of the attempt.
- **Gate.** `npm run validate:quick` has been run in the implementer's session and prints `QUICK VALIDATION: ALL PASSED`.
- **Issue trail.** A summary comment from the implementer exists on issue #233.
