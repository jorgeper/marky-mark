# Spec: Highlights: editor-pane decorations (CodeMirror best-effort painting) (#234)

## Goal

All acceptance criteria in issue-specs/issue-234.md are satisfied for issue #234, with evidence visible in the session: highlight ranges paint in the CodeMirror editor in both plain edit and split edit as background decorations in the highlight's color, mapped best-effort from rendered-text anchors to source ranges by exact-quote match against the source and skipped when absent or ambiguous — never mispainted; in split edit, clicking a painted range activates that highlight's card in the preview pane's panel, while plain edit is paint-only; the editor package gains the capability through a prop/extension seam with no reverse imports (the editor-package-boundary check passes); `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #234.

## Acceptance criteria

- **Painting in both edit modes (PRD 022 Req 12).** Each highlight whose anchor confidently maps to a source range paints in the CodeMirror editor as a background decoration in the highlight's color, in plain edit (`mode === 'edit' && !settings.splitEdit`) and split edit (`mode === 'edit' && settings.splitEdit`) alike. Colors follow the preview's conventions: the four marker tokens from `src/styles.css` (`--mm-marker-yellow/green/blue/pink`, PRD 022 Req 13) for colored entries, the legacy tint for entries without a `color` field. The editor paints (at most) the entry set the preview would paint — entries the preview hides (e.g. resolved highlights while "Show resolved" is off) do not paint in the editor.
- **Best-effort mapping, never mispainted (Req 12).** Anchors are stored over rendered plain text (`Anchor.exact/prefix/suffix`, `src/lib/anchoring.ts`); the editor shows markdown source. Mapping is by exact-quote match of `anchor.exact` against the source: a unique occurrence paints; zero occurrences skip; multiple occurrences may be disambiguated using the anchor's stored context only when that yields one confident winner, otherwise skip. A skipped highlight simply does not paint in the editor — no error, no fallback painting. The mapping is a pure function in `src/lib/` (new module or an `anchoring.ts` addition) with unit tests.
- **A seam, not a reverse import.** The editor package (`editor/`) gains the capability through its public API — a prop on `EditorProps` (the `diff?: DiffLineSets` decoration seam at `editor/src/components/Editor.tsx:237` is the precedent) taking id + source-offset range + color per highlight, plus a click callback seam. No module under `editor/` imports from `src/` (per `editor/AGENTS.md`); the app computes the source ranges and passes them in. The decoration set live-reconfigures when highlights change (compartment, like `diff`) — no editor remount.
- **Coordinate honesty.** The editor document can differ from the raw source (canonical text: table-grid whitespace, SPEC40/SPEC44 — see `canonHead` and `editor/src/lib/selectionMap.ts`). Source offsets must be mapped into editor-doc positions through the existing canonical mapping (the same machinery `selectRangeRef` uses), or the affected ranges skipped — never painted at visibly wrong positions. Typing in the editor must not crash or durably mispaint decorations (recompute or map ranges through changes; transient staleness within a debounce beat is acceptable).
- **Split-edit click activates; plain edit is paint-only (Req 12).** In split edit, clicking a painted range activates that highlight's card in the preview pane's panel — same observable outcome as clicking the preview `mark.hl` (noted entries activate their standing card; note-less entries show their transient active card per #232) — without breaking normal cursor placement in the editor. In plain edit a click on a painted range has no comment-related effect. Editor-pane painting is display-only everywhere: no authoring, recoloring, or removal from the editor pane (PRD 022 non-goal).
- **No regressions.** Preview-pane painting, card lifecycle (#232), the swatch popup (#231), and existing editor decorations (diff since save, find) keep working; existing unit and e2e suites pass with at most mechanical updates.
- **Tests.** Unit tests for the mapping function covering at least: unique match paints with correct offsets, absent quote skips, ambiguous quote skips, context disambiguation (if implemented) picks the right occurrence, and color/id passthrough — in `tests/unit/` (or `editor/tests/` for in-package logic), continuing the repo-wide `U<n>` register (next free after U1106; re-check at write time). E2e in `tests/e2e/` continuing the `E<n>` register (next free after E423; re-check at write time) covering at least: a highlight paints in plain edit and in split edit in its color; an ambiguous/absent quote does not paint; clicking a painted range in split edit activates the card in the panel; plain edit stays paint-only.
- **Test economy.** The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code, e.g. `npx playwright test -g '<title>'` for one e2e), and ran the full quick gate exactly once, right before declaring the goal met — not after every small change, and not as a baseline at the start of the attempt.
- **Gate.** `npm run validate:quick` has been run in the implementer's session and prints `QUICK VALIDATION: ALL PASSED`.
- **Issue trail.** A summary comment from the implementer exists on issue #234.
