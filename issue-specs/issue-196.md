# Spec: Login style issues (#196)

## Goal

All acceptance criteria in issue-specs/issue-196.md are satisfied for issue #196, with evidence visible in the session: the hosted sign-in page is restyled to the splash/landing page's look and feel — the gray card box is gone (logo and sign-in control sit directly on the app background), the logo uses the splash's badge size and placement, fonts match the splash typography, the azure-mode button is Microsoft's standard "Sign in with Microsoft" button (four-square logo, neutral background — not the current dark-blue fill) while other controls match the landing page's `.start-action` button style, all existing `hosted-sign-in*` test ids still pass their e2e tests, and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- The gray box is removed: `src/components/HostedSignIn.tsx` no longer renders a bordered/elevated card (`.hosted-signin-card`'s border + `--mm-bg-elevated` background are gone from the signed-out page). The page shows, centered on the plain app background (`--mm-bg`), essentially just the logo and the sign-in control — matching the issue's "just put the logo and the 'sign in' button, that's it".
- Logo placement and size match the landing page: the splash renders `<AppBadge size={132}>` inside `.splash-mark` (`src/App.tsx` ~line 7151, `SPEC27 §3`); the sign-in page currently uses size 96 — it now uses the same size and spacing as the splash. The `hosted-sign-in-badge` test id stays.
- Fonts are consistent with the landing page: any remaining text (the "Checking session…" hint, the local-mode label, errors) uses the splash's typography scale and muted color (`--mm-fg-muted`, ~12.5–13.5px — see `.splash-*` rules in `src/styles.css` ~lines 1611–1710), not a distinct 20px card title. The standalone "Marky Mark" `<h1>` card title is removed (the splash itself shows no title text — the badge is the identity).
- The azure-mode button follows Microsoft's standard "Sign in with Microsoft" branding (issue image [2]): the four-square Microsoft logo (inline SVG, quadrant colors #F25022 / #7FBA00 / #00A4EF / #FFB900 — no image assets, keeping the bundle-scan clean) followed by the label "Sign in with Microsoft", on a light/neutral themed background with a border — replacing today's dark-blue `--mm-accent` fill. It keeps the `hosted-sign-in-microsoft` test id and its disabled/busy behaviour.
- The local dev mode form (username input + Sign in button) and error text remain functional but restyled to match the landing page's button/input look: buttons styled like `.start-action` (border `--mm-border`, radius 6px, `--mm-hover` wash; note `.start-action` cites `--mm-bg-elev`, but the canonical variable used 28× elsewhere is `--mm-bg-elevated` — don't propagate the typo'd name). Test ids `hosted-sign-in`, `hosted-sign-in-username`, `hosted-sign-in-submit`, `hosted-sign-in-error` are unchanged (an existing test id is never renamed).
- Existing hosted e2e tests still pass unweakened (E165–E168 in `tests/e2e/hosted.spec.ts` drive the local-mode sign-in page by test id). If e2e assertions are added for the new structure (e.g. no card element, Microsoft-branded button markup), they take the next unused `E<n>` (E390+), and if the collected desktop-shim e2e count grows, `E2E_TEST_FLOOR` in `scripts/validate.mjs` (currently 379) is re-pinned to the new count.
- Changed behaviour carries citation comments per `.sandcastle/CODING_STANDARDS.md` (the sign-in page is `PRD 007 Req 5`; the restyle can cite `issue #196`), and no `console.*`, no new network call sites, and no new image assets are introduced.
- Iteration used `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code, e.g. `npx playwright test -g '<title>'`) after each change; the full gate `npm run validate:quick` was run **once**, right before declaring the goal met — not after every small change and not as a starting baseline — and passed, printing `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- A summary comment from the implementer exists on issue #196.

## Context

The sign-in page is the hosted flavor's gate (`PRD 007 Req 5`): `src/components/HostedSignIn.tsx` renders `.hosted-signin` / `.hosted-signin-card` styled at `src/styles.css` ~lines 3518–3592. The landing page it must match is the splash in `src/App.tsx` ~line 7151 (`SPEC27 §3`: `AppBadge size={132}`, version/meta lines, `StartPage` action buttons) with styles at `src/styles.css` ~lines 1611–1710 (`.splash-*`, `.start-action`). This is a CSS + JSX-structure change only — no auth logic (`src/lib/hostedAuth.ts` / `hostedGate.ts`) changes, so no unit-test changes are expected. The issue's attached screenshots are not downloadable in the sandbox; image [2] is Microsoft's standard branded sign-in button per their identity-branding guidelines (four-square logo + "Sign in with Microsoft"), which the criteria above describe. Everything must remain theme-variable driven so it holds in light and dark themes.
