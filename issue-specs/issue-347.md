# Spec: Folder sidebar: tint every open file with a lighter shade of the active file's selection colour (#347)

## Goal

All acceptance criteria in issue-specs/issue-347.md are satisfied for issue #347, with evidence visible in the session: every open-but-inactive row (`.folder-item.open`) in the folder sidebar carries a flat, full-width, `--mm-radius-small` background that is an accent-derived internal token at roughly half the active row's strength (about 7% where `--mm-selected-row` is 14%), declared once beside `--mm-selected-row` in `src/styles.css` with no literal colour in the rule; the active row keeps its stronger tint and bold label, closed rows stay transparent, hovering an open row never drops below the open tint, and open rows still have no shadow, no z-index and no pill geometry; an e2e test (E581 amended and/or a new E-numbered test) proves the three-way picture (active strong, open lighter but non-transparent with lower alpha, closed transparent) under Crisp and One Dark; PRD 025 Reqs 14–15 carry an "Amended (issue #347)" note; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #347.

## Acceptance criteria

- **Open-row tint token.** A new internal token (e.g. `--mm-open-row`) is declared on `.theme-root` in `src/styles.css` directly beside `--mm-selected-row` (around line 109), as `color-mix(in srgb, var(--mm-accent, #0969da) 7%, transparent)` — roughly half the active row's 14% — with a comment citing PRD 025 Req 14 (issue #347). It derives from the contract accent, so every bundled theme tints without defining anything. The `.folder-item.open` rule references the token only; no raw colour literal appears in the rule (the PRD 018 style lint in `scripts/validate.mjs` stays green).
- **Open-row rule.** `.folder-item.open` (the open-but-inactive rows; see `src/styles.css` around line 2606 and `FolderPanel.tsx` lines 594 / 646 for where the class is set) gets: `background: var(--mm-open-row)`, `border-radius: var(--mm-radius-small)`, normal font weight (not bold), and nothing else — no `box-shadow`, no `z-index`, no left margin, no min-width. The active row's `.folder-item.selected` rule is unchanged (14% tint, bold, small radius, no shadow).
- **Hover on an open row keeps the tint.** `.folder-item.open:hover:not(:disabled)` resolves to a non-transparent background whose alpha is ≥ the open tint's alpha (the stronger of `--mm-hover` at 8% and the open tint at 7% — using `--mm-hover` satisfies this today; if the tint is ever the stronger one, hover must use it). Hovering never makes an open row look less open.
- **Three-way picture is observable.** With three files open and one active (e.g. via the E581 setup: click a.md, Mod+click e.md, plus one more open), computed styles show: the `.selected` row non-transparent with `font-weight ≥ 600`; each `.open` row non-transparent, with `font-weight < 600` and an rgba alpha strictly lower than the selected row's; every closed `.folder-item` (no `.open`, no `.selected`) transparent `rgba(0, 0, 0, 0)`. This holds under Crisp (light) and One Dark (dark) — the same two themes E581 already switches between.
- **Flatness assertions stay green.** Open rows still report `box-shadow: none`, `z-index: auto`, `margin-left: 0px`; the trailing slot (`.folder-tab-slot` with the dirty ● / ✕, SPEC36 §3.4/§3.6) is unchanged and still present on open rows; the file tab strip above the page (`FileTabStrip.tsx`, `.tab-btn`) is untouched; the outline (`.folder-item.toc-active`) and search views are untouched.
- **Tests.** E581 in `tests/e2e/folder-tree.spec.ts` currently asserts `.folder-item.open` and every non-selected row are transparent — that is the contract this issue replaces. Amend E581's `open.background` / `others` assertions to the new contract (open rows tinted with lower alpha than the selected row; closed rows transparent), keeping every shadow / z-index / margin / font-weight / header-rule / slot assertion, and update its title and comment. Alternatively (or additionally) add a new test at the next unused E number (E606 at spec time — re-check with `grep -rhoE "test\('E[0-9]+" tests/e2e | sort` before committing; bump if a parallel merge took it) covering the three-way picture and the hover case. No existing test is deleted, skipped or weakened beyond the deliberate contract change in E581; test IDs stay unique.
- **Docs amended.** PRD 025 (`prd/025-centered-page-layout.md`) Reqs 14 and 15 get a `> **Amended (issue #347, 2026-09-08):** …` note in the existing amendment style (see Reqs 6/17), stating that open rows now carry the lighter accent-derived tint and the active row is the strongest, not the only, tinted row; the "only tinted row" wording at PRD line ~336, `docs/specs/SPEC36.md` line ~160 ("the ONLY highlighted row"), and the `src/styles.css` comments at ~105 and ~2590 are corrected to match. `docs/STYLE-GUIDE.md`'s internal-token list (line ~50) names the new token. `docs/MAP.md` is regenerated with `npm run map` if any citation changed (the gate diffs it).
- **Citations.** Every new or changed rule carries a citation comment (`PRD 025 Req 14 (issue #347)` / `Req 15`) per `.sandcastle/CODING_STANDARDS.md`.
- **Iteration and gate.** Iterate with `npm run typecheck` and `npm run test:unit`, plus the single targeted e2e test (`npx playwright test -g 'E581'` / the new E-number) while debugging; do not run the full suite as a baseline. `npm run validate:quick` has been run ONCE in the implementer's session, right before declaring the goal met, and prints `QUICK VALIDATION: ALL PASSED`.
- **Issue comment.** A summary comment from the implementer exists on issue #347 describing the token, the rule, the test change and the gate result.

## Context

The sidebar is SPEC34 (`grep -rn 'SPEC34' src`); the open-set and row classes are SPEC36 (`FolderPanel.tsx` sets `selected` for the active path and `open` for parked open files in both the tree and only-open views, lines ~594 and ~646). PRD 025 Reqs 13–16 (issue #329) flattened the sidebar: `--mm-selected-row` (`src/styles.css:109`, accent at 14%) tints the active row, `--mm-hover` (accent at 8%) is the hover wash, and `.folder-item.open` deliberately sets nothing. This issue is CSS plus one token: no TSX change is expected, so the tint applies identically on desktop and hosted (same component). The `color-mix` output is reported by Playwright as `rgba(r, g, b, a)` (or `color(srgb …)` in some Chromium builds) — parse the alpha rather than comparing strings; E602 in `tests/e2e/file-tabs.spec.ts` shows the repo's existing helpers for parsing computed colours/shadows. Never read `App.tsx` whole; nothing there needs to change.
