# Spec: link copied text for highlights (#309)

## Goal

All acceptance criteria in issue-specs/issue-309.md are satisfied for issue #309, with evidence visible in the session: the active highlight's copy-link confirmation ("Link copied") no longer draws over the document's paragraph text — after a click its caption's bounding box lies entirely outside the highlight block's text column in the default centered layout and is legibly backed wherever it lands; the existing PRD 022 Req 10 contract (position beside the first painted mark line, "Copy link to highlight" rest label, aria-label swap, ~2s revert, URL plus `#hl-<id>`, no text nodes in the preview root) is preserved with E429 still passing; a new e2e test proves the non-overlap; `npm run validate:quick` has been run in the implementer's session and passed; and a summary comment from the implementer exists on issue #309.

## Acceptance criteria

- **The confirmation caption stays out of the text.** With a hosted, addressed file open in preview and a highlight active, clicking the margin copy-link (`data-testid="mm-hl-link"`) shows "Link copied" whose bounding box does not intersect the text column of the block that holds the highlight's first `mark.hl` fragment: in the default centered layout (no folder pane squeeze), `captionRight <= blockContentLeft`, where `blockContentLeft` is the left edge of the highlight's containing block's content box (the `.doc` padding edge, i.e. where the paragraph's glyphs start). Today the caption grows rightward from `left: 6px` in the 32px padding column and lands on top of the words — that is the bug in the issue's screenshot.
- **The caption is legible wherever it lands.** The caption is drawn on an opaque surface (e.g. `var(--mm-bg-elevated)` with the chrome border/radius tokens from `docs/STYLE-GUIDE.md`) and stacks above the document text, so in the squeezed layout (comments pane open, `.doc` clamped to the clip edge per `lib/highlightLink.ts`) it never renders as transparent text over the paragraph. It is fully inside the viewport in the default layout (not clipped away).
- **The glyph position is unchanged.** At rest the control still sits in the left margin level with the highlight's first painted line: `linkBox.x < markBox.x` and `|linkBox.y - markBox.y| < 28`, as E429 asserts. Only the confirming state changes shape.
- **The PRD 022 Req 10 / PRD 020 Req 14 contract is intact.** Rest `title`/`aria-label` is "Copy link to highlight"; on a landed copy the aria-label becomes "Link copied" for ~2s then reverts; the copied text is the file's canonical URL plus `#hl-<comment id>`; the control leaves on deactivation; the hosted-only gate (E432: none on an untitled buffer, E428: none off hosted) holds. The graft still contributes no text nodes to the preview root — the caption remains a pseudo-element or a node outside the anchor text space — so `getDocText()` stays byte-identical and comment anchors resolve.
- **Other copy-link placements are untouched.** The per-heading copy-link (`.mm-heading-link` inline after the heading, E-tests in hosted.spec.ts) and the React `CopyLinkButton` placements (workspace, file, comment card) keep their current look and behaviour; any CSS change is scoped to `.mm-hl-link`.
- **A new e2e test proves the fix.** In `tests/e2e/hosted.spec.ts` beside E429, a new test with the next free E-number (E564 at time of writing; check `grep -rhoE "test\('E[0-9]+" tests/e2e | sort` for the current max) activates a highlight inside a body paragraph, clicks `mm-hl-link`, and asserts the caption's bounding box lies left of the paragraph's content-left edge, is within the viewport, and is visible. Existing E429/E432 pass unchanged.
- **Citations.** Changed code carries the repo's citation comment format naming PRD 022 Req 10 and issue #309 per `.sandcastle/CODING_STANDARDS.md`; `docs/MAP.md` is regenerated with `npm run map` if the spec→code table changes.
- **Iteration and the gate.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (or `npx playwright test -g '<title>'` for the one touched e2e test), baselines with the quick tier only, and runs `npm run validate:quick` ONCE right before declaring the goal met; it prints `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- **A summary comment from the implementer exists on issue #309** describing what changed, the fix approach, and the gate evidence.

## Context

The issue body is one line — "it renders over the text so its jumbled fix this" — plus a screenshot of the preview where the accent-blue caption "Link copied" is drawn across the words "work account" of a paragraph. The control is the active-highlight copy-link from PRD 022 Req 10 (issue #233), grafted by `src/lib/highlightLink.ts` (`updateHighlightLink`, called from the activation effect in `src/App.tsx` near the `PRD 022 Req 10` citation). It reuses the heading-link factory `createHeadingLinkButton` from `editor/src/lib/headingLinks.ts`; the shared look, including the `.is-copied::after { content: 'Link copied' }` caption, lives in `editor/styles.css` under `.doc .mm-heading-link`. The heading placement is inline after the heading text (`margin-left: 8px`), so its caption never collides; the highlight placement overrides it in `src/styles.css` (`.doc .mm-heading-link.mm-hl-link`) to `position: absolute; left: 6px` inside `.doc`, whose padding column is only 32px wide (`editor/styles.css` `.doc { padding: 40px 32px 96px }`). The caption at `--mm-text-caption` is roughly 70px wide, so it overflows into the text column.

Suggested approach (implementer's call): keep the glyph where it is and make the confirming state grow leftward into the workspace gutter rather than rightward — e.g. anchor the caption's right edge to the glyph's right edge (`.mm-hl-link.is-copied::after` positioned absolutely with `right: 0` / `transform: translateX(-100%)`, or set the button's `right` instead of `left` while confirming) — and give the caption an opaque elevated pill so it stays legible if the gutter is narrow. Avoid adding text nodes inside `.doc` (anchor space). E429 in `tests/e2e/hosted.spec.ts` is the model for the new test (helpers `signIn`, `pathWorkspace`, `stubClipboard`, `addHighlight`, `lastCopy`); `page.evaluate` with `getComputedStyle(btn, '::after')` or the button's `boundingBox()` in the copied state can measure the caption. Real commands: `npm run typecheck`, `npm run test:unit`, `npm run test:e2e`, `npm run validate:quick`, `npm run map`.
