# Spec: Slide open/close animations for folder pane and split preview (#5)

## Goal

All acceptance criteria in issue-specs/issue-5.md are satisfied for issue #5, with evidence visible in the session: the folder pane opens and closes as a horizontal slide from/toward the left edge using the app's existing motion language (a ~180ms ease transform transition with `will-change: transform`, as `.toolbar-shell` does) with the pane kept in the DOM through the exit transition, the split preview slides the same way from/toward the right edge, `prefers-reduced-motion: reduce` makes both panes switch instantly with no slide, every toggle surface (chevron, menu, hotkey, Settings checkbox) produces the same animation with end state and persistence identical to an instant toggle, and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- Opening and closing the folder pane animates as a horizontal slide from / toward the left edge, using the app's existing motion language: a transform transition of ~180ms ease with `will-change: transform`, as `.toolbar-shell` does (`src/styles.css:44`). The workspace content follows without visual tearing. The pane currently unmounts when hidden (`folderSeam && settings.showFolders &&` in `src/App.tsx`); it remains in the DOM for the duration of the exit transition, or an equivalent technique, so the slide is visible. (PRD Req 9)
- Opening and closing the split preview animates as a horizontal slide from / toward the right edge with the same duration and easing. (PRD Req 10)
- When `prefers-reduced-motion: reduce` is set, both panes switch instantly with no slide. This is the app's first use of that media query — it applies to these two pane transitions only (the toolbar slide and everything else are unchanged). (PRD Req 11)
- Toggling a pane via any surface — the edge chevrons (`folder-collapse`/`folder-expand`, `preview-collapse`/`preview-expand`), the View → Folders / View → Split Edit menu items, the `Mod+Shift+E` / `Mod+\` hotkeys, and the Settings panel's `set-split-edit` checkbox — produces the same animation, and the end state and persistence (`settings.showFolders` / `settings.splitEdit` in `settings.json`) are identical to an instant toggle. No new settings or state keys. (PRD Req 12)
- E2e coverage exists for the animation, observable via a polled `transform` interpolation the way E25 does for the toolbar (`tests/e2e/app.spec.ts:615` polls `DOMMatrixReadOnly(getComputedStyle(el).transform)` mid-transition), for both panes. Existing suites stay green — in particular the chevron/sync tests around E84/E94/E95 and web e2e W12 (the web build keeps zero folder-pane DOM; no animation DOM may leak there). (PRD Req 13, animation slice)
- Existing behavior is untouched: pane resizing (`folderWidth` drag, `splitRatio` drag and double-click reset), the chevrons' placement and labels from issues #3/#4, full preview mode (`mode === 'preview'`), and the toolbar's own slide all work exactly as before.
- `npm run validate:quick` passes, run ONCE in the implementer's session right before declaring the goal met — not after every small change, and not as a start-of-attempt baseline. Iterate with `npm run typecheck` and `npm run test:unit`, or Playwright tests targeted at the changed specs (e.g. `npx playwright test -g "E25"` or the new animation tests), while developing.
- A summary comment from the implementer exists on issue #5.

## Context

The motion language to copy is `.toolbar-shell` (`src/styles.css:44-57`): `transform` + `transition: transform 180ms ease` + `will-change: transform`, with a `.shown` class flipping the transform. The folder pane mounts conditionally in `src/App.tsx` (~line 3918, `folderSeam && settings.showFolders && <FolderPanel …>`), and the split layout branches on `settings.splitEdit` (~line 4037) — both branches swap DOM instantly today, so the exit animation needs the pane kept mounted until the transition ends (e.g. a "closing" state that unmounts on `transitionend`/timeout) or an equivalent technique. All toggle surfaces already funnel through the `toggleFolders` / `toggleSplit` commands, so animating at the render/CSS layer automatically covers chevron, menu, hotkey, and Settings toggles (Req 12). The chevron edge tabs from issues #3/#4 live in `src/components/FolderPanel.tsx` (`Chevron`, `FolderExpandButton`, `PreviewToggleButton`) with CSS near `.folder-expand` in `src/styles.css`. There is no `prefers-reduced-motion` usage anywhere yet — add it scoped to these two transitions only. E25 (`tests/e2e/app.spec.ts:615`) shows the polled-transform assertion pattern; W12 in the web e2e suite asserts the web build has no folder-pane DOM. `validate:quick` runs typecheck + unit tests + the desktop-shim e2e suite. PRD: `prd/003-pane-chevrons-and-slide-animations.md` (Requirements 9–12 for this issue). Blocked-by issues #3 and #4 have both landed on this branch.
