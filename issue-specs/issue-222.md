# Spec: Copy-link primitive with workspace and file share placements (PRD 020 Reqs 14–17) (#222)

## Goal

All acceptance criteria in issue-specs/issue-222.md are satisfied for issue #222, with evidence visible in the session: one reusable copy-link control exists — a link icon with tooltip "Copy link" that copies its target URL to the clipboard and itself briefly shows "Link copied" (~2s, `aria-live`-announced, no dialog or toast); the control renders only on the hosted platform (Tauri, dev-shim, and single-file builds show none of the placements); on hosted it sits with the workspace's top-left icon cluster copying the workspace's canonical `/<workspace-name>` URL, and top-right above the open file copying the file's canonical Req 5 URL, absent for untitled buffers; and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- **One primitive (Req 14).** A single reusable copy-link control implements both placements — one implementation, not two lookalikes (the `createCopyButton` precedent in `src/lib/codeCopy.ts` is the house pattern: one builder, callers differ only in where they hang it and what URL they feed it). At rest it is a link icon with tooltip "Copy link"; clicking copies the target URL to the clipboard and the control itself transforms to a "Link copied" confirmation for ~2 seconds, then reverts. No dialog and no toast stack. The confirmation is announced to assistive tech via `aria-live`. A rejected clipboard write leaves the control at rest rather than stuck confirming (the `codeCopy.ts` contract). The clipboard write goes through the platform seam (`platform.copyText`, `src/platform/types.ts:139`) or the equivalent existing copy path — not a new ad-hoc clipboard mechanism.
- **Copied URLs are shareable.** The copied text is an absolute URL (origin included) in the canonical Req 5 path form built from `buildAppPath` (`src/lib/hostedPaths.ts:202`) or equivalently from the canonical address bar — never the legacy `?workspace=` form and never a UUID.
- **Hosted only (Req 15).** The control (both placements) renders only when the platform is hosted (`kind: 'hosted'`); in the Tauri, dev-shim (`browser`), and single-file (`web`) builds neither placement produces any DOM. A bundle/grep check or test demonstrates the non-hosted builds are unaffected.
- **Workspace placement (Req 16).** On hosted with a workspace open, the control sits with the workspace's top-left icon cluster (the `leftCluster` / `.edge-cluster-left` / `FileTabStrip` `leading` seam, `src/App.tsx` ~6893–7150) and copies the workspace URL (`/<workspace-name>`). It is present in both layouts (tab strip on and off) and does not depend on the folder pane being closed the way today's left cluster does — a hosted user with the pane open can still copy the workspace link from the top-left region.
- **File placement (Req 17).** On hosted with a saved file open, the control sits top-right above the open file (the `rightCluster` / `.edge-cluster` / `FileTabStrip` `trailing` seam) and copies that file's Req 5 URL (workspace name + percent-encoded path segments, no heading fragment). It is absent for untitled buffers, and it is present for a read-only reader in preview mode — today's right cluster is gated on edit ability (`mode === 'edit' || mayToggleMode`), which must not hide the copy link.
- **Styling.** Both placements are styled per the chrome tokens and the existing edge-cluster/IconButton idiom (`docs/STYLE-GUIDE.md`, `src/components/ui/IconButton.tsx`) in light and dark themes.
- **Tests.** New pure logic (URL selection, confirmation timing contract) has unit tests; new `E<n>`-numbered e2e coverage (continuing from E185, `tests/e2e/hosted.spec.ts` or a sibling) exercises at least: both placements visible on hosted with a saved file open, the click-copies-and-confirms cycle for each placement with the expected URL on the clipboard (or through the platform copy seam), the file control absent for an untitled buffer, and no placements in a non-hosted run — as far as the local-mode harness drives them.
- **Citations.** New behaviour carries `// PRD 020 Req <n>:` citation comments per `.sandcastle/CODING_STANDARDS.md`, and `docs/MAP.md` is regenerated (`npm run map`) if citations moved.
- **Test economy.** The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code), and ran `npm run validate:quick` ONCE right before declaring the goal met — not after every small change and not as a full-suite baseline. `npm run validate:quick` passes in the implementer's session (`QUICK VALIDATION: ALL PASSED`).
- A summary comment from the implementer exists on issue #222.

The two corner clusters are built in `src/App.tsx` (~6893) and ride in the `FileTabStrip` `leading`/`trailing` slots when tabs are on; note both clusters' current render gates (left: pane closed; right: edit-capable) are narrower than the share control needs. Platform gating: `platform.kind === 'hosted'` (`src/platform/types.ts:35`). The issue thread has no comments beyond the body.
