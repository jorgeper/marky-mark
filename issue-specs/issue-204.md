# Spec: Migrate all app chrome onto the primitives (PRD 018 Reqs 12–21) (#204)

## Goal

All acceptance criteria in issue-specs/issue-204.md are satisfied for issue #204, with evidence visible in the session: every `<button>` in src/ (except the Microsoft-branded sign-in button) is a Button/IconButton wrapper or carries a `.btn*`/`.icon-btn` primitive class, with the nine ancestor `button` rules and the visual-only one-off classes deleted from src/styles.css; the three modal trees and four floating-menu trees are collapsed onto `.dialog*`/`.menu*` with per-site rules keeping layout only; all font-size, border-radius, box-shadow and control padding declarations in chrome rules use scale tokens, with document-rendering rules moved into a delimited section; every existing e2e test passes unweakened with every existing `data-testid` preserved; and `npm run validate:quick` has been run in the implementer's session and prints `QUICK VALIDATION: ALL PASSED`.

## Acceptance criteria

- (Req 12) Every `<button>` in `src/` (~152 sites today) is either a `Button`/`IconButton` wrapper from `src/components/ui/` or carries a `.btn*` / `.icon-btn` primitive class. Bare `<button>` elements styled only by an ancestor rule no longer exist; the nine descendant rules named in PRD 018's Problem section (`.modal .actions button`, `.card .row button`, `.find-bar button`, `.folder-header button`, `.edge-cluster button`, `.palette li button`, …) are deleted. The one exception is the Microsoft-branded sign-in button (Req 20).
- (Req 13) One-off button classes that only restated visual properties (`primary`, `linklike`, `destructive`, `table-chip`, `tbtn`, `scope-btn`, `hotkey-reset`, `membership-remove`, `folder-expand`, `sidebar-switch-btn`, `search-opt`, `fm-close`, `hosted-signin-ms`'s duplicated declarations, and the rest found during implementation) are removed from `src/styles.css`. A class survives only if it carries layout (position, flex, margin within its parent) or a test locator existing e2e tests use — and then carries no colour, radius, shadow, font-size, or padding declarations.
- (Req 14) The three modal trees (`.modal`, `.settings-modal`, `.management-modal` and their `workspace-*` variants) are collapsed onto `.dialog*`; per-dialog rules keep only layout (widths, grid of fields) and no shell styling.
- (Req 15) The four floating-menu trees (`.theme-menu`, `.smart-edit-menu` / `.smart-edit-item`, `.palette`, `.folder-menu`) are collapsed onto `.menu*`; per-menu rules keep only what is genuinely different (the theme swatch, the palette's search input).
- (Req 16) The four destructive rules are collapsed onto `.btn-danger`; no `#d1242f` (or any other hard-coded danger colour) remains in `src/styles.css`.
- (Req 17) All `font-size`, `border-radius`, `box-shadow`, and control `padding` declarations in chrome rules use the scale tokens from the CHROME TOKENS block; after migration `src/styles.css` contains no more than the scale's number of distinct values for each of those properties in chrome rules. Document-rendering rules (`.doc` and friends, starting ~line 729 today) are exempt and live in a clearly delimited section (BEGIN/END comment markers, analogous to the CHROME TOKENS block) so the future lint (Req 26, a sibling issue) can tell them apart — that delimiter does not exist yet and must be added.
- (Req 18) Inline `style={{ fontSize: … }}` literals in TSX are replaced by classes — today: three in `src/components/ErrorBoundary.tsx` (lines ~52, 53, 63) and two `<p style={{ fontSize: 13.5 }}>` in `src/App.tsx` (~7567, ~7650). Inline styles remain allowed only for computed geometry (widths, transforms, indents, and the settings-driven `--mm-font-size` custom-property sets in `App.tsx`/`AuxWindow.tsx`).
- (Req 19) Migration is visually conservative: each control moves to the nearest step of the scale; no control changes its variant, and no control gains or loses a border, fill, or shadow it did not have, other than the drift fixes named in PRD 018 Reqs 5 and 16.
- (Req 20) The Microsoft-branded sign-in button (`hosted-sign-in-microsoft`) keeps its branded logo and neutral fill per issue #196, implemented as `Button variant="neutral"` with an additional class carrying only the logo layout; its dimensions, radius, and font come from the primitive.
- (Req 21) Every existing e2e test passes unweakened, and every existing `data-testid` is preserved. Where a test located a control by a removed class (ten spec files under `tests/e2e/` reference legacy names like `tbtn`, `scope-btn`, `theme-menu`, `settings-modal`, …), the test is updated to the control's test id (adding one if it had none) — never by keeping the dead class alive.
- (Req 34) Changed behaviour carries citation comments per `.sandcastle/CODING_STANDARDS.md`, citing `PRD 018 Req <n>`. No new runtime dependency (Req 35).
- Scope guard: PRD 018 Reqs 22–33 (style guide, coding-standards section, the validate.mjs style lint, and the new styling e2e tests) are owned by sibling sub-issues and are NOT implemented here.
- Iteration used `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code — e.g. `npx playwright test -g '<title>'` for a single e2e behaviour) after each change; the full gate was NOT run per-change or as a starting baseline.
- `npm run validate:quick` was run once in the implementer's session, right before declaring the goal met, and printed `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #204.
