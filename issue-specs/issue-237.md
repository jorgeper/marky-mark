# Spec: Create the @marky-mark/editor workspace package: move the editor, author Preview and SplitView, export the contract (#237)

## Goal

All acceptance criteria in issue-specs/issue-237.md are satisfied for issue #237, with evidence visible in the session: an `/editor` npm workspace package (`@marky-mark/editor`) exists containing the editing surface plus newly authored Preview and SplitView components with the full prop/handle/seam contract exported, the app consumes the package with behavior preserved and its comment marks rewired through the Preview's decoration hook, `npm run validate:quick` passes, and a summary comment from the implementer exists on issue #237.

## Acceptance criteria

- (PRD 021 Req 1) Workspace conversion is complete: the root `package.json` declares npm `workspaces` including `editor/`, the app depends on `@marky-mark/editor` as a workspace dependency, and a single `npm install` at the root wires everything — no separate install step inside `editor/`.
- (PRD 021 Req 2) `/editor` is self-contained: its own `package.json` (name `@marky-mark/editor`, `"private": true`) with `react`/`react-dom` as peer dependencies and the CodeMirror packages as regular dependencies; its own build script producing an ESM library; and its own vitest setup such that `npm test` run inside `editor/` executes the package's unit tests in isolation (the unit tests covering moved modules move with them; app-side unit tests stay in `tests/unit/` and keep passing).
- (PRD 021 Req 3, editing surface) The package contains and exports the editing surface: today's `src/components/Editor.tsx` and its companion modules (`livePreview`, `tableMode`, `imageView`, `codeBlockView`, `diagramView`, `SmartEditMenu`, plus `anchoredMenu` and the pure editor-side libs they import, e.g. `remoteSrc`-style helpers, `scrollSync.ts` and whatever else the module graph requires) live under `editor/` and are re-exported from the package entry point. The app imports them only from `@marky-mark/editor` (no deep-path imports into `editor/src`).
- (PRD 021 Req 3, Preview) A new `Preview` component exists in the package, authored from the `.split-preview` subtree currently inline in `App.tsx` (~`src/App.tsx:7537`): markdown rendering via the existing unified pipeline, `data-mm-line` scroll anchors, code-copy affordances, and mermaid and image behaviors all work through it. The unified/remark pipeline is imported only by the Preview side, never by the editing-surface modules.
- (PRD 021 Req 3, SplitView) A new `SplitView` component in the package composes Editor and Preview with the existing divider and sync-scroll behavior (`scrollSync.ts` logic; PRD 001's visual seam preserved). The app's split mode renders through it with no visual or behavioral change.
- (PRD 021 Req 4) The contract is exported and documented: the previously unexported editor `Props` interface, the imperative handles (`EditorSyncHandle`, `SmartEditHandle`, `EditorSearchHandle`, and any others), the seam callbacks (`HeadingLinkSeam`, clipboard seams, `resolveImageSrc`, `onOpenExternal`, `onPasteImages`, …), and the new Preview/SplitView prop types are all exported from the package entry point with doc comments. Everything Marky Mark's `App.tsx` does with the editor/preview/split is expressed through this public API — verifiable because the app compiles using only package exports.
- (PRD 021 Req 8) The Preview exposes a documented post-render DOM-decoration seam (e.g. a callback invoked with the rendered root after each render) sufficient for the app's comment marks (`src/lib/domtext.ts`'s `<mark class="hl">` wrapping) and comment click routing, and the app's comments are rewired through that hook in this same change — comment highlighting and click behavior work exactly as before, nothing left half-wired.
- (PRD 021 Req 12) Citations survive: moved files keep their `SPEC<n>`/PRD citation comments, new components carry citations for what they implement, and `docs/MAP.md` is regenerated via `npm run map` so the gate's MAP diff is clean on the new paths.
- Scope guard: editor/preview/split CSS stays in `src/styles.css` and the app keeps applying it (moves in a later sub-issue); no visual change. The gate's import-boundary enforcement (PRD Req 10), README/samples (Reqs 13–16), and `editor/AGENTS.md` (Req 11) are out of scope here.
- Behavior is preserved: existing e2e suites (editor, split-view, tables, live-preview, smart-edit, images, mermaid, search) pass without behavioral edits — mechanical import-path/selector-neutral updates only.
- The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code) after each change, and ran the full gate `npm run validate:quick` ONCE, right before declaring the goal met — not after every small change and not as a baseline — and it printed `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- A summary comment from the implementer exists on issue #237.
