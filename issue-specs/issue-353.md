# Spec: PRD 026: settings Names section — display name required, URL name normalises with guidance and preview, grandfathered value kept until edited (#353)

## Goal

All acceptance criteria in issue-specs/issue-353.md are satisfied for issue #353, with evidence visible in the session: the settings Names section (`src/components/WorkspaceNames.tsx`) leads with a required **Display name** field (`workspace-friendly-name`, prefilled from the manifest's `name`) followed by **URL name** (`workspace-unique-name`), and Save refuses a blank trimmed display name with `A display name is required.` instead of storing the URL name as the display; the URL-name field shows a grandfathered stored value (e.g. `Team_Docs`) verbatim with no type-time problem and no error paint, and a display-name-only save sends the stored URL name unchanged; every URL-field input is normalised through `normalizeUrlNameTyping`, and once the value differs from the stored one it is settled on blur and at save and must pass `uniqueNameProblem` (empty → `A URL name is required.`) before the manifest PUT; the display name never auto-derives the URL name; `UrlNameGuidance` is mounted beneath the URL-name field with prefix `workspace` and the former-names caption is unchanged; the section's pure validation is unit-tested (U1333+), E535 and E572 are updated, and new hosted e2e tests (E602+) show a seeded grandfathered workspace renamed to its lowercase-dash form while a display-name-only save leaves the stored name in place; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #353.

## Acceptance criteria

- **Field order and labels (PRD 026 Req 10).** In `WorkspaceNames` the first `.field` is labelled **Display name** (no "(optional)") and its input keeps `id`/`data-testid` `workspace-friendly-name`; the second `.field` is labelled **URL name** and its input keeps `id`/`data-testid` `workspace-unique-name`. No test id is renamed and no `autoFocus` is added (the section lives in a settings panel, not a dialog). The intro `.hotkey-hint` paragraph is rewritten so it no longer says a blank display name shows the unique name; it says the display name is what the app shows and the URL name is the workspace's address (wording the implementer's choice, no test asserts it). The `SectionHeader`, `workspace-names-error` line, `workspace-names-save` button and `dialog-actions` wrapper are unchanged.
- **Display name required, prefilled from the manifest (Req 10).** The display-name state is initialised from `manifest.name` (what the chrome shows), not `friendlyNameOf(manifest) ?? ''`, so a workspace whose display name equals its URL name opens with that name in the field rather than an empty required field; `friendlyNameOf` stays exported and U1050 is untouched. At save, `displayName.trim() === ''` refuses first with `A display name is required.` (reuse `DISPLAY_NAME_REQUIRED` from `src/lib/workspaceLifecycle.ts`), no PUT is sent, and the display-name input wears `field invalid invalid-value` exactly while `error === DISPLAY_NAME_REQUIRED`; any display-name `onChange` calls `setError('')` first so editing it retires message and paint. On success the PUT body's `name` is the trimmed display name — the `friendly.trim() || uniqueName` fallback is gone.
- **Grandfathered value untouched until edited (Req 9 + 10).** The stored URL name is read from the `manifest` prop (`manifest.uniqueName ?? ''`) on every render, never copied into state, so after a successful rename the value the save handed back becomes the new baseline. Define `edited = uniqueName !== stored`. While `!edited`: the type-time problem line (`workspace-unique-name-problem`) is absent, the URL-name field wears no error paint (unless a server refusal satisfies `isUniqueNameError`, exactly as today), blur leaves the value alone, and save sends `uniqueName: stored` with no strict check — so a display-name-only save of a `Team_Docs` workspace is a 200 that keeps `Team_Docs` (the server skips Req 1 for an unchanged name; `server/workspaces.ts` is not edited). While `edited`: `typedProblem = settled === '' ? null : uniqueNameProblem(settled)` where `settled = settleUrlName(uniqueName)`; blur replaces the value with `settled`; save refuses `settled === ''` with `A URL name is required.` (`URL_NAME_REQUIRED`), then `uniqueNameProblem(settled)` with its own message, before sending `uniqueName: settled`. The URL-name field wears `field invalid invalid-value` exactly while `typedProblem !== null || (error !== '' && isUniqueNameError(error))` (the existing `nameRejected` rule, unchanged in shape).
- **Normalise as you type, no auto-derive (Req 6 + 10).** Every URL-name `onChange` value passes through `normalizeUrlNameTyping` before it reaches state (`Foo Bar`→`foo-bar`, `foo--bar`→`foo-bar`, `foo-` kept while typing) and calls `setError('')` first (the existing #250 behaviour). Editing the display name never changes the URL-name state — there is no `touched` flag and no `slugifyWorkspaceName` call in this component.
- **Guidance and preview (Req 7).** `UrlNameGuidance` from `src/components/UrlNameGuidance.tsx` is mounted inside the URL-name `.field`, after the input and its problem line, with `origin={window.location.origin}`, `urlName={edited ? settled : uniqueName}` and `testIdPrefix="workspace"`, producing `workspace-url-guidance` (the verbatim sentence `Lowercase letters, numbers and dashes. This is the workspace's address.`) and `workspace-url-preview` (`urlNamePreview(origin, value)`: `${origin}${buildAppPath(value)}`, or `${origin}/…` when empty). The preview updates on every keystroke in the URL field and is unaffected by the display field. The component and its `.url-name-guidance` rule are reused, not duplicated; no new colour or size literal is added (the style lint in the quick gate enforces this).
- **Former-names caption unchanged (PRD 024 Req 16).** `workspace-former-names` keeps its text, its `.hotkey-hint` treatment and its read-only nature, and renders directly after the URL-name `.field` (i.e. after the guidance and preview), before the error line and actions. Document order within the section is therefore `workspace-friendly-name`, `workspace-unique-name`, `workspace-url-guidance`, `workspace-url-preview`, `workspace-former-names`.
- **Pure validation lives in `src/lib` and is unit-tested (Req 13).** A pure exported function in `src/lib/workspaceLifecycle.ts` (name the implementer's choice, e.g. `validateWorkspaceNamesForm({ displayName, urlName, storedUrlName })`) implements the save-time decision above and returns either `{ ok: true, name, uniqueName }` or `{ ok: false, error }`; the component calls it rather than re-implementing the order. New tests in `tests/unit/workspace-lifecycle.test.ts` titled `U1333:` upward (never reuse a number; U1332 is the highest in use) cover: blank display name refused first even when the URL name is also bad; an unedited grandfathered `Team_Docs` passes through untouched with the trimmed display name; an edited value ending in one trailing dash settles (`team-docs-`→`team-docs`); an edited empty value earns `A URL name is required.`; an edited `Team-Docs` earns the charset refusal from `uniqueNameProblem`; an edited value equal to the stored value is treated as unedited. `src/lib/` stays free of React/DOM imports; no `console.*` in `src/`.
- **Existing e2e tests updated in place, not weakened.** In `tests/e2e/hosted.spec.ts`: E535's type-time refusal step uses a reserved word (`scratchpad`) instead of `has spaces` (which now normalises to `has-spaces`), and the rest of its assertions stand; E572's document-order array becomes `['workspace-friendly-name', 'workspace-unique-name', 'workspace-url-guidance', 'workspace-url-preview', 'workspace-former-names']` and its comment describes the new placement. E536, E537 and the styling tests E5xx that list `workspace-names-section` need no change (their `fill()` values are already lowercase-dash and they never touch the display field's emptiness) — if one fails, fix the product, not the test.
- **New e2e coverage (Req 14, settings part).** New tests titled `E602:` upward (E601 is the highest in use), all in `tests/e2e/hosted.spec.ts`, every name timestamped per worker as `pathWorkspace` does:
  - **Grandfathered rename (Req 9 + 10).** Seed a workspace whose stored `uniqueName` fails Req 1 but passes the legacy rule — e.g. `E602_Team_Docs-w<worker>-<stamp>` — by creating it through the API and then overwriting `workspaces/<id>/manifest.json` in Azurite with the same manifest carrying the legacy name (the `BlobServiceClient.fromConnectionString(AZURITE_CONNECTION_STRING).getContainerClient('marky-mark')` pattern the PRD 017 policy tests already use; `serializeWorkspaceManifest` from `src/lib/hostedWorkspace` or `JSON.stringify`); confirm via `GET /api/workspaces` that the listing shows the legacy name before driving the UI. Then: the settings URL field shows the legacy name verbatim, `workspace-unique-name-problem` has count 0 and the field is not painted (reuse `fieldPaint`/`errorTokens`); the preview reads `${origin}/${encodeURIComponent(legacy)}`; changing only the display name and saving leaves the API manifest's `uniqueName` at the legacy value with `formerNames` undefined and the tab's pathname unchanged; then filling the URL field with its lowercase-dash form (e.g. `e602-team-docs-w<worker>-<stamp>`) and saving lands the tab on `/<renamed>`, the API manifest holds the new name with `formerNames` `[legacy]`, and `workspace-former-names` lists the legacy name.
  - **Required fields (Req 10 + 8).** Clearing the display field and saving shows `A display name is required.` in `workspace-names-error` with the display field in the #245 paint and the URL field not painted; the stored manifest is unchanged; typing in the display field clears message and paint. Clearing the URL field and saving shows `A URL name is required.` with the URL field painted; typing restores it.
  - **Normalise and preview without auto-derive (Req 6 + 7 + 10).** `pressSequentially('Foo Bar')` into the emptied URL field shows `foo-` after the space and `foo-bar` at the end with the preview at `${origin}/foo-bar`; blur strips a trailing dash; typing into the display field leaves the URL field's value unchanged; the guidance sentence is visible at the caption size and muted colour (compare against `var(--mm-text-caption)` / `var(--mm-fg-muted)` resolved on the page, as E601 does), never the danger colour.
- **Citations and comments.** Every changed behaviour carries a `PRD 026 Req <n>` citation per `.sandcastle/CODING_STANDARDS.md`; the `PRD 020 Req 4` / `Req 2` header and inline comments in `WorkspaceNames.tsx` that describe the optional display name, the unique-name-first order, or the "blank stores the unique name" rule are rewritten to the amended contract. `docs/MAP.md` is regenerated with `npm run map` only if the gate's map check reports drift.
- **Verification economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (or `npx vitest run tests/unit/workspace-lifecycle.test.ts`) after each change, uses targeted runs such as `npx playwright test -g 'E535|E572|E602'` while debugging the section, and does not run the full gate as a baseline at the start of an attempt.
- **Gate.** `npm run validate:quick` has been run once in the implementer's session, right before declaring the goal met, and prints `QUICK VALIDATION: ALL PASSED` (its e2e step runs `tests/e2e/hosted.spec.ts` against the local hosted server, so the new E tests are part of it).
- **Summary comment.** A summary comment from the implementer exists on issue #353 describing what changed, the tests added/updated, and the gate result.
