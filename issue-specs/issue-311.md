# Spec: scratchpad file to show in folder panel (#311)

## Goal

All acceptance criteria in issue-specs/issue-311.md are satisfied for issue #311, with evidence visible in the session: while the scratchpad's boot-opened scratch buffer is alive, the folder panel shows a "Scratchpad file" row in the same accent/italic `--mm-scratch-name` treatment as its tab and toolbar name, selected while the buffer is active; opening another file in the scratchpad workspace parks the scratch buffer instead of discarding it, so the row (and its tab) stay and clicking the row brings the buffer back with its text and dirty state; closing the row's ✕, saving, or leaving the workspace removes the row, and no ordinary "Untitled" buffer ever gets one; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #311.

## Acceptance criteria

- **The row exists.** While the scratch buffer (the one the hosted `scratchStart` boot opened and `setScratchMark(true)` flagged in `src/App.tsx`) is alive — active or parked — the folder panel (`src/components/FolderPanel.tsx`) shows one row for it: file glyph, label from the shared resolution in `src/lib/docName.ts` (`untitledDisplayName(true).name`, i.e. "Scratchpad file"), rendered as the first row under the workspace root in tree view and first in the SPEC36 §5.3 only-open list. The row carries its own test id `folder-item-scratch` (NOT `folder-item`, so existing `folder-item` counts and `filter({ hasText })` locators in `tests/e2e/hosted.spec.ts` are unaffected) and `data-scratch="true"`.
- **Same blue/italics.** The row's label carries the existing `.scratch-name` class so it resolves `--mm-scratch-name` / `--mm-scratch-name-style` exactly like the toolbar name and the tab label (PRD 023 Req 7). No colour, font-style or size literal is added to `src/styles.css` for it (the style lint in `tests/unit/style-lint.test.ts` enforces this); any new rule uses existing chrome tokens.
- **Open-set visuals.** The row uses the SPEC36 §4 tab styling: `selected` while the scratch buffer is active, `open` while it is parked, and the §3.4/§3.6 trailing slot — a ● (`folder-dirty`) while the buffer is dirty, swapped for the ✕ (`folder-tab-close`) on hover. No context menu (right-click opens nothing, like the untitled tab), no drag source, no rename.
- **Click back.** Opening any other file in the scratchpad workspace (sidebar click, Mod+click, tab click, deep link) while the scratch buffer is active **parks** it — text, dirty state, editor history and selection — instead of discarding it, with no unsaved-changes prompt (PRD 019 Req 11's exemption stands). The row and the file-tab strip's scratch tab stay, both in the parked/inactive state. Clicking the row (or the tab) restores the buffer: the editor shows the parked text in edit mode, `docname` and the browser title read "Scratchpad file", the dirty dot reflects the parked dirtiness, the previously active file parks as usual, and the address bar returns to the canonical `/<username>/scratchpad` URL (PRD 020 Req 10/11) as it reads at boot. Clicking the row while the buffer is already active is a no-op. This deliberately amends the "opening another file discards it" leg of PRD 019 Req 11 / E398 for the scratch buffer, per the issue's "so that I can click back on it".
- **Closing still discards silently.** The row's ✕ (and the tab's ✕ / middle-click / File → Close while the scratch buffer is active) discards the buffer with no prompt, dirty or not; the row and tab disappear; SPEC36 §3.5 neighbour activation (or the splash) follows as for any close. Closing the parked scratch from its row ✕ leaves the active file untouched. Leaving the workspace, a reload, and a fresh scratchpad visit still start a fresh buffer with the old one gone (PRD 023 Reqs 1–3; the SPEC30 §3 crash-draft shadow keeps covering the active scratch buffer as today; the parked buffer is not persisted to `session`/`foldertree`).
- **Saving replaces the row.** The first save (issue #292's picker, E399) turns the buffer into an ordinary file: the scratch row disappears and the saved file's ordinary `folder-item` row is the selected one. No scratch row survives a save.
- **Scoped to the scratch buffer (PRD 023 Req 8).** No row is ever shown for an ordinary untitled buffer (⌘N on desktop, the shim, or the single-file build), and nothing changes outside the hosted scratchpad workspace: desktop/shim `FolderPanel` rendering, `openFiles` ordering (SPEC36 §1), cycling hotkeys (§6), the quit walk (§7), and the New File flow are untouched. The `openFiles: string[]` open set stays path-only — the scratch buffer's presence is a separate, explicit prop into `FolderPanel` and `FileTabStrip`, not a fake path in the set.
- **One source of truth.** The row, the tab and the toolbar name all read the same `docName.ts` resolution and the same scratch state, so they cannot disagree; `stateRef`/`scratchRef` synchronous guards keep reading a value that is correct at guard time (the pattern issue #291 established).
- **Coverage.** New hosted e2e tests in `tests/e2e/hosted.spec.ts` (next free `E<n>` after E549; the `test-ID uniqueness` step in `scripts/validate.mjs` is the arbiter) pin: the row's presence, label, `.scratch-name` computed italic + accent colour (in the mold of E447), `selected` state at boot; park-and-restore via the row (dirty text survives the round trip, no `open-prompt`, URL and `docname` correct both ways); the ✕ discard with no prompt; the row's absence after save (extend or sit beside E399); and E398 amended to the new contract (opening a file over the dirty scratch still raises no prompt, but the text now returns on click-back). Any new pure helper (e.g. row-model or park-entry shaping in `src/lib/`) gets `U<n>` unit tests (next free after U1264). The e2e count floor in `scripts/validate.mjs` must not regress.
- **Citations and map.** Every changed behaviour site carries its citation comment in the repo's format (`// Issue #311: …`, alongside the PRD 019/023 and SPEC36 citations already there), per `.sandcastle/CODING_STANDARDS.md`; `docs/MAP.md` is regenerated with `npm run map` if the gate's freshness check complains.
- **Test economy.** Iterate with `npm run typecheck` and `npm run test:unit` (or a single test via `npx vitest run <file>` / `npx playwright test -g '<title>'`). The full gate runs **once**, right before declaring the goal met — not after every change and not as a start-of-attempt baseline (baseline with the quick tier only).
- **`npm run validate:quick` passes**, run in the implementer's session, printing `QUICK VALIDATION: ALL PASSED`.
- **A summary comment from the implementer exists on issue #311**, describing what changed (including the amended discard-on-open leg) and carrying the validate:quick evidence.

## Context

The issue (no comment thread; its screenshot did not download) asks for the scratchpad's buffer to appear in the folder panel "with special rendering (same blue/italics) so that I can click back on it". Today the untitled buffer sits outside the SPEC36 open set (`FileTabStrip.tsx` appends its tab as always-active; `FolderPanel.tsx` has no row for it) and `openDocGuarded` / `modOpenFile` (`src/App.tsx:~2590`) discard the scratch buffer silently when another file opens (E398). "Click back" therefore needs a park entry for the scratch buffer beside `parkRef` (SPEC36 §2; park entries are keyed by path, so the scratch one needs its own slot or key) and a restore path that `startUntitled`-style resets the surface with the parked text instead of an empty buffer.

Scratch state: `scratch` / `scratchRef` / `setScratchMark` (`src/App.tsx:~527`), armed only by the hosted `scratchStart` boot (`~3058`), cleared in `startUntitled`, `openDoc`, close and save. Name resolution: `src/lib/docName.ts`. Row markup and styling: `FileRow` in `FolderPanel.tsx:~470`, `.folder-item.selected/.open` in `src/styles.css:~2450–2530`, `.scratch-name` at `~599`, tokens at `~128`. The `FolderPanel` and `FileTabStrip` props are wired at `src/App.tsx:~7992` and `~8168`; `onCloseUntitled` dispatches `closeFile` (`~4823`). Hosted e2e house setup (`signIn`, `dropDraft`, `/api/me/scratchpad`, `docname`, `file-tab`, `dirty-dot`, `open-prompt`) is in `tests/e2e/hosted.spec.ts` around E397–E399, E447 and E521; the hosted lane runs inside `npm run test:e2e` and so inside `validate:quick`. Read `docs/STYLE-GUIDE.md` before touching chrome. Background: `prd/023-scratch-fresh-buffer.md`, issue-specs for #290–#293.
