All acceptance criteria in issue-specs/issue-206.md are satisfied for issue #206, with evidence visible in the session: a new `tests/e2e/styling.spec.ts` asserts via computed styles that representative chrome controls agree under one light and one dark bundled theme and that a chrome-token override changes a primitive; `E2E_TEST_FLOOR` in `scripts/validate.mjs` is re-pinned to the grown desktop-shim test count; the PRD 018 closeout audit (citation comments, unchanged runtime `dependencies`) is clean; and `npm run validate:quick` has passed in the implementer's session printing `QUICK VALIDATION: ALL PASSED`.

## Acceptance criteria

- (Req 30) A new `tests/e2e/styling.spec.ts` exists in the desktop-shim suite, with tests numbered from the next unused `E<n>` ids (highest existing is E391, so E392+). The tests load the app and read computed styles from representative controls: the splash's neutral action (a `start-<id>` button on `data-testid="start-actions"`), the hosted sign-in's local-mode submit button (`data-testid="hosted-sign-in-submit"`), a dialog's primary action, a toolbar icon button (an `.icon-btn` site), and a destructive button from a workspace settings surface (e.g. `data-testid="workspace-delete-submit"`). For each pair of controls sharing a primitive variant, the tests assert equal `border-radius`, `font-family`, `font-size`, and `padding`; for the neutral variant they assert the computed background equals the resolved value of the theme's `--mm-bg-elevated`.
- (Req 31) The same assertions pass under one light and one dark bundled theme (e.g. `crisp` and `github-dark`), with neither theme defining any chrome token — proving the chrome follows the theme through the derived defaults.
- (Req 32) One e2e test in the same file asserts that overriding a chrome token (a fixture theme, or a `.theme-root` style injected by the test, e.g. setting `--mm-radius-sm` or `--mm-danger`) changes the affected primitive's computed style — proving PRD 018 Req 6's override story is real.
- (Req 33) `E2E_TEST_FLOOR` in `scripts/validate.mjs` (currently `380` at line ~302) is re-pinned to the new collected desktop-shim test count, since the new spec file grows it. (Only the desktop-shim config counts; `test:e2e:web` is separate.)
- (Req 34) Closeout audit: behaviour changed across the PRD 018 sub-issues (#203, #204, #205) carries citation comments per `.sandcastle/CODING_STANDARDS.md` citing `PRD 018 Req <n>`; the chrome token block (`src/styles.css` ~lines 50–139) and each primitive rule (the `PRIMITIVES` block) cite the requirement that defines them. Any gap found is fixed on this branch; if the audit finds no gaps, the implementer's summary comment says so explicitly.
- (Req 35) Closeout audit: `package.json` `dependencies` are unchanged from before PRD 018 (no runtime dependency was added by issues #203–#206). The new e2e tests use only the existing Playwright devDependency.
- (Req 36) `npm run validate:quick` passes in the implementer's session and prints `QUICK VALIDATION: ALL PASSED`, run ONCE right before declaring the goal met — not after every small change, and not as a baseline. Iterate with `npm run typecheck` and `npm run test:unit`, plus targeted e2e runs of the new file only (`npx playwright test tests/e2e/styling.spec.ts` or `-g '<title>'`), since the full e2e suite is minutes and serialized machine-wide.
