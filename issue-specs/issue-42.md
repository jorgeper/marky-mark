# Spec: bugs with file management (#42)

## Goal

All acceptance criteria in issue-specs/issue-42.md are satisfied for issue #42, with evidence visible in the session: every dirty-detection comparison site in the app has been audited and uses one consistent predicate, a document whose buffer differs from its saved text only by canonicalization or line-ending representation is never reported dirty (so no spurious save/discard prompt appears), unit tests cover the fixed cases, and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- Every site that decides "is this document dirty?" has been audited and they all agree on one predicate. Today the active buffer uses `canonicalOf(buffer) !== savedText` (`src/App.tsx:453`) while parked buffers are raw-compared as `pk.buffer !== pk.savedText` (`src/App.tsx:456-467`, `:1451`, `:1664`, `:1708`, `:2606`). After the change, no site can classify a buffer as dirty when its canonical form equals the saved text — either because parked entries always store canonical text, or because every comparison goes through a single shared helper. The implementer's summary comment lists the audited sites and the verdict for each.
- A file that differs from the in-editor buffer only by line-ending representation is not reported dirty. Concretely: open a document whose on-disk content uses CRLF (loadDocParts at `src/App.tsx:1024` does no normalization, while CodeMirror's `doc.toString()` joins lines with `\n` — see `src/components/Editor.tsx:981`), type a character and undo it (or trigger any doc change that leaves the text logically identical): the window shows no dirty state and closing the tab or app shows no save/discard prompt. The fix point (normalize once at load vs. normalize in the comparison) is the implementer's choice, but the chosen behaviour must be deliberate about what a subsequent Save writes to disk, and documented in the summary comment.
- A document in table mode (tracked grids expanded in the editor, compact form on disk — SPEC38/40 §3.5) that the user has not logically edited shows no dirty indicator in the sidebar, and switching tabs away and back, closing its tab, or quitting produces no save/discard prompt.
- No existing guard behaviour regresses: genuinely dirty documents (including dirty untitled buffers and dirty parked tabs) still prompt on tab close, file open over a dirty doc, workspace close, and the SPEC36 §7 quit walk. The existing e2e suites covering this (`tests/e2e/documents.spec.ts`, `tests/e2e/tabs-and-workspace.spec.ts`, `tests/e2e/tables.spec.ts`) pass unchanged unless a test itself encoded the buggy behaviour, in which case the test is corrected with a comment citing this issue.
- Unit tests exist in `tests/unit/` for the fixed comparison logic (at minimum: canonical-equal parked buffer is clean; CRLF-vs-LF-only difference is clean; a real one-character edit is dirty). If the fix lands in pure logic extracted to `src/lib/`, the tests target that module directly.
- New or changed behaviour carries `// SPEC<n> §x.y` or issue-citation comments per `.sandcastle/CODING_STANDARDS.md`, and `docs/MAP.md` is regenerated via `npm run map` if spec→code coverage changed.
- Iteration used `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code) after each change; the full gate was NOT run per-change and NOT run as a baseline. `npm run validate:quick` has been run exactly once, right before declaring the goal met, and prints `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- A summary comment from the implementer exists on issue #42 describing the audit results, the root causes found, the fixes, and the validation evidence.

## Context

The user report: a save/discard prompt appears for files they haven't really changed. Dirty detection lives in `src/App.tsx` — grep `SPEC36` for the tab/park/quit-walk machinery and `canonicalOf` for the comparison sites; do not read `App.tsx` end-to-end. Two known inconsistencies to start from: (1) parked-buffer checks skip canonicalization, so a doc parked while table mode had grids expanded raw-compares grid text against compact saved text; note `parkActive` (`src/App.tsx:1250`) stashes `s.buffer` as-is and the editor only pushes canonical text on unmount (`src/components/Editor.tsx:1265`), so ordering matters. (2) Nothing normalizes line endings between `readTextFile` and CodeMirror, whose `toString()` emits `\n`, so any edit to a CRLF file makes the whole buffer differ even after undo. Audit beyond these two — the issue asks for a sweep of the change-detection logic, including the watcher's never-clobber path (`src/App.tsx:1414`) and the parked-restore disk-wins rule (`src/App.tsx:1451`). E2e tests run via `npx playwright test -g '<title>'` for single behaviours; the full suite is minutes and serialized.
