# Spec: Heading share affordance and heading-link landing (PRD 020 Reqs 18–19) (#223)

## Goal

All acceptance criteria in issue-specs/issue-223.md are satisfied for issue #223, with evidence visible in the session: hovering a preview heading (or resting the editor cursor on a heading line) reveals the hosted-only copy-link control that copies the file URL plus a GitHub-style `#<slug>` derived from the section model; landing on a `#<slug>` URL scrolls the opened file to that heading in the current view mode, with a brief dismissible notice when no heading matches; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #223.

## Acceptance criteria

- **Slug derivation (Req 18).** A pure, unit-tested function derives heading slugs from the section model (`src/lib/sectionModel.ts` — heading titles in document order), never from scraping DOM. Slugs are GitHub-style: heading text lowercased, punctuation dropped, spaces → `-`, duplicate slugs deduped `-1`, `-2`… in document order. Unit tests cover punctuation, unicode/edge text, and duplicate-heading dedupe.
- **Heading share URL (Req 18).** The share-URL logic layer (`src/lib/shareLinks.ts`, whose scope note explicitly defers `#fragment` emission to this issue) exposes a heading share URL: the file's canonical Req 5 URL plus `#<slug>`, null when no file rides the path.
- **Preview placement (Req 18).** In the rendered preview, hovering a heading reveals the copy-link control beside it; clicking copies the heading URL and confirms per the Req 14 contract (`CopyLinkButton` / `createCopyLinkController` — "Link copied" ~2s, `aria-live`, no dialog).
- **Editor placement (Req 18).** In the editor, a cursor resting on a heading line reveals the control in the gutter; clicking copies the same heading URL with the same confirmation contract.
- **Hosted only (Req 15).** Both heading placements render only on the hosted platform — absent in Tauri, dev-shim, and single-file builds, matching the existing workspace/file placements' gating.
- **Landing (Req 19).** Opening a Req 5 file URL with `#<slug>` opens the file and scrolls to the matching heading in the current view mode, reusing the TOC's existing navigate-to-line machinery (PRD 012: `scrollToLine` for edit, the preview scroll path for read). The hash survives the hosted sign-in round trip (the existing `visit.hash` preservation).
- **Graceful miss (Req 19).** When no heading matches the slug, the file opens at the top with a brief dismissible notice reading "That section wasn't found — it may have been renamed"; the link otherwise behaves exactly like a normal Req 5 file link.
- **Tests.** New/updated unit tests for slug derivation and the heading share URL, and E-numbered e2e coverage (continuing from E406, in `tests/e2e/hosted.spec.ts` or the suite that fits) for: the preview hover affordance copying the slugged URL, the editor gutter affordance, landing on a `#<slug>` link scrolled to the heading, and the not-found notice.
- **Citations.** New behavior carries citation comments per `.sandcastle/CODING_STANDARDS.md` (PRD 020 Reqs 18/19); styling follows `docs/STYLE-GUIDE.md` chrome tokens.
- **Verification economy.** The implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code, e.g. `npx playwright test -g '<title>'` for one e2e), and ran the full gate `npm run validate:quick` exactly ONCE, right before declaring the goal met — it printed `QUICK VALIDATION: ALL PASSED` in the implementer's session. No full-suite baseline run at the start.
- A summary comment from the implementer exists on issue #223.
