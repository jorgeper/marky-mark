# Spec: Fluid mode (4/5): deletion effects (Fade, Pop, Burst) on a ghost of the removed text (#336)

## Goal

All acceptance criteria in issue-specs/issue-336.md are satisfied for issue #336, with evidence visible in the session: with the Fluid mode switch on and Deletion mapped to Fade, Pop or Burst, a document change that purely removes text (Backspace, Delete, deleting a selection, cut, undo/redo — never a replacement such as typing over a selection) draws, in the existing `fluid-overlay` layer, a ghost carrying the removed text at its last painted position, which Fade dissolves, Pop scales out to ~0.8 while dissolving, and Burst dissolves while scattering a handful of small particles that live no longer than 400 ms, after which every element is removed; a change removing more than `FLUID_LARGE_OPERATION_CHARS` characters or `FLUID_LARGE_OPERATION_LINES` lines draws nothing; the deletion itself is never deferred; the ghost never enters the content DOM and is cancelled and removed at once on scroll, resize, a further document change, theme-variant change or the mode turning off; under `prefers-reduced-motion: reduce` no ghost or particle is created; the span decision, the ghost's box and the particle geometry are pure, unit-tested functions in the editor package; one e2e test proves the negatives without any time-based wait, with E580's Backspace step narrowed to assert no caret ghost; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #336.

## Acceptance criteria

### Which removals animate (PRD 025 Reqs 12, 14)

- A pure, exported function in the editor package (a new `editor/src/lib/fluidDeletion.ts`, re-exported from `editor/src/index.ts` like `fluidSelection.ts`) decides which removed spans of one applied transaction get a ghost. It takes a plain descriptor, not a `Transaction` — e.g. `{ docChanged; userEvent: string | null; spans: Array<{ fromA; toA; fromB; insertedLength; lines }> }` where `spans` is what `update.changes.iterChanges` yields (one entry per changed range, `lines` = document lines the removed range touched in the start document: `lineAt(toA).number - lineAt(fromA).number + 1`) — and returns the spans to ghost (an empty list meaning no effect).
- It returns nothing when `docChanged` is false or no span removes text (`toA === fromA` for all of them: typing, paste, Enter, an insertion-only undo/redo).
- A span that removes **and** inserts text (`insertedLength > 0`) is a replacement and is never ghosted: typing or pasting over a selection, completions, IME composition, smart-edit / table-edit rewrites. This is what keeps E582's "typing over a selection draws nothing" step true; it is also the seam #337's insertion effect will own. A transaction mixing a replacement span and a pure-removal span ghosts only the pure one.
- Otherwise every pure-removal span is ghosted whatever the user event — `delete.backward`, `delete.forward`, `delete.selection`, `delete.cut`, `delete.line`, `undo`, `redo`, `move.drop`'s removal, or none at all (a host `applyEdit`/vim `x`/`dd`) — **unless** the change is a large operation: the total removed characters across the eligible spans, or the total `lines`, is large by `isFluidLargeOperation(chars, lines)` from `editor/src/lib/fluid.ts`, in which case the list is empty (no effect at all, Req 14). Exactly 2,000 characters or exactly 50 lines still animates (strictly-greater, U1284). No new threshold constants are introduced.
- The editor consults this function only when the mode is on and the deletion mapping is `fade`, `pop` or `burst`; with `deletion=none` no per-transaction work beyond the branch happens.

### The ghost (PRD 025 Reqs 7, 8, 12, 15, 17, 20)

- **Why a re-render, not a capture.** The update listener runs after the transaction; the removed text is gone from the DOM, and CodeMirror throws `Reading the editor layout isn't allowed during an update` on any `coordsAtPos` from a `ViewPlugin.update`, so nothing can be measured before the change without intercepting dispatch (forbidden by Req 9). The ghost is therefore a re-render: an element carrying the removed text (`startState.doc.sliceString(fromA, toA)`, set via `textContent`, never HTML) placed where that text was last painted. Markdown styling of the removed text (heading size, bold, code tint) is not reproduced; the ghost uses the content's base font and the theme's foreground. That is the accepted reading of "snapshot" for this increment.
- A pure, exported function (same module) turns the measured start of the removal into the ghost's box: given `{ start: FluidPosCoords, contentLeft, contentRight }` (the `view.coordsAtPos(fromB)` box and one `contentDOM.getBoundingClientRect()` read, both translated into the overlay frame exactly as `selectionChanged` does) it returns `{ left: contentLeft, top: start.top, width: contentRight - contentLeft, indent: start.left - contentLeft, lineHeight: start.bottom - start.top }`. The ghost is positioned at `left/top`, sized to the content width, given `text-indent: <indent>px` so its first line starts where the removed text started and later lines fall back to the content's left edge, `white-space: pre-wrap` (the editor runs `EditorView.lineWrapping`) and an inline `line-height` of `lineHeight` so multi-line removals land line-for-line. If `coordsAtPos(fromB)` returns `null` (not rendered / off-screen) that span draws nothing.
- The ghost is a `div` inside the existing `fluid-overlay` layer with class `fluid-deletion-ghost` and `data-testid="fluid-deletion-ghost"`, styled in `editor/styles.css` beside the caret and selection ghost rules: `position: absolute`, `pointer-events: none`, `font-family: var(--mm-font-mono, monospace)` (the same rule `.cm-content` uses; size inherits from the scroller), `color: var(--mm-fg, …)`, `will-change: transform, opacity`. Themes gain no new tokens. One ghost per eligible span (a multi-cursor Backspace draws one per cursor); the large-operation rule bounds the total text.
- **Fade** animates the ghost's opacity from 1 to 0 over `FLUID_DURATIONS_MS.fade`. **Pop** animates `transform: scale(1)` → `scale(0.8)` together with opacity 1 → 0 over `FLUID_DURATIONS_MS.pop`, with `transform-origin` fixed inside the removed span (its start, or its first line's centre). **Burst** fades the text ghost as Fade does and additionally spawns `FLUID_BURST_PARTICLES` (a new exported constant in `fluid.ts` or the new module, between 6 and 12) particle `div`s (class `fluid-burst-particle`, `data-testid="fluid-burst-particle"`, ~3–4 px, `--mm-accent` or `--mm-fg`) that each translate outward along their own vector while fading 1 → 0 over `FLUID_DURATIONS_MS.burst` (380 ms, within Req 8's 400 ms). All three are driven by the Web Animations API (`element.animate`, ease-out) or a `requestAnimationFrame` loop; no library is added — `dependencies` in `package.json` and `editor/package.json` and `THIRD-PARTY-NOTICES.md` are unchanged. Burst is offered for deletion only; the applicability table is unchanged.
- **Particle geometry is pure.** A pure, exported function (same module) `fluidBurstParticles(box: FluidRect, count: number)` returns `count` particles `{ x, y, dx, dy }` with origins spread along `box` (a zero-width box yields all origins at that point) and displacement vectors that are deterministic from the index (no `Math.random`), non-zero, not all parallel, and no longer than a named constant (e.g. `FLUID_BURST_DISTANCE_PX`, 12–32 px). The editor passes the removed text's first painted line as `box`: the first client rect of a `Range` over the ghost's text node (one layout read of an overlay element, not of content), translated into the overlay frame, falling back to a zero-width box at the removal point when no rect exists.
- The in-flight registry gains one entry per ghost holding the text element and its particles; `stop` cancels every animation, `finish` runs when the longest one finishes (Burst: the particles), and every element is removed the moment it finishes. No root class is worn: nothing real needs hiding, and the ghost sits over the caret's true position for no longer than its own duration (Req 17).
- New behaviour carries a citation comment (`// PRD 025 Req <n>: …`) per `.sandcastle/CODING_STANDARDS.md`; no `console.*` in `editor/src/`.

### Never-delay (PRD 025 Req 9)

- The effect is scheduled from the same `EditorView.updateListener` `fluidExtension` already installs (`editor/src/components/fluidView.ts`), after the transaction is applied: `update.state.doc` already lacks the removed text when the ghost is created. Nothing calls `preventDefault`, wraps `dispatch`, adds a `transactionFilter`/`transactionExtender`, intercepts a key, `beforeinput` or `cut` event, debounces, batches or defers a document change or a selection update.
- The only synchronous work added per deletion is: the span decision, one `coordsAtPos` and one content-rect read per ghost (plus one overlay-rect read for Burst), creating and appending the ghost (and particles), and starting the animations. No `MutationObserver` on the content DOM, no `getComputedStyle` of content.
- The listener's existing guard `if (!u.selectionSet) return` must not skip deletions that set no selection (a host `applyEdit` removal); route on `u.docChanged` for the deletion branch.

### Coexistence with the other effects (PRD 025 Reqs 10, 11, 15)

- `FluidOverlay.update()` still cancels everything on `docChanged || geometryChanged`, so a rapid run of Backspaces shows only the latest character's ghost, each keystroke replacing the last — that is Req 15 as already implemented, not a new rule.
- Within one update the deletion branch runs **after** `caretResult` / `selectionChanged`, and the caret and selection effects' own "replace the one in flight" cancels (`cursorMoved`'s `cancelAll`, `selectionChanged`'s caret-ghost cancel) are narrowed to caret and selection ghosts, so: an undo that removes text and lands the caret shows both the caret ghost and the deletion ghost; a navigation move or Shift+arrow while a deletion ghost is fading leaves it to finish. Only the Req 15 triggers (scroll, `geometryChanged`, `docChanged`, `themeVariant` change, mapping change / mode off, view destroyed) and reduced motion / the large-operation rule remove a deletion ghost early. With `fluid` `null`/absent nothing changes from #333–#335: no extension, listener, timer or overlay element (E577/E580/E582 keep passing).
- A caret move caused by a deletion is still never animated (`isFluidNavigationMove` is unchanged, Req 10).

### Reduced motion (PRD 025 Req 16)

- The existing `prefersReducedMotion()` read (at scheduling time, never cached) gates the deletion effect exactly as it gates the other two: when it matches, no ghost or particle element is created and no animation or frame is scheduled. The layer and `data-fluid` attribute remain; the Settings row, page and pickers stay editable.

### Documentation (PRD 025 Req 19)

- The **Fluid mode** section of `editor/README.md` gains a short **Deletion** paragraph after the selection one: which changes animate (any pure removal, whatever caused it), that a replacement such as typing over a selection never does, that the ghost is a re-rendered copy of the removed text at its last painted position, what Fade, Pop and Burst look like with their durations, the large-operation rule by name of the two constants, and the names of the pure decision/geometry functions. No second section is added.

### Tests (PRD 025 Reqs 21–23)

- Unit tests in a new `editor/tests/fluid-deletion.test.ts`, IDs continuing from the next unused `U` number (U1296 at spec time; check with `grep -rhoE 'U[0-9]+:' tests editor/tests | sort -t U -k2 -n | tail -1`), cover: the span decision's animate cases (`delete.backward`, `delete.forward`, `delete.selection`, `delete.cut`, `undo`, `redo`, a null user event; a multi-line removal; two pure-removal spans both returned); its no-effect cases (`docChanged` false; insertion-only spans; a replacement span; a transaction mixing a replacement and a pure removal returning only the pure one); the large-operation cases (removing more than 2,000 characters; more than 50 lines; two spans that only together exceed a threshold; exactly 2,000 characters and exactly 50 lines still returned); the ghost box (indent = start.left − contentLeft, width = content width, lineHeight = bottom − top, indent 0 when the removal starts at the content's left edge); the burst particles (exact count, origins within the box, a zero-width box, displacement lengths within the constant and non-zero, not all vectors parallel, deterministic across two calls); and that `FLUID_DURATIONS_MS.burst` ≤ 400 and `FLUID_BURST_PARTICLES` is within 6–12. Plain numbers only: no timers, fake timers, `requestAnimationFrame` or DOM.
- One e2e test, ID the next unused `E` number (E583 at spec time), next to E582 in `tests/e2e/settings-and-themes.spec.ts`: enables the switch with the default mapping (Deletion → Fade) via `openSettings(page, 'experimental')` + `saveSettings`; then asserts only negatives that need no animation observation, reading counts of `page.getByTestId('fluid-deletion-ghost')` and `fluid-burst-particle` (and the layer's child count where the whole layer must be empty) — (a) under `page.emulateMedia({ reducedMotion: 'reduce' })`, after clicking the content, Control+End and Backspace, the layer has zero children and `data-fluid` is intact; (b) back on `'no-preference'`, after Control+Home, Home, Shift+End and pressing `Q`, the first line's text is exactly `Q` and there is no deletion ghost (a replacement never draws one); after pressing `Z` there is still none (an insertion is not a deletion); after Backspace the first line's text is exactly `Q` immediately (the deletion is real and synchronous) — with no assertion about the ghost that may now be fading; (c) the large-operation rule: after Control+End and enough Enter presses to take `fixtures/welcome.md` (45 lines, 1,649 characters at spec time) past 50 lines, Control+A then Backspace leaves the content with a single empty line and zero children; (d) after re-saving with Deletion → Burst and reduced motion on again, Backspace draws neither a ghost nor a particle (zero children); (e) after re-saving with Deletion → None (motion allowed), typing a character then Backspace leaves zero children and the layer still has count 1. It never waits for, measures or screenshots an animation and uses no `waitForTimeout`.
- **One permitted amendment to an existing test.** E580's Backspace step (`tests/e2e/settings-and-themes.spec.ts` ~L992–995, "Deleting is not a navigation move either") asserts the layer has zero children, which a Fade ghost now makes false. Its assertion is narrowed to `page.getByTestId('fluid-caret-ghost')` having count 0 — the caret-effect claim it was always making — with its ID, title, and every other step unchanged. No other existing test or test ID is changed, renamed, weakened or skipped. The rest of the e2e suite runs with the switch off and is unaffected.
