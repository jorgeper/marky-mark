# Spec: Standalone bundle, hello-editor sample, independence check, and editor/README.md (#240)

## Goal

All acceptance criteria in issue-specs/issue-240.md are satisfied for issue #240, with evidence visible in the session: the `@marky-mark/editor` build additionally emits a self-contained standalone browser bundle (React included, no externals) with a tiny imperative mount API; `editor/samples/hello-editor/index.html` mounts the editor+preview from that bundle with starter markdown and works by just building the package once and opening the file (no npm install, no build step, no network); an automated check proves the sample mounts and accepts input with no Marky Mark app code involved; `editor/README.md` documents the package for an outside web developer; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #240.

## Acceptance criteria

- **Standalone bundle (PRD 021 Req 14).** The editor package build emits, in addition to the existing externals-only ESM library (`editor/vite.config.ts`), one self-contained browser bundle with React and every runtime dependency included (no externals, no bare imports at runtime) plus a tiny imperative mount API (e.g. a function taking a DOM element and options such as initial markdown). The bundle is produced by a package script (extend `editor/package.json` `scripts` — e.g. the existing `build` or a new `build:standalone` run via `npm run <script> -w editor`), and building it does not change what the library build emits for React consumers.
- **hello-editor sample (PRD 021 Req 15).** `editor/samples/hello-editor/index.html` exists: one HTML file plus at most a few lines of inline script that mounts the editor+preview from the standalone bundle with starter markdown. The flow is: build the package once, open the file, it works — no npm install for the consumer, no build step for the sample, no network. Note the `file://` constraint: Chromium blocks `<script type="module" src=…>` cross-file loads from `file://` URLs, so a classic-script (IIFE/UMD) bundle — or an equivalent arrangement that demonstrably opens from disk — is what makes "open the file" literally true. Any CSS the sample needs (package `styles.css` / `default-theme.css` or CSS inlined into the bundle) loads the same way.
- **Independence check (PRD 021 Req 16).** An automated check in the unit or e2e tier — with a test ID on the repo-wide register (`U<n>` for `editor/tests/`, `E<n>` for `tests/e2e/`; the test-ID uniqueness scan in `scripts/validate.mjs` covers both) — loads hello-editor against the built standalone bundle and asserts the editor mounts and accepts typed input, with no Marky Mark app code (`src/`, `server/`, `src-tauri/`) involved. The check runs as part of `npm run validate:quick` and passes from a clean checkout: whatever tier it lives in must arrange for the standalone bundle to exist when it runs (build it in setup, or wire the build into the gate) rather than assuming a stale `dist/`.
- **editor/README.md (PRD 021 Req 13).** Written for an outside web developer, it covers: what the component is; a quickstart that *is* the hello-editor sample; the full props/seams/handles API (`Editor`/`EditorProps`, `Preview`/`PreviewProps`, `SplitView`/`SplitViewProps`, the imperative handles `EditorSyncHandle`/`SmartEditHandle`/`EditorSearchHandle`, and the seam types — all exported from `editor/src/index.ts`); the `--mm-*` theming contract (may summarize and link `editor/THEMING.md`); the decoration hook; how to run tests and build (`npm test -w editor`, `npm run typecheck -w editor`, the build script(s)); and the boundary statement — what this package deliberately does not do (per `editor/AGENTS.md`: no file access, app settings, comment overlays, theme collection; app-flavored needs arrive through seams).
- **Boundary intact.** The editor-package-boundary gate still passes: nothing under `editor/` (including the sample, standalone entry, and any new tests/config) imports app code, and any root-side test infra touches the package only through built artifacts or declared entry points.
- **Gate.** `npm run validate:quick` has been run once in the implementer's session, right before declaring the goal met, and prints `QUICK VALIDATION: ALL PASSED`. Iterate with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code, e.g. `npm test -w editor` / `npx playwright test -g '<title>'`) — do not re-run the full gate after every small change, and baseline an attempt with the quick pair only.
- **Issue comment.** A summary comment from the implementer exists on issue #240 describing what was done and the verification evidence.

## Context

This is the final packaging slice of PRD 021 (`prd/021-embeddable-editor.md`, Reqs 13–16); parent #224, previously blocked by #238 (now merged). The package lives in `editor/` (workspace `@marky-mark/editor`): public API in `editor/src/index.ts`, library build in `editor/vite.config.ts` (ESM, everything external — the standalone bundle is a second, opposite build), styling contract in `editor/styles.css` + `editor/default-theme.css` + `editor/THEMING.md`, directives in `editor/AGENTS.md`. Package tests (`editor/tests/`, `U<n>` IDs, happy-dom available) run via `npm test -w editor`; root e2e suites live in `tests/e2e/` (`E<n>` IDs, Playwright). The mount API needs `react` + `react-dom/client` bundled in — both are already devDependencies of the package. New behaviour should carry citation comments (existing package code cites `PRD 021 Req <n> (issue #<n>)`); if spec-numbered citations change, `npm run map` regenerates `docs/MAP.md` (the gate diffs it).
