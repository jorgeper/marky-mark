# Spec: Hosted e2e coverage for the scratch fresh-buffer flow (#293)

## Goal

All acceptance criteria in issue-specs/issue-293.md are satisfied for issue #293, with evidence visible in the session: the hosted suite covers every leg of PRD 023 Req 13 — including the previously untested presentation half (browser tab title, the accent/italic `.scratch-name` treatment on toolbar and file tab, and the Req 8 scoping) — no test asserts the retired heading-derived pre-fill, `docs/MAP.md` is regenerated by `npm run map`, `npm run validate:quick` has been run in the implementer's session and passes, and a summary comment from the implementer exists on issue #293.

## Acceptance criteria

- The hosted suite (`tests/e2e/hosted.spec.ts`, run by `npm run test:e2e` against the local hosted server) covers every leg PRD 023 Req 13 lists, each leg traceable to a named E-numbered test:
  - bare `/<username>/scratch` boots fresh on first visit **and** on reload (Req 1);
  - `/<username>/scratch/<path>` opens the file and boots no scratch buffer (Req 2);
  - the Open Workspace "My scratch" row boots fresh (Req 3);
  - re-entry over a **dirty** scratch buffer replaces it with no prompt and no `beforeunload` dialog (Req 4);
  - "Scratch file" in the toolbar name, the file tab and the browser tab title, in the accent/italic treatment, with the usual dirty dot (Reqs 6–7);
  - a non-boot buffer inside the scratch workspace is **not** scratch-labelled or scratch-styled (Req 8);
  - Save opens the picker pre-filled with a free `Untitled.md` at the scratch root, Cancel keeps the buffer, an empty buffer still asks, and the saved file behaves as an ordinary workspace file (Reqs 9–12).
- Legs already asserted by the merged slices (E397, E398, E399, E433, E434 from #290/#291/#292) count as covered and are **not** duplicated; the implementer's comment names which test covers which leg, so a reader can check the mapping without re-reading the suite.
- The gaps those tests leave are closed by new hosted tests, at minimum:
  - the **browser tab title** reads "Scratch file" while the scratch buffer is focused (nothing in `tests/e2e/` asserts `document.title` for it today), and reverts to the file's real name once saved (Req 12);
  - the **accent/italic treatment** is asserted on the rendered chrome, not just the label text: the toolbar name (`Toolbar.tsx`'s `span.scratch-name[data-scratch]`) and the file-tab label (`FileTabStrip.tsx`'s `.file-tab-label.scratch-name`) resolve to `font-style: italic` and the theme accent colour via the `--mm-scratch-name` / `--mm-scratch-name-style` tokens — computed-style assertions in the style of `tests/e2e/file-tabs.spec.ts`;
  - **Req 8 scoping**: inside the scratch workspace, a buffer that is not the boot's scratch buffer carries neither the "Scratch file" label nor the `.scratch-name` treatment. Hosted has no ⌘N untitled route (`beginNewFile` in `src/App.tsx` routes to the in-workspace picker when the platform has no `saveFileDialog`), so assert this through the route hosted actually offers and say so in the test comment; the pure ⌘N-buffer branch stays pinned by U1125 in `tests/unit/doc-name.test.ts`.
- No test in `tests/` asserts the retired heading-/first-line-/timestamp-derived save pre-fill (PRD 019 Req 12, replaced by PRD 023 Req 9). If the audit finds none left, that is a satisfied criterion, not a reason to add one — say so in the summary comment.
- New tests follow the repo's conventions: title starts with a repo-unique `E<n>:` id taken from the next unused number (E445 is the highest in `tests/e2e/` today; the `test-ID uniqueness` gate in `scripts/validate.mjs` is the arbiter after a parallel merge), and each carries a citation comment naming the contract it covers (`.sandcastle/CODING_STANDARDS.md`).
- `docs/MAP.md` is regenerated with `npm run map` and committed — never hand-edited — so it matches what the generator derives from the tree (the freshness check runs in the quick tier).
- Iteration uses the cheap loop: `npm run typecheck`, `npm run test:unit`, and single hosted tests via `npx playwright test -g '<title>'`. The full gate is **not** used as a baseline and not re-run after every edit.
- `npm run validate:quick` has been run **once**, at the end, in the implementer's session, and prints `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #293: what was added, the leg→test mapping, and the gate evidence.
