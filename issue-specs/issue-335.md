# Spec: Fluid mode (3/5): selection change effects (Glide, Elastic) and the large-operation snap (#335)

## Goal

All acceptance criteria in issue-specs/issue-335.md are satisfied for issue #335, with evidence visible in the session: with the Fluid mode switch on and Selection change mapped to Glide or Elastic, a selection-only transaction that leaves a non-empty main range (Shift+arrow/Home/End, select-all, a mouse drag's `select.pointer` steps, a host `selectRange`, a find-hit, undo/redo restoring a range) draws ghost selection rectangles in the existing `fluid-overlay` layer that tween from the previous painted shape toward the new range, and a further selection change while one is in flight re-targets the running ghost from its current geometry (so a drag's target follows the pointer) rather than restarting or waiting; a selection change whose previous or new main range spans more than `FLUID_LARGE_OPERATION_CHARS` or `FLUID_LARGE_OPERATION_LINES` snaps (no ghost, any in-flight ghost cancelled), decided by the exported `isFluidLargeOperation`; the real selection and document change synchronously exactly as with the mode off, the ghost never enters the content DOM, is cancelled and removed immediately on scroll, resize, document change, theme-variant change or the mode turning off, and is removed the moment it finishes; under `prefers-reduced-motion: reduce` no ghost is created; the selection-change decision and the rectangle geometry are pure, unit-tested functions in the editor package; one e2e test proves the negatives (reduced motion, typing over a selection, the large-operation snap, Selection change → None) without any time-based wait; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #335.

## Acceptance criteria

### The selection-change decision (PRD 025 Reqs 11, 14)

- A pure, exported function in the editor package (a new `editor/src/lib/fluidSelection.ts`, re-exported from `editor/src/index.ts` like `fluidCursor.ts`) decides what a transaction does to the painted selection. It takes a plain descriptor, not a `Transaction` — e.g. `{ docChanged; selectionSet; userEvent: string | null; from: { anchor; head }; to: { anchor; head }; fromLines; toLines }` where `from` is the old main range already mapped through the transaction's changes and `fromLines` / `toLines` are the number of document lines each range touches (`lineAt(to).number - lineAt(from).number + 1`, or `1` for a caret) — and returns one of `'animate' | 'snap' | 'none'`.
- `'none'` when: `selectionSet` is false; the resulting main range is empty (a caret result belongs to the cursor effect of #334, so one transaction never triggers both effects); anchor and head are both unchanged; or the transaction is `docChanged` with a user event other than `undo` / `redo` (typing over a selection, `delete.selection`, paste, completions, smart-edit / table-edit rewrites never animate the selection).
- Otherwise `'snap'` when the larger of the two ranges is a large operation — `isFluidLargeOperation(chars, lines)` from `editor/src/lib/fluid.ts` is `true` for either the previous range (`|from.head - from.anchor|`, `fromLines`) or the new one — and `'animate'` otherwise. Exactly 2,000 characters or exactly 50 lines still animates (the predicate is strictly-greater, U1284). No new threshold constants are introduced; the two exported in #333 are the only numbers.
- `'animate'` covers a selection-only transaction whatever its user event (`select` for Shift+arrow/Home/End and select-all, `select.pointer` for a click-drag step or shift-click, none for a host `selectRange` range, a find-hit selecting its match, vim visual moves) and a `docChanged` `undo` / `redo` that lands a range.
- The editor consults this function only when the mode is on and the selection mapping is `glide` or `elastic`; with `selection=none` no per-transaction work beyond the branch happens. Only the main range is animated; secondary ranges (multi-cursor) always snap.

### The ghost and its geometry (PRD 025 Reqs 7, 8, 11, 20)

- A pure, exported function (same module) turns a range's measured coordinates into at most three rectangles in the overlay's frame — the first line's tail, the full-width middle block, the last line's head; a single-line range yields one; a caret (the `from` side of a caret→range change) yields a zero-width rectangle at the caret — so the shape can be unit-tested with plain numbers. Coordinates come from `view.coordsAtPos` (both ends of both ranges) and one `contentDOM.getBoundingClientRect()` read for the left/right edges, translated by the layer's own rect exactly as the caret ghost does. If any needed position has no coordinates (not rendered / off-screen), the change snaps: no ghost is drawn and any in-flight selection ghost is cancelled.
- The ghost is a fixed set of `div`s (one per rectangle slot, so a 1-rect shape tweens into a 3-rect shape element-to-element) inside the existing `fluid-overlay` layer, each carrying `data-testid="fluid-selection-ghost"`, class `fluid-selection-ghost`, coloured with the theme's existing `--mm-selection` token (translucent, so text under it stays legible; themes gain no new tokens). The tween interpolates each rectangle's left/top/width/height from the previous shape to the new one with the curves already exported by #334: **Glide** uses `glideAt` over `FLUID_DURATIONS_MS.glide`; **Elastic** uses `elasticAt` over `FLUID_DURATIONS_MS.elastic` (the overshoot reads as the rubber band stretching past the new end and settling). The driver is a `requestAnimationFrame` loop sampling the curve or the Web Animations API; no library is added — `dependencies` in `package.json` and `editor/package.json` and `THIRD-PARTY-NOTICES.md` are unchanged.
- **Re-targeting (Req 11).** A second `'animate'` change while a selection ghost is in flight does not remove the ghost or restart it from the pre-drag shape: the ghost's *current* interpolated geometry (the curve sampled at the elapsed fraction) becomes the new start and the new range becomes the target, restarting the clock. During a mouse drag CodeMirror dispatches one `select.pointer` transaction per pointer move, so this rule is what makes the target follow the pointer continuously; nothing listens to pointer events directly, and nothing waits for `mouseup`. At most one selection ghost exists at a time.
- While a selection ghost is in flight the editor root wears a class (e.g. `fluid-selection-in-flight`) whose only rule hides `.cm-selectionBackground` (CSS `visibility`, no layout), mirroring `fluid-caret-in-flight`; every finish and cancel path removes it, so the real painted selection is never hidden for longer than the effect's duration (Req 17). The SPEC23 `.mm-code-sel` re-tint inside code constructs may be left visible.
- A caret result while a selection ghost is in flight (click, arrow, Escape) cancels the selection ghost immediately, then the cursor effect proceeds as #334 defines; a range result cancels any caret ghost in flight. New behaviour carries a citation comment (`// PRD 025 Req <n>: …`) per `.sandcastle/CODING_STANDARDS.md`; no `console.*` in `editor/src/`.

### Never-delay (PRD 025 Req 9)

- The effect is scheduled from the same `EditorView.updateListener` path `fluidExtension` already installs (`editor/src/components/fluidView.ts`), after the transaction is applied: `update.state.selection` already equals the final selection when the ghost is created or re-targeted. Nothing calls `preventDefault`, wraps `dispatch`, intercepts the pointer or a keymap, debounces, batches or defers a selection update or a document change.
- The only synchronous work added per selection change is: the decision, the `coordsAtPos` reads and one content-rect read, creating or re-targeting the ghost elements, and starting the frame/animation. No `MutationObserver` on the content DOM, no `getComputedStyle` of content.

### The overlay rules (PRD 025 Reqs 3, 15, 17)

- Everything lives in the existing `FluidOverlay` plugin and its in-flight registry: the selection ghost is appended only inside `fluid-overlay` (never `.cm-content`, `.cm-line`, `.cm-selectionLayer` or any CodeMirror-managed element), is absolutely positioned and `pointer-events: none`, inherits the layer's `aria-hidden`, and never resizes or reflows the content DOM. With `fluid` `null`/absent nothing changes from #333/#334: no extension, listener, timer or overlay element (E577/E580 keep passing).
- A selection ghost in flight is **cancelled and removed immediately** through the existing `cancelAll` path on: a `scroll` on `view.scrollDOM`; `update.geometryChanged`; any `docChanged` update; a `themeVariant` prop change; the mapping changing or the mode turning off; the view being destroyed — plus the two new triggers above (`'snap'`, and a caret result). The `fluid-overlay` layer has zero children whenever no effect is in flight, and every ghost element is removed the moment its animation finishes.

### Reduced motion (PRD 025 Req 16)

- The existing `prefersReducedMotion()` read (at scheduling time, never cached) gates the selection effect exactly as it gates the caret ghost: when it matches, no element is created, no frame or animation is scheduled, and the listener returns. The layer and `data-fluid` attribute remain; the Settings row, page and pickers stay editable.

### Documentation (PRD 025 Req 19)

- The **Fluid mode** section of `editor/README.md` gains a short **Selection change** paragraph after the cursor one: which changes animate (any change that leaves a range, including each step of a drag, which re-targets the running ghost), what Glide and Elastic look like on a selection, that a caret result is the cursor effect's territory, and the large-operation snap by name of the two constants. No second section is added.

### Tests (PRD 025 Reqs 21–23)

- Unit tests in a new `editor/tests/fluid-selection.test.ts`, IDs continuing from the next unused `U` number (U1292 at spec time; check with `grep -rhoE 'U[0-9]+:' tests editor/tests | sort -t U -k2 -n | tail -1`), cover: the decision's `'animate'` cases (`select`, `select.pointer`, absent user event, `undo`, `redo` landing a range, caret→range, range→range); its `'none'` cases (no `selectionSet`, caret result, unchanged anchor+head, `input.type`, `delete.selection`, `input.paste`); its `'snap'` cases (new range over 2,000 chars, new range over 50 lines, previous range large with a small new one, and exactly 2,000 chars / exactly 50 lines animating); and the rectangle geometry (single-line → one rect; multi-line → three; caret → one zero-width rect; the middle block spans the content edges). Plain numbers only: no timers, fake timers, `requestAnimationFrame` or DOM.
- One e2e test, ID the next unused `E` number (E581 at spec time), next to E580 in `tests/e2e/settings-and-themes.spec.ts`: enables the switch with the default mapping (Selection change → Elastic) via `openSettings(page, 'experimental')` + `saveSettings`; then asserts only negatives that need no animation observation — (a) under `page.emulateMedia({ reducedMotion: 'reduce' })`, after Shift+End and Shift+ArrowDown the layer has zero children and `data-fluid` is intact; (b) back on `'no-preference'`, after Home, Shift+End, then pressing `Q`, the first line's text is exactly `Q` (the selection was real and synchronous: typing replaced it) and the layer has zero children (a document change cancels, typing never animates); (c) the large-operation snap: after Control+End and enough Enter presses to take `fixtures/welcome.md` (45 lines at spec time) past 50 lines, Control+A leaves zero children; (d) after re-saving with Selection change → None, Shift+End leaves zero children and the layer still has count 1. It never waits for, measures or screenshots an animation and uses no `waitForTimeout`.
- No existing test or test ID is changed, renamed, weakened or skipped. The rest of the e2e suite runs with the switch off and is unaffected.

- **How the real selection is painted:** `drawSelection()` (`Editor.tsx` ~L2095, SPEC24 §5) paints `.cm-selectionBackground` divs into `.cm-selectionLayer` behind `.cm-content`; the app's tint is `--mm-selection` (`editor/styles.css` ~L671). The selection ghost sits in `fluid-overlay` (z-index 25, above content) with the same translucent token, so hiding the real one while the ghost flies reads as the selection itself moving. CodeMirror's `select.pointer` user event is set per drag step (`@codemirror/view` `setSelectionOrigin`), so the update listener already fires for every pointer move.
- **Keeping cursor and selection effects apart:** `isFluidNavigationMove` returns `false` for a non-empty result (`toEmpty === false`) precisely so this increment can own range results; route by `u.state.selection.main.empty` in the update listener before calling either effect.
- **Re-targeting hint:** a `requestAnimationFrame` loop that stores `{ start: rect[], target: rect[], startedAt, curve }` and writes each slot's `left/top/width/height` per frame makes re-targeting a matter of replacing `start` with the current sampled geometry and `target` with the new one; WAAPI works too if the implementer reads the current geometry from the curve rather than from `getComputedStyle`. `performance.now()` is fine; no test observes the loop.
- **Boundary:** `editor/AGENTS.md` — nothing under `editor/` imports from `src/`; the editor-package-boundary check in `scripts/validate.mjs` enforces it. Reduced motion stays in-package via `matchMedia`.
- **Conventions:** `.sandcastle/CODING_STANDARDS.md` (citation comments, stable `U<n>`/`E<n>` IDs, `getByTestId` first). IDs top out at E580 / U1291 at spec time.
