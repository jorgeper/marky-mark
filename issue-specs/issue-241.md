# Spec: Behavior preservation: full-gate verification of Marky Mark on the packaged editor (#241)

## Goal

All acceptance criteria in issue-specs/issue-241.md are satisfied for issue #241, with evidence visible in the session: every full-gate step runnable in the sandbox passes on the app consuming the packaged editor — `npm run validate:quick` prints `QUICK VALIDATION: ALL PASSED`, and `npm run build:web`, `npm run test:e2e:web`, and `npm run build` each exit 0 (together, `npm run validate` minus the sandbox-unavailable `cargo check`); any regressions those steps uncover are fixed without weakening tests; and a summary comment from the implementer exists on issue #241.

## Acceptance criteria

- **Full-gate steps pass on the packaged editor (PRD 021 Req 17).** With the app consuming `@marky-mark/editor` (the state of this branch after #237–#240), the following have been run in the implementer's session and pass:
  - `npm run validate:quick` prints `QUICK VALIDATION: ALL PASSED` — this covers the gate's pre-step scans (version lock-step, MAP.md, CLAUDE.md link, test-ID uniqueness, style lint, editor package boundary, e2e test-count floor), typecheck, unit tests, and the entire desktop-shim e2e tier, which includes the suites Req 17 names (editor, split-view, tables, live-preview, smart-edit, images, mermaid, search, toc).
  - `npm run build:web` exits 0 (the single-file web build produces a working artifact), then `npm run test:e2e:web` exits 0 (the web e2e suite runs against `dist-web`, so the build must come first).
  - `npm run build` exits 0 (the desktop bundle build).
  These four commands are exactly the full gate's step list in `scripts/validate.mjs` minus `cargo check`.
- **`cargo check` disposition.** The sandbox has no Rust toolchain by design (`.sandcastle/Dockerfile` records that the one flow needing the full gate's Rust step runs in the owner's session via `/cut-release`). The implementer does not attempt to install Rust and does not claim `npm run validate` passed end-to-end; the summary comment states explicitly that the `cargo check` step is deferred to the owner's release flow.
- **Regressions fixed, tests unweakened.** Any failure the steps above uncover is fixed on this branch, in app or editor-package code — not by adjusting tests. The existing e2e suites pass unmodified except for mechanical import-path updates; the branch diff shows no test deleted, skipped, or with loosened assertions relative to the baseline. If everything already passes, that is a valid outcome: this issue's deliverable is the verification evidence plus any fixes it forced.
- **No behavioral or visual deltas.** The e2e suites are the proxy for "no visual or behavioral differences in the editor, preview, or split view". If the implementer notices a genuine difference the suites don't cover, the behavior is fixed rather than the expectation changed, and the summary comment records it.
- **Test economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code — `npx playwright test -g '<title>'`, and `npm run test:e2e:failed` to re-run only just-failed e2e tests) and runs the gate commands above ONCE, right before declaring the goal met — not after every small change, and not as a baseline at the start of an attempt (baseline with the quick tier only). The e2e tiers are serialized machine-wide; don't interleave them with other work.
- **Issue comment.** A summary comment from the implementer exists on issue #241 reporting the outcome of each gate command, any regressions found and how they were fixed (or that none were found), and the `cargo check` deferral note.

## Context

This is the closing verification slice of PRD 021 (`prd/021-embeddable-editor.md`, Req 17 under "Behavior preservation"); parent #224. Its blockers #237–#240 (workspace conversion, package API, standalone bundle, boundary scan) are already merged into this branch, so the app already consumes `@marky-mark/editor` — the work here is running the widest runnable gate against that state and fixing whatever it surfaces. The full gate's step list lives in `scripts/validate.mjs` (`steps` array, ~line 392); the quick tier is its first three steps plus the pre-step scans. `cargo check` is the only full-gate step that cannot run in the sandbox (no Rust — see the comment at `.sandcastle/Dockerfile:40`), which is why the criteria enumerate the other steps individually instead of requiring `npm run validate` to exit 0. E2e suites live in `tests/e2e/` (Playwright, `E<n>` IDs); the web config is `playwright.web.config.ts`. If any fix touches spec-cited behavior, keep citation comments accurate and regenerate `docs/MAP.md` with `npm run map` (the gate diffs it).
