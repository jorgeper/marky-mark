# Spec: Fluid mode (5/5): insertion effects (Fade, Pop) scoped to the inserted range (#337)

## Goal

All acceptance criteria in issue-specs/issue-337.md are satisfied for issue #337, with evidence visible in the session: with the Fluid mode switch on and Insertion mapped to Fade or Pop, every document change that inserts text (typing, paste, undo/redo, smart-edit and table-edit rewrites, typing or pasting over a selection) draws, in the existing `fluid-overlay` layer and scoped to the inserted range only, a page-coloured mask over the inserted text's painted rectangles, which Fade dissolves so the real text appears to fade in, and which Pop holds while a re-rendered copy of the inserted text scales in from ~0.8 on top, after which every element is removed; a change inserting or removing more than `FLUID_LARGE_OPERATION_CHARS` characters or `FLUID_LARGE_OPERATION_LINES` lines, a pure removal, or an IME composition step draws nothing; the insertion itself is never deferred and the caret keeps pace with typing; nothing enters the content DOM and every element is cancelled and removed at once on scroll, resize, a further document change, theme-variant change or the mode turning off; under `prefers-reduced-motion: reduce` no element is created; the span decision is a pure, unit-tested function in the editor package; one e2e test proves the negatives without any time-based wait, with E580's and E582's typing steps narrowed to their own ghost kinds; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #337.

## Acceptance criteria

### Which insertions animate (PRD 025 Reqs 13, 14)

- A pure, exported function in the editor package (a new `editor/src/lib/fluidInsertion.ts`, re-exported from `editor/src/index.ts` like `fluidDeletion.ts`) decides which inserted spans of one applied transaction get an effect. It takes a plain descriptor, not a `Transaction` — e.g. `{ docChanged; userEvent: string | null; spans: Array<{ fromB; toB; removedLength; removedLines; insertedLines }> }` where `spans` is what `update.changes.iterChanges` yields (one entry per changed range; `insertedLines` = new-document lines the inserted range touches, `state.doc.lineAt(toB).number - state.doc.lineAt(fromB).number + 1`; `removedLines` = start-document lines the removed range touched, as `fluidDeletionSpans` already receives) — and returns the spans to animate (an empty list meaning no effect).
- It returns nothing when `docChanged` is false or no span inserts text (`toB === fromB` for all of them: Backspace, Delete, cut, delete-line, a removal-only undo/redo).
- A span that inserts text is animated whether or not it also removed text (`removedLength > 0`): typing or pasting over a selection, completions, smart-edit and table-edit rewrites are insertions of their new text (this is the replacement seam #336 left to this increment). Whatever the user event — `input.type`, `input.paste`, `input.drop`, `undo`, `redo`, or none (a host `applyEdit`, vim `p`) — every inserting span is returned, **except** that a transaction whose user event is `input.type.compose` (an IME composition step, whose text is still being decided and must stay readable) returns nothing.
- The **large-operation rule** (Req 14, "a single change *touching* more than…") is applied to the whole change: the total inserted characters across the eligible spans, or the total `insertedLines`, **or** the total `removedLength`, or the total `removedLines`, being large by `isFluidLargeOperation(chars, lines)` from `editor/src/lib/fluid.ts` empties the list — so select-all + type replaces a 50+-line document with one character and draws nothing. Exactly 2,000 characters or exactly 50 lines still animates (strictly greater). No new threshold constants are introduced.
- The editor consults this function only when the mode is on and the insertion mapping is `fade` or `pop`; with `insertion=none` no per-transaction work beyond the branch happens. A transaction mixing a pure-removal span and an inserting span (multi-cursor, a drop) gives the deletion branch its ghost and the insertion branch its mask; each decision sees only its own spans.

### The effect (PRD 025 Reqs 7, 8, 13, 15, 17, 20)

- **Why a mask, not a re-render alone.** After the update the inserted text is already painted in `.cm-content`, and Req 15 forbids inserting into or restyling the content DOM (no mark decoration, no per-range class). So the inserted range is *covered*: one or more `div`s with class `fluid-insertion-mask` and `data-testid="fluid-insertion-mask"`, background `var(--mm-bg, #ffffff)` (the same variable `.editor-wrap .cm-editor` paints its background with; themes gain no new tokens), positioned over the inserted range's painted rectangles. The rectangles are the existing pure geometry `fluidSelectionRects({ start, end, contentLeft, contentRight })` from `fluidSelection.ts` with `start = coordsAtPos(fromB)`, `end = coordsAtPos(toB)` and one `contentDOM.getBoundingClientRect()` read, all translated into the overlay frame exactly as `selectionChanged` and `deletionChanged` do — one mask element per rectangle (a single-line insertion is one rectangle; a multi-line paste is up to three). If either `coordsAtPos` returns `null` that span draws nothing. Rectangles with zero width or zero height need no element (a bare Enter draws nothing visible either way). The mask may briefly cover a tinted block (a code card, a table-mode line) with the page colour; that is accepted for this increment.
- **Fade** animates every mask's opacity from 1 to 0 over `FLUID_DURATIONS_MS.fade`, so the real text appears to fade in and is exactly the real, Markdown-styled text when the effect ends. No text is re-rendered for Fade.
- **Pop** holds the masks at full opacity for `FLUID_DURATIONS_MS.pop` and draws, above them, a re-rendered copy of the inserted text: a `div` with class `fluid-insertion-ghost` and `data-testid="fluid-insertion-ghost"`, `textContent` = `u.state.doc.sliceString(fromB, toB)` (never HTML), boxed by the existing pure `fluidDeletionBox({ start, contentLeft, contentRight })` (content-wide block, `text-indent` to the span's start, inline `line-height`, `white-space: pre-wrap`), sharing the deletion ghost's font/colour rules (`var(--mm-font-mono, monospace)`, `var(--mm-fg, …)`) so the two rules may be one selector list in `editor/styles.css`. It animates `opacity 0 → 1` together with `transform: scale(0.8) → scale(1)` over `FLUID_DURATIONS_MS.pop`, `transform-origin` fixed inside the span (its start, on its first line's centre), ease-out. When the ghost's animation finishes, the ghost **and its masks are removed together** so the real text is never uncovered before the copy has settled at scale 1. Markdown styling of the copy is not reproduced (the accepted reading from #336); the hand-off is the moment the ghost and mask vanish.
- All animation is driven by the Web Animations API (`element.animate`) or a `requestAnimationFrame` loop; no library is added — `dependencies` in `package.json` and `editor/package.json` and `THIRD-PARTY-NOTICES.md` are unchanged. Burst is not offered for insertion; the applicability table is unchanged.
- Styles live in `editor/styles.css` beside the deletion-ghost rules: `.fluid-insertion-mask { position: absolute; background: var(--mm-bg, #ffffff); pointer-events: none; will-change: opacity }` and the ghost as above with `will-change: transform, opacity`. Both are children of the existing `fluid-overlay` layer (already `pointer-events: none`, `aria-hidden`, `z-index: 25`); the layer sits over the caret's true position for no longer than the effect's own duration (Req 17), and the mask's right edge is the inserted range's end, where the real caret stands.
- The in-flight registry (`FluidOverlay.inFlight`) gains one entry per animated span with a new `FluidGhostKind` `'insertion'`, holding the masks (and the Pop ghost), `cls: null` (no root class is worn: nothing real needs hiding), `stop` cancelling every animation; `finish` runs when the longest animation ends and `discard` removes every element. `cancelKinds('caret', 'selection')` and `cancelKinds('selection')` do not touch it; `cancelAll` does.
- New behaviour carries a citation comment (`// PRD 025 Req <n>: …`) per `.sandcastle/CODING_STANDARDS.md`; no `console.*` in `editor/src/`.

### Never-delay (PRD 025 Reqs 9, 10)

- The effect is scheduled from the same `EditorView.updateListener` `fluidExtension` installs (`editor/src/components/fluidView.ts`), after the transaction is applied and after the deletion branch: `u.state.doc` already contains the inserted text when the mask is created. Nothing calls `preventDefault`, wraps `dispatch`, adds a `transactionFilter`/`transactionExtender`, intercepts a key, `beforeinput`, `paste` or `input` event, debounces, batches or defers a document change or a selection update.
- The only synchronous work added per insertion is: the span decision, two `coordsAtPos` reads per span and one content-rect read per update (share the one `iterChanges` pass and the one content-rect read with `deletionChanged` rather than iterating twice), creating and appending the mask(s) (and the Pop ghost), and starting the animations. No `MutationObserver` on the content DOM, no `getComputedStyle` of content, no layout read of the overlay beyond the frame rect.
- A caret move caused by an insertion is still never animated (`isFluidNavigationMove` is unchanged): the caret keeps pace with typing. An undo that reinserts text and lands the caret shows both the caret ghost and the insertion effect.

### Coexistence with the other effects (PRD 025 Reqs 11, 12, 15)

- `FluidOverlay.update()` still cancels everything on `docChanged || geometryChanged`, so fast typing shows only the latest character's effect, each keystroke replacing the last — that is Req 15 as already implemented, not a new rule.
- The insertion branch runs **after** `caretResult` / `selectionChanged` and `deletionChanged` within one update; a navigation move or Shift+arrow while an insertion effect is in flight leaves it to finish. Only the Req 15 triggers (scroll, `geometryChanged`, `docChanged`, `themeVariant` change, mapping change / mode off, view destroyed) and reduced motion / the large-operation rule remove it early. With `fluid` `null`/absent nothing changes from #333–#336: no extension, listener, timer or overlay element (E577 keeps passing).
- The deletion decision (`fluidDeletionSpans`) is unchanged: a replacement still never draws a deletion ghost (E586 (b) keeps passing).

### Reduced motion (PRD 025 Req 16)

- The existing `prefersReducedMotion()` read (at scheduling time, never cached) gates the insertion effect exactly as it gates the other three: when it matches, no mask or ghost element is created and no animation or frame is scheduled. The layer and `data-fluid` attribute remain; the Settings row, page and pickers stay editable.

### Documentation (PRD 025 Req 19)

- The **Fluid mode** section of `editor/README.md` gains a short **Insertion** paragraph after the deletion one: which changes animate (every insertion, including a replacement's new text, whatever caused it), that an IME composition step and a pure removal never do, that the effect is a page-coloured mask over the inserted range that Fade dissolves (180 ms) to reveal the real text and that Pop holds while a re-rendered copy scales in from ~0.8 (160 ms) before both vanish, the large-operation rule by name of the two constants (counting what the change inserted or removed), that a scroll, resize, further edit or theme change removes it at once, and the name of the pure decision function. The paragraph's "all four actions are live" state is stated once; no second section is added.

### Tests (PRD 025 Reqs 21–23)

- Unit tests in a new `editor/tests/fluid-insertion.test.ts`, IDs continuing from the next unused `U` number (U1302 at spec time; check with `grep -rhoE '\bU[0-9]+:' tests editor/tests | sort -t U -k2 -n | tail -1`), cover: the span decision's animate cases (`input.type`, `input.paste`, `undo`, `redo`, a null user event; a replacement span with `removedLength > 0`; a multi-line insertion; two inserting spans both returned); its no-effect cases (`docChanged` false; removal-only spans; `input.type.compose`; a transaction mixing a pure removal and an insertion returning only the inserting span); the large-operation cases (inserting more than 2,000 characters; more than 50 lines; a replacement whose removed side alone exceeds a threshold while inserting one character; two spans that only together exceed a threshold; exactly 2,000 characters and exactly 50 lines still returned); and that `FLUID_DURATIONS_MS.fade` and `FLUID_DURATIONS_MS.pop` lie within 120–250 ms and `fluidEffectsFor('insertion')` is exactly `['fade', 'pop']`. Plain numbers only: no timers, fake timers, `requestAnimationFrame` or DOM. Geometry is not re-tested: `fluidSelectionRects` and `fluidDeletionBox` are already covered by U1292–U1299.
- One e2e test, ID the next unused `E` number (E587 at spec time), next to E586 in `tests/e2e/settings-and-themes.spec.ts`: enables the switch with the default mapping (Insertion → Pop) via `openSettings(page, 'experimental')` + `saveSettings`; then asserts only negatives that need no animation observation, reading counts of `page.getByTestId('fluid-insertion-mask')` and `fluid-insertion-ghost` (and the layer's child count where the whole layer must be empty) — (a) under `page.emulateMedia({ reducedMotion: 'reduce' })`, after clicking the content, Control+Home, Home and pressing `Q`, the first line's text starts with `Q` immediately and the layer has zero children and `data-fluid` is intact; (b) back on `'no-preference'`, after Home, Shift+End and pressing `W`, the first line's text is exactly `W` immediately (a replacement is real and synchronous, with no assertion about the mask or ghost that may now be in flight); after Backspace the first line is empty immediately and there is no insertion mask and no insertion ghost (a pure removal never draws one); after ArrowRight/End there is still none (a navigation move is not an insertion); (c) the large-operation rule: after Control+End and enough Enter presses to take `fixtures/welcome.md` (45 lines, 1,649 characters at spec time) past 50 lines, Control+A then pressing `M` leaves the content with a single line reading exactly `M` and zero children; (d) after re-saving with Insertion → Fade and reduced motion on again, typing a character updates the line immediately and draws nothing (zero children); (e) after re-saving with Insertion → None (motion allowed), typing a character updates the line immediately, leaves zero children, and the layer still has count 1. It never waits for, measures or screenshots an animation and uses no `waitForTimeout`.
- **Permitted amendments to existing tests, and only these.** Two tests assert an empty layer right after typing with the default mapping, which an insertion effect now makes false: E580 (b) (`tests/e2e/settings-and-themes.spec.ts` ~L988–992, the `ghosts()` checks after pressing `Q` and `Z`) is narrowed to `page.getByTestId('fluid-caret-ghost')` having count 0 — the caret-effect claim it was always making; E582 (b) and (c) (~L1051 after pressing `Q`, ~L1059 after Control+A following the Enter presses) are narrowed to `page.getByTestId('fluid-selection-ghost')` having count 0 — the selection-effect claim. IDs, titles and every other step stay unchanged. No other existing test or test ID is changed, renamed, weakened or skipped; E586's `ghosts()` checks stay as they are (each follows a Backspace or reduced motion, which leave no insertion element). The rest of the e2e suite runs with the switch off and is unaffected.
