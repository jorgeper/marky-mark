# Spec: open file behavior (#64)

## Goal

All acceptance criteria in issue-specs/issue-64.md are satisfied for issue #64, with evidence visible in the session: a plain click on a not-yet-open markdown file in the folder sidebar opens it in addition to the already-open files — clicking around accumulates open tabs instead of silently replacing the current one — with every open file rendered as a tab (active row on the front plane, the rest on the panel plane) carrying a hover ✕ that closes it, and `npm run validate:quick` passes in the implementer's session.

## Acceptance criteria

- **Additive plain click.** In the folder sidebar, a plain click on a markdown file row that is not currently open adds it to the open set and makes it active; no previously open file leaves the set, and no unsaved-changes prompt appears (the outgoing document parks, exactly as Mod+click does today under SPEC36 §2). Plain-clicking N distinct files in sequence leaves N open tabs. Plain click on an already-open row still just activates it; the dirty-untitled guard (SPEC36 §2.6 — an untitled buffer can't park) is the only navigation prompt that remains.
- **All user-initiated opens follow the same rule.** File → Open, Open Recent, file drop, create-then-open, and explicit boot opens (which all route through `openDocGuarded`, `src/App.tsx:1652`) also open additively rather than replacing the active file.
- **Tab indication is visible.** With a set built by plain clicks, every open file's row shows the SPEC36 §4 tab treatment: the active row keeps the front-plane `.selected` look (the only row that breaks the panel/workspace seam) and open-but-inactive rows carry the `open` panel-plane tab shape. Each open row shows the ✕ (`folder-tab-close`) on hover; the ✕ still closes per SPEC36 §3.4–§3.5 (dirty file activates and prompts; closing the active file activates its tree-order neighbor; closing the last file lands on the splash), and the dirty ● (`folder-dirty`) still swaps for the ✕ on hover.
- **Nothing else regresses.** Mod+click, Ctrl+Tab / Ctrl+Shift+Tab cycling, only-open-files mode, quit-walk of dirty files, and open-set persistence/restore (SPEC36 §5–§8) behave as before — the only contract change is plain-open no longer replacing.
- **Spec history is amended.** `docs/specs/SPEC36.md` carries an amendment note stating that §3.2's replace semantics changed to additive per issue #64; citation comments touched by the change remain accurate per `docs/COMMENT-FORMAT.md`, and `docs/MAP.md` is regenerated via `npm run map` if the citation set changed.
- **Tests reflect the new contract.** E100 (`tests/e2e/tabs-and-workspace.spec.ts:19`), whose title and body assert "plain-click replaces", is updated to assert additive semantics; any other test that leaned on replace-on-click (check `tests/e2e/tabs-and-workspace.spec.ts` E103/E104 setup and `tests/e2e/folder-tree.spec.ts`) is updated and passes. Unit tests are untouched unless `src/lib/openFiles.ts` logic changes (it likely doesn't — the change is in App-level open routing).
- Iteration was done with `npm run typecheck` and `npm run test:unit` (plus targeted e2e runs like `npx playwright test -g 'E100'`), with the full gate run ONCE at the end — not after every small change, and not as a starting baseline.
- `npm run validate:quick` passes in the implementer's session, printing `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #64.

## Context

The tabs feature shipped in SPEC36 (`docs/specs/SPEC36.md`), but §3.2 deliberately made plain click REPLACE the active file — only Mod+click accumulates tabs — so the user never sees tabs pile up by normal clicking, which is what issue #64 complains about. The open routing lives in `src/App.tsx`: `openDocGuarded` (~line 1652) sends not-open targets through `openReplacing` (~line 1634, which evicts the outgoing doc) instead of the park-and-add path `modOpenFile` uses (~line 1680). The minimal change is to route not-open targets through the additive park-and-open path and retire the replace path plus its now-dead dirty prompt branch; the visual tab treatment, ✕ close, park map, and persistence already exist and need no rework. Grep `SPEC36 §3` for the citation map. The persisted open set is already capped (`OPEN_CAP = 50` in `src/lib/openFiles.ts`), so unbounded growth from click-accumulation is handled at the persistence layer. Follow `.sandcastle/CODING_STANDARDS.md`.
