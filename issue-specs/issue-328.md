# Spec: No pane motion: preview mounts in place, sidebar and comments column toggle instantly (#328)

## Goal

All acceptance criteria in issue-specs/issue-328.md are satisfied for issue #328, with evidence visible in the session: toggling the split preview mounts or unmounts `.split-preview` in place with no `preview-sliding` / `preview-out` / `preview-pre` phase classes, no `transform`, no `transition` and no `will-change`, the editor's width changing in the same frame while the issue #165 guarantees (same editor instance, pane arrives holding content) still hold; the sidebar and comments column appear and disappear instantly through every toggle surface, with the `.folder-slide` / `.comments-slide` 180 ms width and transform transitions, their `sliding` / `out` phase classes, the `paneSlide` phase machinery and the pane-slide `prefers-reduced-motion` rules gone (the hosted boot-indicator rule stays); the `--mm-split-edge-shade` inset shade is removed from the split divider while its 1 px `--mm-border` hairline and hover accent, own scrollbars, sync scroll, divider drag (clamped 0.2–0.8, double-click reset) and `--mm-pane-min` behaviour are unchanged; SPEC7 §5 and PRD 003 Reqs 9–12 carry amendment notes and the slide e2e assertions are rewritten (not deleted) plus a new test asserts no transition applies on toggle; `npm run validate:quick` has been run once at the end and prints `QUICK VALIDATION: ALL PASSED`; and a summary comment from the implementer exists on issue #328.

## Acceptance criteria

- **Split preview mounts in place (PRD 025 Req 22).** Toggling `splitEdit` through every surface (the `preview-collapse` / `preview-expand` chevrons, the View menu row, `Mod+\`, the Settings checkbox) mounts or unmounts `.split-preview` directly. The `.workspace.split` element never carries `preview-sliding`, `preview-out` or `preview-pre`; the rules in `src/styles.css` under the `.workspace.split.preview-*` selectors (absolute positioning, `transition`, `will-change`, `translateX`, the mid-slide `overflow-x: hidden` on the scroller) are removed, and the steady-state `.split-preview` / `.split-editor` rules gain no transition. In the first frame after the toggle the editor's width already equals the workspace width minus the preview and divider (open) or the full workspace width (closed). The issue #165 guarantees stay: the editor instance survives both directions with its scroll position and caret (the `.split-editor` `display: contents` wrapper and `splitActive` keying stay), and an opening toggle still pre-renders through `prerenderSplitPane` so the pane arrives holding content in the frame it enters the DOM.
- **Sidebar and comments column toggle instantly (PRD 025 Req 12).** `showFolders` (edge chevron, `folder-collapse` / `folder-expand`, View menu, hotkeys, Settings, `showSidebarView`) and `showComments` (`comments-collapse` / `comments-expand`, View menu, the toggleComments hotkey) flip their pane in the DOM within a frame or two of the toggle. `.folder-slide` and `.comments-slide` never carry `sliding` or `out`; their `transition: width 180ms`, the inner `.folder-panel` / `.comments-pane` `transition: transform 180ms` + `will-change: transform` and the `translateX(±100%)` / `width: 0` rules are removed from `src/styles.css`. The wrapper elements themselves may remain as plain fixed-width containers (the `paneWidthDrag` in `src/components/FolderPanel.tsx` writes `--mm-folders` onto the `.folder-slide` wrapper and the print rules list it) — only the phase classes and their motion go. The persisted end state is identical to today's (settings.json shows the flipped `showFolders` / `splitEdit` / `showComments`).
- **Slide machinery removed, not parked.** `src/lib/paneSlide.ts` (`SlidePhase`, `SLIDE_MS`, `SLIDE_SETTLE_MS`, `slideOnToggle`, `slideOnFrame`, `slideOnSettle`, `slideMounted`, `slideClasses`) and `usePaneSlide` in `src/App.tsx` are deleted together with the `armFolderSlide` / `armSplitSlide` / `armCommentsSlide` refs and the `prefers-reduced-motion` matchMedia sampling; `sidebarMounted`, `splitActive` and `commentsPaneMounted` derive from the settings predicates alone. The `slide` prop and `slideClasses` usage are dropped from `FolderPanel.tsx`, `TocPanel.tsx` and `SearchPanel.tsx`. `tests/unit/pane-slide.test.ts` (U123) is deleted with the module (the duplicate-ID gate only forbids reuse, so U123 retires; do not assign it to a new test). `npm run typecheck` reports no dangling imports.
- **Reduced-motion block trimmed (PRD 025 Req 12).** The `@media (prefers-reduced-motion: reduce)` block in `src/styles.css` no longer lists any `.folder-slide`, `.comments-slide` or `.workspace.split.preview-*` selector. The hosted boot-indicator rule inside it (`.hosted-booting .hosted-booting-spinner`, PRD 020 Req 5+6, issue #316) is unchanged, and its lead comment no longer describes the block as the pane-slide carve-out. `--mm-slide-ease` is kept if any remaining rule still references it, otherwise removed with its internal-token comment; either way the style lint reports no undefined `var(--mm-…)`.
- **Divider reads as one plane (PRD 025 Req 23).** In `editor/styles.css` the `.split-divider::before` and `.split-divider:hover::before` rules keep exactly the 1 px inset hairline (`--mm-border` at rest, `--mm-accent` on hover/drag) and drop the `var(--mm-split-edge-shade)` layer. The `--mm-split-edge-shade` declaration is removed from `editor/default-theme.css`, from the internal tokens in `src/styles.css`, and from the token table in `editor/THEMING.md`. Any change under `editor/` follows `editor/AGENTS.md` (no imports from `src/`); the editor package's own suite passes (`npm test` inside `editor/`) and the editor-package-boundary check in the quick gate stays green.
- **Nothing else about the split changes (PRD 025 Reqs 24–26).** Each half keeps its own scrollbar and the existing sync-scroll behaviour; dragging `split-divider` still moves `--mm-split` with the 0.2–0.8 clamp, persists `splitRatio` on release and resets to 0.5 on double-click; the workspace width does not change with the ratio; `paneMinWidth` still floors each half's content at `--mm-pane-min` with horizontal scrolling below it. The existing tests pinning these (E39, E40, E134, E438, E441 and the rest of `tests/e2e/split-view.spec.ts`) still pass unmodified except where they waited on a slide (next criterion).
- **Amendments and citations.** SPEC7 §5 in `docs/specs/SPEC7.md` and PRD 003 Reqs 9–12 in `prd/003-pane-chevrons-and-slide-animations.md` each carry a `> **Amended (issue #328, 2026-09-07):** …` note in the repo's existing amendment style stating that panes switch instantly per PRD 025 Reqs 12 and 22 and the reduced-motion carve-out is gone. Code citations that pointed at PRD 003 Reqs 9–12 for slide behaviour (`src/App.tsx`, the three panel components, `src/styles.css`) are removed or re-pointed; the new behaviour carries `// PRD 025 Req 12 (issue #328): …` / `PRD 025 Req 22` / `PRD 025 Req 23` citations per `.sandcastle/CODING_STANDARDS.md`. The PRD-wide amendment sweep (PRD 025 Req 29: SPEC34, SPEC36 §4.1, PRD 013, PRD 023 §14–15) is NOT done here — it belongs to sibling #332. If `npm run map` output changes, the regenerated `docs/MAP.md` is committed alongside.
- **E2E tests rewritten, not deleted (PRD 025 Req 30).** E133 in `tests/e2e/shell-and-menus.spec.ts` keeps its number and its functional guarantees (panes mount/unmount through the toggles, settings persist, steady state carries no transform) with the reduced-motion leg and the slide wording replaced by instant-toggle assertions. E355 in `tests/e2e/split-view.spec.ts` keeps its issue #165 assertions (content at mount, no Suspense fallback, same editor instance, caret and top line preserved, text column transform-free) and asserts that `.workspace.preview-sliding` is never seen (`slideSeen` false, or the field removed) with the separate reduced-motion leg folded into the same instant expectation. The "let the slide settle" waits and comments in `split-view.spec.ts` (near the E40 divider drag and the preview chevron re-pin), in E435 of `tests/e2e/comments.spec.ts`, and the `stableBox` doc comment in `tests/e2e/helpers.ts` no longer describe a 180 ms slide. No existing test is deleted, renamed or renumbered.
- **New test: no transition on toggle (PRD 025 Req 30).** A new test in `tests/e2e/split-view.spec.ts` (or `shell-and-menus.spec.ts`) takes the next unused E-number (E577 at spec time; re-check with `grep -rhoE "test\('E[0-9]+" tests/e2e | sort -t E -k2 -n | tail -1` before committing) and, for each of the three panes (folder sidebar, split preview, comments column), toggles it open and closed through a chevron or hotkey and asserts: the pane element is present (open) or absent (closed) within two `requestAnimationFrame`s of the click; at the frame it appears, the pane and its wrapper report `transition-duration` of `0s`, `transform` of `none` and `will-change` of `auto` via `getComputedStyle`; the workspace never carries a `preview-*` class and the wrappers never carry `sliding` / `out` (observed with a `MutationObserver` on class attributes, as E355 does); and for the split, the editor's bounding width plus the preview's bounding width plus the divider fill the workspace in that same frame.
- **Iteration economy.** The implementer iterates with `npm run typecheck` and `npm run test:unit` (plus targeted e2e runs such as `npx playwright test -g 'E133'`, `-g 'E355'`, `-g 'E577'`, and `npm test` inside `editor/` when `editor/` changed) after each change, and baselines an attempt with the quick tier only.
- **Full gate.** `npm run validate:quick` has been run ONCE in the implementer's session, right before declaring the goal met (not after every small change and not as a baseline at the start), and prints `QUICK VALIDATION: ALL PASSED`.
- **Summary comment.** A summary comment from the implementer exists on issue #328 describing what was removed, the amendment notes added, the rewritten and new test numbers, and the validate:quick result.
