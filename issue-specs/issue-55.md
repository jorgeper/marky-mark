# Spec: sometimes tables don't render right (#55)

## Goal

All acceptance criteria in issue-specs/issue-55.md are satisfied for issue #55, with evidence visible in the session: with live preview and the table grid view both on, grid lines show their raw cell markdown (no live-preview marker hiding inside tracked grid spans) so every pipe column stays aligned; unit and e2e regression coverage for this exists and passes; `npm run validate:quick` has been run in the implementer's session and passed; and a summary comment from the implementer exists on issue #55.

## Acceptance criteria

- Root cause fixed: when both `tableGridView` and `livePreview` settings are on, no live-preview decoration that changes the visible character count (marker `hide` spans, link-syntax collapse, checkbox widget replacement) applies within a tracked table-grid span. Grid lines display their raw cell markdown — `**Host**` with asterisks visible, code spans with backticks visible — so every line of a rendered grid has the same visible length and all `|` columns align. The exclusion is selection-independent: it holds when the caret is outside the table (it must not rely on PRD 006 §8's reveal rule).
- Live preview outside grid spans is unchanged: the existing live-preview e2e tests (E142–E150 in `tests/e2e/live-preview.spec.ts`) and unit tests (`tests/unit/live-preview.test.ts`) still pass unmodified (or with only additive changes).
- Unit coverage exists for the exclusion path (e.g. in `tests/unit/live-preview.test.ts`): decorations are suppressed inside an excluded/grid region and still produced for identical constructs outside it.
- An e2e regression test exists using the next free E number (E157 at spec time — re-check with a grep before writing) that seeds `livePreview: true`, opens a document containing a table shaped like the issue #55 repro (cells with `**bold**` terms and backtick code spans), and asserts the rendered grid lines still contain the raw markers (e.g. visible text includes `**Host**`) and/or that all grid-span lines have equal visible text length. The test passes.
- Changed behavior carries citation comments per `docs/COMMENT-FORMAT.md`; if citations or E-test coverage change what `npm run map` derives, `docs/MAP.md` has been regenerated with `npm run map` (the validation gate diffs it).
- Test economy: the implementer iterated with `npm run typecheck` and `npm run test:unit` (or tests targeted at the changed code), used `npx playwright test -g '<title>'` for single e2e runs while debugging, and ran `npm run validate:quick` ONCE right before declaring the goal met (not after every small change, and not as a full-suite baseline at the start) — it printed `QUICK VALIDATION: ALL PASSED` in the implementer's session.
- A summary comment from the implementer exists on issue #55.

## Context

Diagnosis (verified against the issue's screenshot and by running the repro table through the layout engine): `layoutTable` in `src/lib/tableEdit.ts` pads grid columns by **raw character count**, including inline markers. The live-preview layer (`src/lib/livePreview.ts` pure core, mapped to CodeMirror decorations by `src/components/livePreview.ts`) hides `**`/`` ` ``/link markers everywhere, including inside grid lines — so each row loses a different number of visible characters and its pipes shift left (the screenshot shows the `**Host**` row's pipe pulled exactly 4 characters left; header and separator rows stay aligned). The pure layout itself round-trips correctly at all widths, so the fix belongs in the live-preview decoration path, not in `tableEdit.ts`.

Tracked grid spans live in `tableModeField` (`src/components/tableMode.ts`, `GridSet.spans`), registered in `src/components/Editor.tsx` alongside `livePreviewExtension`. Reasonable shapes: filter decos against grid spans in the component layer, or thread excluded ranges into `computeLivePreviewDecos` — implementer's choice, but keep `src/lib/livePreview.ts` pure (no DOM/platform imports). Width-neutral styling (bold weight, code background via `mm-md-*` syntax classes) may keep applying inside grids; only character-count-changing decorations must be excluded. Defaults: `livePreview` off, `tableGridView` on (`src/lib/settings.ts`) — that's why the bug appears "sometimes". E2e helpers/seed-settings live in `tests/e2e/helpers.ts` / `fixtures.ts`; table e2e in `tests/e2e/tables.spec.ts`.
