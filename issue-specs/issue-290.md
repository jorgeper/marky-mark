# Spec: Scratch boots fresh on every entry: both bare URL forms and the Open Workspace row (#290)

## Goal

All acceptance criteria in issue-specs/issue-290.md are satisfied for issue #290, with evidence visible in the session: entering the caller's own scratch with no target file — `/scratch`, a bare `/<username>/scratch` (first visit *and* browser reload), or the Open Workspace dialog's "My scratch" row — always ends in a fresh, empty scratch buffer focused in edit mode that silently replaces any buffer already there, while `/<username>/scratch/<path>` and anyone else's scratch boot no buffer at all; unit coverage for the routing/boot decision exists and the e2e tests that asserted the removed "reload just re-binds" behaviour are updated rather than deleted; `npm run validate:quick` passes in the implementer's session; and a summary comment from the implementer exists on issue #290.

## Acceptance criteria

- **Req 1 — both bare URL forms boot fresh.** A signed-in visit to `/scratch` **or** to the caller's own bare `/<username>/scratch` (no file segment) ends with the scratch workspace bound and a fresh, empty scratch buffer focused in edit mode, on every visit including a browser reload of the canonical bare URL. The "a reload of the canonical URL just re-binds" guard in `src/components/HostedSignIn.tsx` (the `fresh` argument to `bindScratch`, currently `path.kind === 'scratch'`) is gone. PRD 020 Req 11 is unchanged: `/scratch` still rewrites to `/<username>/scratch` before `<App/>` mounts.
- **Req 2 — a file URL opens the file.** `/<username>/scratch/<path>` binds the workspace and opens that file, and boots no scratch buffer (`scratch` is absent from the stored boot record). A missing file still lands on the not-found page naming `<username>/scratch` and the relative path, exactly as today.
- **Req 3 — the Open Workspace row boots fresh too.** Choosing the caller's own scratch workspace from the Open Workspace dialog (the badged "My scratch" row, `OpenWorkspaceDialog` → `lifecycle.navigateTo`) lands in a fresh scratch buffer with the same semantics as Req 1. If the existing navigation to the canonical bare URL already delivers this once Req 1 lands, no new navigation path is invented — but the behaviour is asserted by a test rather than assumed.
- **Req 4 — re-entry replaces silently.** With a scratch buffer already open — dirty or clean — re-entering the scratch workspace by any Req 1 or Req 3 route discards it with no unsaved-changes prompt and no `beforeunload` dialog (PRD 019 Req 11's exemption already covers the guard in `App.tsx`'s close-guard path), and a new empty scratch buffer takes its place, still prompt-exempt.
- **Req 5 — only the caller's own scratch.** Visiting another user's scratch, with or without a file segment, boots no scratch buffer; the existing `/api/scratch/<username>` resolution and its identical 404 for unknown/unprovisioned/inaccessible are unchanged.
- **One rule, not per-route.** The boot decision is "own scratch **and** no target file", not "arrived by the shortcut URL": the caller's own scratch reached by its unique-name path or the legacy `?workspace=<uuid>` form with no file (the `row?.scratchpad` branch in `resolveHostedVisit`, which rewrites to the canonical bare URL) boots fresh the same way. Only a file segment suppresses the boot.
- **Nothing else about scratch moves.** No naming or styling change — the booted buffer still shows "Untitled" in the toolbar, file tab and browser tab, and the first save still behaves as today (PRD 019 Req 12's content-derived pre-fill stays; the sibling slices replace it). PRD 019 Req 11's discard semantics are unchanged and the prompt exemption stays scoped to the boot's buffer: a ⌘N buffer inside the scratch workspace still prompts normally. Desktop (Tauri) and single-file builds are untouched (PRD 019 Req 4).
- **Unit coverage for the routing/boot decision.** New `U<n>:`-titled tests (next free number after U1114) cover the decision for: `/scratch`, own bare `/<username>/scratch`, own `/<username>/scratch/<file>`, another user's scratch with and without a file, and re-entry. This means the decision is reachable from a unit test — extract it as a pure helper (e.g. beside `parseAppPath`/`buildScratchPath` in `src/lib/hostedPaths.ts`) rather than testing it only through the DOM-bound `resolveHostedVisit`.
- **Existing tests updated, not deleted.** `tests/e2e/hosted.spec.ts` E397 currently asserts that a reload of `/<username>/scratch` re-binds without a scratch buffer; it asserts the new behaviour instead. E398/E399/E404 still pass. Hosted e2e coverage exists for the Open Workspace row booting fresh (Req 3) and for re-entry over a dirty scratch buffer replacing it with no prompt (Req 4), as new `E<n>:` tests (next free number after E432).
- **Citations.** Every changed or added behaviour site carries its contract citation in the repo's format (`// PRD 023 Req <n>: <what and why>`, alongside the PRD 019/020 citations already there), per `.sandcastle/CODING_STANDARDS.md`.
- **Test economy.** Iteration uses `npm run typecheck` and `npm run test:unit` (or `npx playwright test -g '<title>'` for one e2e behaviour). The full gate is run **once**, right before declaring the goal met — not after every change, and not as a start-of-attempt baseline (baseline with the quick pair only).
- **`npm run validate:quick` passes**, run in the implementer's session, printing `QUICK VALIDATION: ALL PASSED`. It includes the docs/MAP.md freshness check (run `npm run map` and commit the result if it complains), the test-ID uniqueness check and the e2e count floor.
- **A summary comment from the implementer exists on issue #290**, describing what changed and carrying the validate:quick evidence.

## Context

The whole decision lives in `resolveHostedVisit` in `src/components/HostedSignIn.tsx` (~line 160–205): it resolves the caller's handle via `/api/me`, resolve-or-creates their scratch via `POST /api/me/scratchpad`, then calls the local `bindScratch(id, owner, file, fresh)`. `fresh` is what writes `scratch: true` into the sessionStorage boot record (`storeHostedBoot`, `src/lib/hostedGate.ts`); `src/platform/hosted.ts:100` turns that into the platform's `scratchStart` flag (`src/platform/types.ts:258`), and `src/App.tsx:2794-2803` consumes it — `startUntitledRef.current()` opens the buffer and `scratchRef.current = true` arms the PRD 019 Req 11 prompt exemption. Nothing downstream of the boot record needs to change; the change is which visits set `fresh`.

The Open Workspace route is `OpenWorkspaceDialog` (`src/components/WorkspaceSwitcher.tsx:209`, `choose` → `lifecycle.navigateTo(id)`) → `navigateTo` in `src/platform/hostedWorkspaces.ts:255`, which for a `scratchpad`-flagged row does `window.location.assign(buildScratchPath(handle))` — a full page load onto the canonical bare URL, so it re-enters `resolveHostedVisit`. Check that before adding any new plumbing.

Path parsing (`parseAppPath` → `{kind: 'scratch'}` / `{kind: 'user-scratch', username, file}`) and `buildScratchPath` are in `src/lib/hostedPaths.ts`, already unit-tested in `tests/unit/hosted-paths.test.ts` (U1036, U1061, U1062) — the natural home for a pure boot-decision helper. Boot-record round-tripping is tested in `tests/unit/hosted-gate.test.ts` (line ~118 comments on the old "reload just re-binds" intent). The hosted e2e suite is `tests/e2e/hosted.spec.ts`, run against the local server started by `playwright.config.ts`; it is part of `npm run test:e2e` and therefore of `validate:quick`.

Background: `prd/023-scratch-fresh-buffer.md` (Reqs 1–5 are this slice; Reqs 6–12 are the sibling slices) and parent issue #273. This is hosted-build-only work.
