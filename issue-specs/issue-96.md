# Spec: E2e coverage sweep for the server-mode menu and exclusive modes (#96)

## Goal

All acceptance criteria in issue-specs/issue-96.md are satisfied for issue #96,
with evidence visible in the session: PRD 009 Req 18's list is audited item by
item against the tests actually in the tree, the gaps that audit finds are
closed by new E-numbered e2e tests (at minimum Close File / Close Workspace →
initial page with the hosted `?workspace=<id>` clearing, and workspace New File
/ Save As… through the save picker), E209 and any local-file-inside-workspace
assertion are confirmed gone, `docs/MAP.md` is regenerated by `npm run map`,
`npm run validate:quick` passes in the implementer's session, and a summary
comment from the implementer exists on issue #96.

## Acceptance criteria

- The Req 18 list is audited against the tree, and the audit's per-item verdict
  (already covered by which test / newly added as which test) is recorded in
  the issue comment. Req 18's items are: the frozen item-set tests, Close File
  and Close Workspace → initial page, the implicit mode switch with dirty
  prompt, workspace New File / Save As…, Sign out, and E209's retirement.
- The frozen hamburger item-set tests reflect the post-#93/#94/#95 structure —
  `E13` (tests/e2e/shell-and-menus.spec.ts), `E201` (tests/e2e/hosted.spec.ts)
  and `W13` (tests/e2e/web.spec.ts) each assert the left-anchored menu button,
  the separator-divided groups of Req 8 and the mode/capability gating of Req 9
  for their flavor. Where an assertion is missing (button-before-document-name
  ordering, exact row list, exact separator count, hidden vs merely disabled
  rows), it is added rather than assumed.
- An E-numbered e2e test covers **Close File → initial page** driven through
  the in-app menu row (`menu-close-file`), not only the `__mmDispatch` command
  seam: with one file open, activating the row lands on the initial page
  (`empty-hint` / start actions visible, no document).
- An E-numbered e2e test covers **Close Workspace → initial page** on hosted:
  activating `menu-close-workspace` returns to the initial page, and per Req 6
  the `?workspace=<id>` binding is cleared from the URL so a reload lands on the
  initial page rather than back in the workspace.
- The implicit mode switch with a dirty prompt and its cancel path (Req 4) is
  covered — `E210` / `E211` (shim) and `E212` (hosted) already carry this; if
  the audit finds a crossing path in Req 4 with no coverage at all (e.g.
  drag-and-drop of a local file while a workspace is open), a test covers it.
- An E-numbered e2e test covers workspace **New File** (Req 13): the menu row
  opens the save picker (`save-picker`, `save-picker-name`,
  `save-picker-folder`), confirming creates the file through the workspace file
  API and opens it as the current document — no floating untitled buffer.
- An E-numbered e2e test covers workspace **Save As…** (Req 14): the picker
  writes a copy at the chosen name/folder and the current document switches to
  the new file, with the original left intact.
- Sign out (Req 17) is covered — `E215` already asserts the dirty prompt, the
  Cancel path, and the token + workspace-binding drop; the audit confirms it,
  and nothing new is added unless a Req 17 clause is uncovered.
- `E209` is gone from `tests/e2e/`, and no test (new or existing) asserts that a
  local file opens *inside* an open workspace — the only local-file-with-
  workspace-open assertions are the mode crossing of Req 5.
- Every new test is E-numbered per repo convention, continuing above the current
  maximum (`E215`); tests added to `tests/e2e/web.spec.ts` use `W<n>` instead,
  per CODING_STANDARDS § Testing. New tests carry the PRD/spec citation comment
  required by `docs/COMMENT-FORMAT.md`.
- `docs/MAP.md` is regenerated via `npm run map` and committed, so the committed
  file matches what the generator derives from the tree (the validation gate
  diffs it).
- Iteration used `npm run typecheck` and `npm run test:unit`, plus targeted e2e
  runs (`npx playwright test -g '<title>'`) for the tests being written — not
  the full suite after each change, and no full-gate baseline at the start.
- `npm run validate:quick` has been run ONCE at the end, in the implementer's
  session, and prints `QUICK VALIDATION: ALL PASSED`.
- A summary comment from the implementer exists on issue #96, naming the audit
  verdict per Req 18 item, the new test numbers, and the gate result.

## Context

All blockers (#93, #94, #95) plus #90–#92 have landed on `main`; this issue only
adds the coverage those changes did not bring with them. What is already in the
tree: `E13` (shell-and-menus.spec.ts:79), `E201` (hosted.spec.ts:1458), `W13`
(web.spec.ts:429) — updated item sets; `E210`/`E211`
(tabs-and-workspace.spec.ts) — shim mode crossings with Cancel; `E212`
(hosted.spec.ts:1774) — hosted crossing plus `?workspace` clearing; `E213` —
handle-backed save; `E214` (shell-and-menus.spec.ts:872) — View ▸; `E215`
(hosted.spec.ts:1932) — Sign out. `E209` already survives only as a prose
mention in a comment at hosted.spec.ts:1780. `tests/unit/save-picker.test.ts`
covers the Req 13/14 picker logic, but no e2e drives it — that is the largest
gap.

Test helpers live in `tests/e2e/helpers.ts` / `fixtures.ts`; hosted tests use the
signed-in fixture and the `HOSTED` origin, shim tests the in-memory `__mmfs`.
Prefer driving the new tests through the real menu rows (`menu-close-file`,
`menu-close-workspace`, `menu-new-file`, `menu-save-as`) so they exercise the
menu wiring, and reach for `__mmDispatch` only for setup. PRD requirements are
in `prd/009-server-mode-menu.md`; coding and test-numbering rules in
`.sandcastle/CODING_STANDARDS.md`. `npm run test:e2e` is minutes long and
serialized — keep it out of the inner loop.
